# Search Genre Assertions і Request Profiles — пошук по всіх джерелах і фільтри по жанрах

## Контекст

Гриль 2026-09-10 (тема хвилі: «фільтри по жанрах, пошук по усіх джерелах»)
протиставив код і рішення ADR-0039/спеки #681 та спайка хвилі 50 і знайшов
чотири розбіжності:

1. **Пошук викидає жанр.** `mergeGlobalSearchResults` (GlobalSearch.kt) не
   переносить `SourceBook.genre` у картку — `GlobalSearchResult` поля genre не
   має взагалі. Фасет-модель (CONTEXT.md, «Local facet projection») каже:
   genre membership — Source-owned assertion, що пишеться крізь
   `LocalFacetWriter` з переліку каталогу. Твір, видимий лише через пошук,
   ніколи не потрапляє в «Фільтри».
2. **Шлюз змушує фічу знати ритм.** Шов `SourceRequestGate.run(url,
   requestClass, cacheTtlMillis, fetch)` вимагає від викликача класифікувати
   запит і обирати TTL — суперечить ADR-0039 «Фічі більше не знають про
   ритм».
3. **«Один токен на прохід» не виконано.** ADR-0039 §5 обіцяє TTL-оновленню
   один токен на прохід; код списує токен на запит. Enumeration каталогу
   (≈40 сторінок на джерело) при кошику 6 і поповненні 1/10 с дає частковий
   каталог без жодного контракту для `GateOutcome.Deferred` — споживач не
   знає, чи «6 книг» це правда, чи бюджет.
4. **Пошук knigi-online не верифікований.** Спайк хвилі 50 зафіксував
   «пошук серверно відсутній (чесна порожнеча, як chytaylo)»; адаптер
   реалізує `/?s=` без живої фікстури — тест підставляє розмітку
   `/audioknyhy/` під URL пошуку. Один із двох документів суперечить
   етосу «measured absences, never fabricated» (ADR-0014).

## Рішення

1. **Пошук — джерело genre assertions.** Картка пошуку з непорожнім claimed
   genre пише assertion у фасети крізь той самий `LocalFacetWriter` (єдині
   двері запису) на рівні per-adapter результату fan-out — ДО MergeKey-merge,
   бо об'єднана картка викидає per-source поля. Assertion identity:
   (sourceId, сторінка, exact source text, observedAt) — та сама форма, що в
   каталогу. Жанр ніколи не вигадується; порожній рядок нічого не пише
   (ADR-0014).
2. **Дедуп із каталогом: ранг provenance.** Документ з enumeration завжди
   старший за пошуковий для тієї самої пари (Source, work), незалежно від
   часу спостереження — повніший набір каталогу не зменшується пошуковим
   single-genre хітом. Усередині одного класу діє чинне атомарне правило:
   суворо новіший документ Source заміщає весь його набір (включно з
   порожнім), рівний/старший — no-op. Пошук заповнює прогалину творів, які
   ніколи не перелічувалися. Семантика «Фільтрів» не змінюється: значення в
   межах виміру OR, виміри AND, порожній вимір = без фільтра.
3. **Профіль запитів в адаптері.** Адаптер декларує на ендпоінт клас запиту
   і TTL кешу (search = LISTENER_ACTION, enumeration = TTL_REFRESH,
   обкладинки = COVER, …); шов ввічливості (T2: `HttpFetcher`) читає
   профіль. Фіча не класифікує й не знає чисел. Амендує ADR-0039 §2.
4. **Токен на запит + ліміти проходу.** Токен списується на запит (код
   лишається). «Один токен на прохід» переформульовується: прохід не може
   витратити більше, ніж дозволяє кошик; `Deferred` для каталог/стрічок має
   контракт споживача — частковий каталог це чесний стан (показує, що є),
   ніколи не виглядає повним і не фабрикує решту; поповнення — наступним
   проходом за TTL. Амендує ADR-0039 §5.
5. **Пошук knigi-online — після живого переспайка.** `/?s=`-шлях шипиться
   лише разом із живою фікстурою реальної відповіді WordPress-пошуку; тест
   із вигаданою розміткою пошуку не входить. Переспайк виконано
   (2026-09-10, фікстура `search-s-nestayko.html`) — тодішній вердикт
   спайка «пошук відсутній» виявився помилковим: пошук працює.

## Наслідки

- Твір, знайдений лише пошуком, з'являється під своїм жанровим чіпом
  «Фільтрів»; каталог не втрачає повноти від пошукових хітів.
- Ритм повертається в декларацію адаптера, а не у викликача; нове джерело
  не додає нового ритму.
- Частковий каталог за вичерпаного кошика — видимий чесний стан, а не тиха
  брехня.
- Живий захват `/?s=` виконано і пошук підтверджено (фікстура
  `search-s-nestayko.html`); реєстрація KnigiOnlineAdapter у
  `App.sourceAdapters` відкрита. Водночас виправлено розбіжність
  заголовків: search-картки несуть anchor з «Аудіокнига »-префіксом, який
  `splitTitleAuthor` тепер знімає — один твір, один заголовок на всіх
  поверхнях адаптера.
