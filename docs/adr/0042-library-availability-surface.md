# Доступність аудіо видима в медіатеці — пріоритетна перевірка без шкоди джерелам

## Контекст

Гриль 2026-09-11 (тема: «конфуз користувача: книги в медіатеці виглядають
доступними, поки не перевіриш їх у джерелах»). Факти, покладені в основу:

1. **Тиха недоступність.** 4read-only книга (напр. фан-переклад «Передісторія
   Джеймса Поттера…») виглядає як звичайна; про відсутність аудіо слухач
   дізнається лише у плеєрі — «Не вдалося відновити відтворення».
2. **Вердикт існує, але невидимий.** Мапування заміщення шукає заміну
   (union → shared-кеш → локальний індекс → один залп), проте його результат
   ніде не показано до дотику; prewarm обмежений п'ятьма книгами зі 129.
3. **Source Watch уже є** (ADR-0037 §6) — локальне спостереження за Твором і
   нотифікація появи джерела — але вимагає окремої дії та не має видимого
   стану.
4. **Масштаб джерел — пізніший шар.** Єдиний безкоштовний каталог рівня
   4read — sluhay.com (~10k за meta), решта суттєво менші; YouTube — довгий
   хвіст (#725, #726). Нові джерела підвищують частку «знайдено», але не
   лікують тихий стан.
5. **Обмеження ввічливості.** ADR-0039/0040: token bucket на домен, класи
   запитів, фон палить бюджет лише при кошику, повному більш ніж наполовину;
   сплески недопустимі — джерела не повинні нас забанити.

## Рішення

1. **Доступність — видимий стан картки**, а не секрет плеєра. Проблемна
   книга показує один зі станів: «перевіряємо», «джерел не знайдено» (з часом
   перевірки) або «знайдено в {джерело}». Книга з доступним аудіо нічим не
   маркується — жодного шуму.
2. **Автоспостереження.** Кожна книга без доступного аудіо стає під Source
   Watch без окремої дії слухача; ручне спостереження лишається для явного
   вибору, але не є умовою видимості стану.
3. **Чесність вердикту.** Час останньої перевірки видимий; тап дає повторну
   перевірку (дія слухача). Внутрішні вікна вердиктів (6 год / 15 хв,
   ADR-0037) не показуються числами — вони лишаються дисципліною запитів.
4. **Два негаразди — два тексти.** «Аудіо джерела вимкнено» (Source Audio
   Refusal) і «джерел не знайдено» (немає ніде) не змішуються: перше пояснює,
   чому книга виглядає зламаною, друге — результат чесного пошуку.
5. **Пріоритетна черга, не «все на старті».** Перевірка йде за видимістю
   (картки у в'юпорті), далі — добовий дельта-скан у фоні. Union-first (нуль
   запитів), далі щонайбільше один залп на Твір; ритм — наявний гейт без
   змін; фонова перевірка — лише при повному більш ніж наполовину кошику.
   Спроба перевірити всі 129+ книг на старті відкинута: ризик бану і марна
   праця при 15-хвилинному негативному вікні.
6. **Порядок робіт.** Спершу цей шар; потім #725 (sluhay.com session-backed) і
   #726 (YouTube як пошукове джерело) — вони множать «знайдено», тоді як
   чесно показувати «немає» треба вже.

## Наслідки

- Слухач бачить, які книги реально слухаються, а які чекають на джерело;
  конфуз «обіцяної книги» зникає.
- Prewarm стає чергою з пріоритетом видимості; з'являються вимоги до текстів
  станів і тапової повторної перевірки.
- Джерельний бюджет не зростає: перевірки живуть на наявних вердиктах і
  гейті, власного циклу опитування не створюють.
- #725/#726 лишаються чинними як підвищення частки «знайдено», але не як
  умова чесного стану.
