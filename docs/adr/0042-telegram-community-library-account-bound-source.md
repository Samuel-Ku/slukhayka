# Спільна бібліотека: Telegram як джерело під акаунтом слухача, модерація зовні (ADR-0028/0035)

Обговорення 2026-09-11 (grilling-сесія). Слухачі мають аудіокниги, яких немає
на публічних джерелах, і хочуть ділитися ними зі спільнотою. Застосунок уже
приймає надходження-посилання (ADR-0035), але Telegram-надходження
публікуються metadata-only: у вебпрев'ю `t.me/s/…` звуку немає. Питання, яке
треба вирішити до коду: **хто хостить файли, як пристрій їх добуває, де
відбувається модерація і як позначити таке походження.**

## Рішення

1. **Хостить Telegram, не проєкт.** Файли живуть у зареєстрованій спільнотній
   Telegram-групі (**Спільна бібліотека**), куди їх заливають самі слухачі
   поза застосунком. Проєкт не хостить, не конвертує й не роздає аудіо; у
   спільній базі лишаються тільки посилання й метадані — ADR-0028 і
   «нейтральна позиція» ADR-0035 п.5 збережені. Нова сутність бібліотеки не
   заводиться: це ще одне **джерело** (Source).

2. **Добувач — на пристрої, під акаунтом слухача (MTProto/TDLib).** Пристрій
   входить у Telegram акаунтом слухача й тягне файл повідомлення напряму.
   Слухач мусить бути членом групи; сесія локальна, не синхронізується й
   може бути завершена. Вхід і членство ніколи не стаються неявно. Бот-сервер
   не заводимо: він вимагав би процесу-сервера й світив би токен у APK, що
   порушило б ADR-0028.

3. **Новий `Source Access Mode = TELEGRAM`.** Account-bound доступ — окремий
   клас, а не замаскований `BROWSER`. Автоплей пробує його останнім
   (`LOCAL < DIRECT < UNKNOWN < BROWSER < TELEGRAM`) і ніколи не відкриває
   його як неявний побічний ефект — лише явна дія/відновлення.

4. **Модерація — зовнішня.** Адміни/боти групи схвалюють матеріал до того, як
   він стає доступним; застосунок читає лише схвалене. Модераторського шлюзу
   в застосунку немає (ADR-0035 лишається чинним); внутрішній бар'єр —
   Verified Submission після реального програвання, прибирання — Shared
   Tombstone і скарги.

5. **Ознаки походження — факти, а не оцінки.** Кожне Verified Submission несе
   «Від слухачів»; Source із зареєстрованої групи додатково несе «Зі спільної
   бібліотеки». Ознаки виводяться з перевірних фактів (подав слухач; лінк
   веде на зареєстровану модеровану групу) і не є гарантією якості. Слово
   «ексклюзив» свідомо відкинуте як непеpевірна маркетингова обіцянка
   (`docs/voice.md`).

6. **Кілька лінків, багаточастинні книжки.** Типово одне посилання = одна
   книжка; частини однієї книжки по повідомленнях збираються в один Edition
   за наявним `Channel Post Pattern`. Межі розділів — лише спостережені
   (ADR-0007/0035).

7. **Поверхні.** Бейдж на картці (наявний слот `MetadataChip`) і рейка «Від
   слухачів» на Огляді з фільтром «Лише зі спільної бібліотеки». Дев'ятий
   блок «Слухати» не чіпаємо (ADR-0015).

8. **Web — чесне читання.** Картки видимі, відтворення недоступне (немає
   браузерного Telegram-акаунта); це свідома різниця платформ у delta-леджері
   ADR-0034. Серверний relay для web — ні (ADR-0024/0028). Майбутній напрямок —
   відтворення через web-клієнт Telegram.

## Наслідки

- Спільна бібліотека розширює базу без праці куратора й без хостингу з боку
  проєкту; якість тримається зовнішньою модерацією та внутрішньою
  верифікацією програванням.
- Кожна інсталяція мусить мати робочий MTProto-шов і сесію слухача; без
  сесії або членства джерело чесно недоступне.
- Зберігання Telegram-сесії — новий безпековий поверх; він не синхронізується
  й має бути явно оборотним.
- Факти групи живуть у Реєстрі джерел (`sources.json`), тож додавання чи
  заміна груп не вимагає форків коду; паритет платформ припінається
  конформанс-тестом (ADR-0038).
- Завантаження локального файлу в групу із застосунку та web-відтворення —
  окремі майбутні хвилі, не v1.

## Відхилені варіанти

- **Централізований хостинг файлів проєктом** — проєкт стає ретранслятором
  контенту; прямо суперечить ADR-0028/0035.
- **Серверний Telegram-бот/relay** — сервер торкається джерел і світить токен
  у APK; порушує ADR-0028 і нейтральну позицію.
- **Device-to-device (P2P) роздача файлів** — не хостить, але теж робить
  проєкт розповсюджувачем аудіо; обрано модель «джерело = Telegram».
- **Перевикористати `BROWSER`** — recovery-рушій чекає WebView, модель бреше.
- **In-app модераторський шлюз** — повертає ручну працю, яку ADR-0035 відкинув.
- **Публічне прев'ю `t.me/s/…` як добувач** — звуку не віддає, не задовольняє
  потребу.
- **Мітка «ексклюзив»** — непеpевірна обіцянка, суперечить голосу проєкту.
