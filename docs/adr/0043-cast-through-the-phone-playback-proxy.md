# Кастування через Проксі відтворення на телефоні

## Контекст

Слухач хоче перенаправляти прослуховування на телевізор чи стрімер
(Chromecast/ТВ), а не лише слухати з телефона. Наївний каст — приймач сам
тягне URL джерела — не працює на ключових джерелах: стрім віддає 403 без
`Referer` джерела-власника, частина URL підписана, cookie-bound або
сесійна, а приватний маршрут (проксі/Tor/DoH) і самозагоєння стрімів
(ADR-0019) лишилися б осторонь. Друга мережева дорога повз транспорт
порушила б принцип «один шов, один HTTP транспорт».

Рішення вже реалізовано в коді (`PlaybackProxy` #361, `CastPlaybackController`
#362, випущено у v1.3.5), але зафіксоване лише в коментарях; ця ADR дає
йому канонічний запис.

## Рішення

1. **Приймач ніколи не ходить в інтернет сам.** На телефоні піднімається
   вбудований HTTP-сервер («Проксі відтворення»), завʼязаний на Wi-Fi-адресу
   й ефемерний порт, із свіжим випадковим токеном у шляху. Приймач грає
   `http://<телефон>:<порт>/<токен>/...`, а байти бере проксі.
2. **Проксі фетчить апстрім крізь єдиний транспорт** (`HttpFetcher` /
   `getRangeStream`): per-source `Referer`, спільний OkHttp, приватний
   маршрут (проксі/Tor/DoH) і самозагоєння стрімів зберігаються без
   обхідних шляхів. Байти релеяться дослівно; чесні стани — 403 на
   неправильний токен (до будь-якого апстріму), 416 на недосяжний діапазон,
   502 на невдалий апстрім, жодних сфабрикованих тіл.
3. **`CastPlayer` підміняє локальний плеєр за наявним швом `MediaSession`**
   (`CastEngineHook` в `AudioPlayerManager`): нотифікація, апаратні кнопки
   медіа та UI працюють без змін; на кожну команду — одна точка відгалуження
   на межі рушія.
4. **Default Media Receiver**, без власного Web Receiver: немає hosted
   receiver-поверхні, яку треба тримати й захищати. Вистачає аудіо-only.
5. **Чесні стани.** Розділ без стрімового Source не кастується — захоплення
   скасовується з поясненням, а не з загадкою. Втрата приймача завершує
   сесію, а локальний рушій перепідготовлює відтворення `PAUSED` на
   дзеркальній позиції — без тихого фолбеку.
6. **Сон і Wi-Fi.** Wake- і Wi-Fi-локи тримають проксі живим при вимкненому
   екрані; URL захищені токеном.

## Відкладені альтернативи

- **Власний Web Receiver (hosted):** відкладено — Default Media Receiver
  покриває аудіо-only.
- **Прямий fetch приймачем:** відкинуто — 403-без-`Referer`, обхід єдиного
  транспорту, приватного маршруту й самозагоєння.

## Примітка про нумерацію

Коментарі в коді та `AndroidManifest.xml` досі посилаються на «ADR-0024» для
кастування (#362), але ADR-0024 — це рішення про Web Transport. Ця ADR-0043 є
канонічним записом кастування; застарілі посилання варто переспрямувати,
коли зручно.

## Наслідки

- Кастування ходить тим самим транспортом: жодної другої мережевої дороги,
  жодного тихого обходу приватності чи самозагоєння.
- Приймач свідомо «дурний»: аудіо-only, без веб-поверхні для підтримки.
- Ціна: телефон мусить лишатися досяжним у локальній мережі та не спати під
  час кастування.
