# Локальний пошуковий індекс — FTS4-проєкція Дзеркала

## Контекст

Пошук по джерелах був живим мережевим залпом на кожен новий запит:
після debounce і мінімум 2 символів `searchAllSources` ішов паралельно
по всіх адаптерах крізь Source Request Gate, половина адаптерів
відповідала порожнечею і падала у feed-fallback, а Дзеркало каталогу
пошуком не читалося взагалі. Повторний запит бив по мережі знову;
«гугл-відчуття» (набрав → миттєво побачив) не існувало.

Гриль #822 (Q1–Q15, тікети #823–#826) ухвалив: миттєвий локальний
індекс як основний шлях (назва+автор+серія+наратор), живе — лише добір
за бідною локальною відповіддю, індексація — лише через чинний
Source Request Gate без нових «підозрілих рухів».

## Рішення

1. **Носій — FTS4-проєкція Дзеркала** (`works_fts`: workId + згорнуті
   title/author/series/narrator), один рядок на Твір з ідентичністю.
   FTS4, не FTS5: FTS5/unicode61 відсутній у Robolectric SQLite, тож
   JVM-тести впали б; FTS4 працює і на пристрої, і під тестом.
   Згортка — та сама в обидва боки (CollectionMatcher-фолд:
   MergeKey-правило + зріз дужок, кирилиця недоторкана), бо bundled
   токенайзер не вміє в український регістр/конфузables.
2. **Запис — лише існуючі транзакційні дверки**: `upsertWorkWithSource` /
   `safeUpsertWorkSource` / `applyFacetRows` (нарратор) переписують рядок
   індексу в тій самій транзакції; міграція 47→48 (спершу планувалася
   44→45, перенумерована при злитті з v1.8, де 45 зайняла `readthroughs`)
   створює таблицю і бекфілить Kotlin-проходом (у SQL згортка неможлива).
   Tombstone чистить рядок на тих самих дверках; окремого
   індексатор-воркера немає.
3. **Читання — індекс першим**: достатня локальна відповідь (≥3 карток,
   ВИДИМИХ під чинним мовним фільтром — #824: FTS → фільтр мови → добір)
   повертається з нулем запитів; тонка — тримає свої рядки, живий залп
   добирає gap; gap-fill дзеркалить live-хіти bounded-20 з гардами
   scam/blank/tombstone і БЕЗ жанрових клеймів (ранг ENUMERATION не
   отруюється — жанри з пошуку лишаються SEARCH-рангу крізь чинний
   шов). Локальний ранг (точна назва → префікс → MATCH-порядок)
   застосовується поверх абеткового мерджу, лише коли індекс доклався.
4. **Гарди поверхні**: tombstone/scam ніколи не віддаються;
   BROWSER/TELEGRAM-рядок — лише за живої першосторонньої сесії (той
   самий `sessionAlive`-шов, що в мапінгу заміщення, приварений в App
   тим самим чекером); відмова не фільтрує картки (metadata untouched,
   як live) — гейт лишається на Play. Мовний фільтр і ru-виняток без
   змін; debounce/мін. 2 символи без змін; бюджетів Gate і TTL не
   чіпали.
5. **Форма MATCH — голий префікс** (`tok*`, не `"tok"*`): лапкована
   зірка не матчить нічого (перевірено і на системному SQLite 3.53, і
   під Robolectric) — прототип бенчмарку мав хибну форму, recall якої
   ніколи не асертився. Слова-оператори AND/OR/NOT/NEAR лишаються
   quoted-exact без зірки.

Відхилені ходи: розширення TSV `workIndex` (це URL-резолвер для тапу,
не контентний індекс); FTS5 (блоковано Robolectric); окремий фоновий
краулер (порушив би ритм-етику ADR-0039); SQL-бекфіл у міграції
(згортка вимагає Kotlin).

## Наслідки

- Повторний і покритий запити — нуль мережевих запитів: індекс, потім
  shared-кеш, і лише тоді мережа.
- SLO-замір (`WorkSearchSloTest`, 10k Творів, Robolectric JVM SQLite):
  18 запитів (exact/префікс/мультитокен/серія/автор) — усі локально,
  p50=0ms p95=1ms при гейті 1000ms. Серединна підстрічка, трансліт і
  одруки — задокументовані позаскопові спостереження (0 хітів), не
  асерти.
- Частковий каталог за сухого кошика лишається чесним станом (ADR-0040
  без змін); пошук не додає жодного нового ритму жодному домену.
