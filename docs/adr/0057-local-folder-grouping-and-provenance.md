# Вибір групування локальної папки

У прев’ю імпорту слухач обирає, чим є файли безпосередньо у вибраній папці:
розділами однієї книги або окремими книгами (#1052). Початковий режим —
окремі книги, як у попередніх версіях. Кожна підпапка лишається окремою
книгою в обох режимах. Назва однієї кореневої книги приходить від вибраної
папки; коли її немає, слухач має заповнити назву перед підтвердженням.
Назви файлів не є підставою для автоматичного об’єднання.

`LocalImportGrouping` задає спільне правило групування й природного
сортування для планувальника та rescan. Прямий імпорт будує план і проходить
через `applyImportPlan`. Єдиний шлях запису — `applyImportPlan`. `ImportGrantStore`
зберігає режим та назву разом із SAF-деревом після застосування плану;
старі grants без режиму означають окремі книги.

Дві заплановані книги можна явно об’єднати. Вибрана ціль зберігає свої дані,
розділи другої книги додаються в кінець. Попередня згода на приєднання до
книги в бібліотеці скидається: після зміни складу потрібне нове рішення.
Зміна режиму перебудовує тільки книги з кореневими файлами. Зроблені для них
корекції скидаються після попередження; правки інших підпапок зберігаються.
Усе це лишається чернеткою до підтвердження імпорту.

## Походження переживає корекції

Назва книги та назви Chapter належать слухачеві. Вони не можуть бути ключем
повторного сканування папки. `LocalFolderMemory` зберігає фізичне походження:
SAF-дерево, групи відносних шляхів та хеші файлів, закріплені за книгою.
Пам’ять живе в локальних `FIELD` corrections із зарезервованим ключем
`local-folder:<sha256 URI>`. Новий знімок власника замінює попередній;
пам’ять інших власників та непрочитані записи зберігаються.

Походження записується в тій самій Room-транзакції, що й локальні
Edition/Chapter/SourceTrack. Для імпорту береться хеш скопійованих байтів.
Для rescan скопійовані байти мають відповідати хешу сканування; змінений
або непрочитаний файл пропускається з чесним результатом. Скасування
прибирає тільки незбережені копії поточної групи. Раніше збережені книги
та їхні файли лишаються цілими. Відкат окремої книги показує всі незбережені
файли в результаті імпорту; дублікати рахуються окремо.

Одна книга може прийняти файли кількох SAF-дерев. Кожне дерево сканується
за власною пам’яттю, тому файли іншого дерева не вважаються зниклими.
Підтверджене об’єднання озвучень переносить походження на книгу, що лишається,
у транзакції перенесення Source; фізичні назви файлів не підміняються назвами
логічних Chapter.

## Межі повторного сканування

Живий хеш SourceTrack має перевагу. За його відсутності використовуються
збережений хеш, відносний шлях та власник групи. Так rescan знаходить
перейменовані файли й папки та зберігає підтверджені назви книг. Відома
перенесена копія не привласнює папку іншої книги. Неоднозначна папка після
розділення не отримує мовчазного власника для невідомого нового файла.

Локальна Edition отримує нові Chapter після збережених. Їхні попередні ID,
ручний порядок, Listening State та закладки лишаються незмінними (ADR-0056).
Зміна структури Edition з кількома Source відхиляється без підтвердженого
зіставлення. Зникнення оригіналу не видаляє приватну копію. Збережені хеші
видаленої книги блокують її автоматичне повернення навіть після зміни шляху;
живі треки та походження явного повторного імпорту мають перевагу над
пам’яттю видалених власників. Два живі власники після split лишаються
неоднозначними для невідомого нового файла.

Явне приєднання до наявної книги записує походження й тоді, коли всі файли
виявилися дублікатами її локальних треків. Власник хешу перевіряється
повторно всередині транзакції; дублікати іншої книги не дають права
привласнити її папку. Видалення підтвердженої цілі до першого rescan
також лишає бар’єр проти автоматичного повернення цих файлів.
