# Системне повернення та клавіатура

Застосунок явно вмикає `android:enableOnBackInvokedCallback="true"` на рівні
`application` (#1121). Навігаційні дії лишаються в AndroidX Compose
`BackHandler`: цей API підтримує завершений системний жест без окремого
обробника прогресу. Скасований жест не виконує навігаційну дію. Власні
анімації переходів за прогресом жесту тут не додаються.

## Політика та механізм — різні вимоги

Перевірено 4 жовтня 2026 року за офіційною документацією:

- [Google Play](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en-EN)
  вимагає API 36 для нових застосунків та оновлень з 31 серпня 2026 року.
  Це вимога до `targetSdk`, а не окрема вимога явно записати прапорець `true`.
- [Android 16](https://developer.android.com/about/versions/16/behavior-changes-16#predictive-back)
  для `targetSdk >= 36` вмикає системні predictive back анімації за замовчуванням.
  Старий `onBackPressed` та доставка `KEYCODE_BACK` у застосунок більше не є
  шляхом перехоплення. Потрібні підтримувані callbacks або тимчасовий opt-out.
- [AndroidX Compose](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture)
  рекомендує `BackHandler`, коли потрібна лише дія після завершення жесту.
  `PredictiveBackHandler` потрібен для власної реакції на прогрес.

Явний прапорець прибирає неоднозначність налаштування на API 33–35 та
попередження про неввімкнені callbacks. Сам по собі він не змінює правил
повернення всередині застосунку і не виправляє конфлікт із клавіатурою.

## Перший Back належить IME

Під час нативної перевірки пошук із відкритою клавіатурою перехоплював Back
обробником очищення запиту: клавіатура могла лишатись відкритою. Це
відтворилось і з явним прапорцем. У пошуках Огляду та Медіатеки обробник
очищення вимкнений, доки `WindowInsets.isImeVisible` має значення `true`.

Тому перший системний Back ховає клавіатуру та зберігає текст. Наступний
очищає непорожній запит. Порожній пошук передає Back звичайній навігації;
на корені це системне повернення до попереднього завдання. Правило однакове
для жесту й кнопки Back. Інші навігаційні обробники зберігають свій scope.

## Межа перевірки

`SettingsNavigationTest` використовує справжній IME та системне введення,
бо семантична дія редагування тексту сама по собі не доводить, що клавіатура
була відкрита. Жестова перевірка запускається без скрипта, який примусово
перемикає пристрій на три кнопки. Скрипт і CI перевіряють також кнопковий
шлях. Нативні логи та знімки лишаються поза репозиторієм (ADR-0016).
