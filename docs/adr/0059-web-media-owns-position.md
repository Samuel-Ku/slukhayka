# Позицію вебплеєра повідомляє медіаелемент (#934)

Таймер двигуна рухав позицію й розділ незалежно від `<audio>`. Під час
буферизації індекс міг змінитися без зміни аудіо, а `ended` робив ще один
перехід. Дві незалежні дороги не можуть гарантувати один перехід.

## Рішення

1. `HTMLAudioElement.currentTime` — фактична позиція. `PlaybackEngine`
   зберігає її через `observePosition`, без множення на швидкість та без
   обмеження джерельною тривалістю. Тривалість у метаданих може помилятися.
   Лише явні seek, load та Smart Rewind командують зміною позиції елемента.
2. `PlaybackEngine.tick(deltaMs)` прибраний. `timeupdate` та адаптерний
   тікер читають елемент; тікер не рухає позицію й не перемотує аудіо.
3. Природне завершення має одну дорогу. Актуальна підтверджена медіасесія
   з активним наміром Play та `audio.ended === true` споживається один раз; адаптер або готує
   наступний розділ з нуля, або записує завершення останнього. Старий
   callback, повторний event або пізня відповідь play не керують новою сесією.
4. Якщо `ended` event не доставлено у фоні чи офлайні, властивість
   `audio.ended` читається на тіку та при поверненні сторінки. Якщо браузер
   не повідомив завершення навіть цією властивістю, лишається остання
   фактична позиція. `paused`, `waiting`, досягнення metadata duration чи
   настінний час самі не доводять завершення.
5. Звичайний таймер сну рахує час незалежно від позиції аудіо. Режим
   «до кінця розділу» читає медіа й зупиняється перед автоматичним
   переходом; буферизація та зміна швидкості не вигадують кінець розділу.

## Наявні гарантії

18 тестів чистого двигуна зберігають load, pause, speed, seek, rewind,
спроби fallback і підписки. Перевірки таймерного поступу замінені точним
дзеркаленням медіапозиції та забороною самостійного переходу. Природний
перехід і завершення перевіряються через публічний `AudioEngine`, разом із
позицією елемента, джерелом і персистованим Listening State. Додаткові
тести покривають тік + timeupdate + ended, старі події, буферизацію,
seek, швидкість, сон та відновлення. Реальне медіа перевіряється у браузері.

Офлайн-кеш і прямий/relay порядок не змінюються. Єдина позиція працює
однаково для HTTP і кешованих байтів. iOS Safari та встановлена PWA
залишаються платформами окремої перевірки (ADR-0034); настільний браузер
не доводить їхню поведінку.
