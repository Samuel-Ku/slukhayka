## 4. Сценарії gate (з чеклісту #437/#434, розгорнуто)

Для кожного пункту: `pass / fail / partial` + 1–2 рядки деталей.

1. **JVM зелений.** `bash scripts/test-all.sh` — 0 падінь, включно з
   `WorkSourceFkRegressionTest`.
2. **Браузерне відновлення наявної 4read-книги.** Медіатека → книга,
   імпортована з 4read раніше (стрім, який вже не грає) → Play → очікується
   чесна відмова → «Оновити через браузер» → відкривається вбудований
   WebView на 4read → якщо з'явиться Cloudflare — пройти → відкрити книгу і
   запустити «Слухати» на сайті → аудіо захоплюється → браузер закривається
   сам → плеєр продовжує з ТОГО САМОГО розділу і позиції. Зафіксуй книгу,
   розділ, позицію до/після.
3. **Повторне відновлення без дубліката.** Повтори п.2 на тій самій книзі →
   у медіатеці не з'являється другий Work/Edition/Source.
4. **Мертве аудіо ≠ успіх.** Якщо після recovery стрім не грає — застосунок
   НЕ оголошує успіх; браузер лишається відкритим з повідомленням
   «Аудіо ще не знайдено…».
5. **Пряме джерело стартує без браузера.** Рекомендована книга з
   direct-джерелом (soundbooks / audiobookmp3 / lihtar / sluhayua) починає
   грати без WebView; прямі проби не затягуються надовго (~10 с бюджет).
6. **Блок «Джерела» на сторінці книги.** Порядок local → direct → unknown →
   browser; біля 4read — «Потрібен браузер»; TalkBack читає стан рядка
   (stateDescription); рядки НЕ клікабельні — тап нічого не робить.
7. **Cookie-ізоляція.** У вбудованому браузері 4read спроба переходу на
   чужий хост блокується з повідомленням «Перехід за межі … заблоковано»;
   після сесії 4read cookie не з'являються на інших доменах.
8. **Працює з вимкненим Firebase.** Той самий сценарій recovery при
   вимкненому Firebase (на debug-збірці — див. зауваження вище).
9. **Тап «Сни» не крашить** (регресія #388). Медіатека → книга «Сни» →
   відкривається без падіння процесу.

## 6. Межі (обов'язково)

- **Не пушити, не мержити, не тегувати.** Merge й тег — людина.
- **Не міняти код** у цьому завданні (виняток: жодного).
- **Паралельна робота:** у цьому робочому дереві може одночасно працювати
  інший агент (факт 2026-08-30: у DAO двічі з'являлася стороння no-op
  заглушка). Перед комітами перевіряй `git status`/`git diff`; якщо бачиш
  чужі незакомічені зміни — НЕ затирай їх, а зазнач у звіті.
- JVM-тести і CI — єдине джерело «зеленості»; «зібралось у мене» не рахується.
