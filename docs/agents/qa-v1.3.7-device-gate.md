## 4. Сценарії gate (з чеклісту #437/#434, розгорнуто)

Для кожного: `pass / fail / partial` + 1–2 рядки деталей. ЙДИ ПО ПОРЯДКУ —
кроки A–B готують дані для сценаріїв 1–3.

### Крок A. Пряме джерело (сценарій 4)

Пошук → картка книги з direct-джерела (audiobookmp3 — у базі вже є
«Без Меріт») → тап → очікується відтворення БЕЗ браузера, бюджет ~10 с.
Лог-підтвердження: `adb logcat -d -s AudioPlayer:*` містить `HTTP 200` на
трек (формат: `https://*.redirectto.cc/.../track-N.mp3`). Прогін 15:03
вже показав 200 — повтори і зафіксуй.

### Крок B. Імпорт 4read-книги через нові двері (передумова сценаріїв 1–3)

Пошук → знайди книгу, чиї джерела ТІЛЬКИ 4read (напр., «Сни» Лесь Курбас)
→ тап по картці → очікується snackbar «Ця книга лише на 4read — потрібен
браузер» з дією **«Відкрити»** (нове, 47691e3; раніше тап мовчав) →
вбудований браузер відкриває пошук 4read з prefilled назвою → знайди
книгу на сайті → натисни «Слухати» на сайті → з'явиться «Додати цю книгу»
→ імпорт → книга у медіатеці. Якщо snackbar не з'явився або двері не
працюють — це **fail сценарію-передумови**, фіксуй окремо (це найсвіжіший
код у збірці).

### Сценарії

1. **Браузерне відновлення наявної 4read-книги.** Спершу зроби стрім
   «мертвим» чесним шляхом: force-stop застосунку
   (`$ADB shell am force-stop com.slukhayka.audiobooks.debug`), зачекай
   ~10 хв (4read-стріми протухають), повтори Play. Якщо стрім досі грає —
   познач `partial` з причиною «стрім ще живий», НЕ ламай мережу навмисно
   (recovery теж потребує мережі). Далі: Play → очікується чесна відмова →
   «Оновити через браузер» → вбудований WebView на 4read → якщо з'явиться
   Cloudflare — пройти → відкрити книгу і запустити «Слухати» на сайті →
   аудіо захоплюється → браузер закривається сам → плеєр продовжує з ТОГО
   САМОГО розділу і позиції. Зафіксуй книгу, розділ, позицію до/після.
2. **Повторне відновлення без дубліката.** Повтори п.1 на тій самій книзі →
   у медіатеці не з'являється другий Work/Edition/Source.
3. **Мертве аудіо ≠ успіх.** Якщо після recovery стрім не грає — застосунок
   НЕ оголошує успіх; браузер лишається відкритим з повідомленням
   «Аудіо ще не знайдено…».
4. **Пряме джерело стартує без браузера.** = крок A (результат перенесись).
5. **Блок «Джерела» на сторінці книги.** Порядок local → direct → unknown →
   browser; біля 4read — «Потрібен браузер»; TalkBack читає стан рядка
   (stateDescription); рядки НЕ клікабельні — тап нічого не робить.
   Примітка: якщо книга імпортована пошуком, рядок джерела приходить з
   fallback-гілки (давній пропуск, розділ 8) — перевіряй порядок і стан,
   не кількість рядків.
6. **Cookie-ізоляція.** У вбудованому браузері 4read перехід на чужий хост
   блокується з повідомленням «Перехід за межі … заблоковано»; після сесії
   cookie 4read не з'являються на інших доменах.
7. **Працює з вимкненим Firebase.** Той самий сценарій recovery при
   вимкненому Firebase (див. N/A-застереження в розділі 3).
8. **Тап «Сни» не крашить** (регресія #388). Книги «Сни» в базі може НЕ
   бути (базу стерто) — тоді імпортуй її через крок B і перевір тап по
   сторінці книги (відкривається без падіння процесу). Якщо «Сни» немає на
   4read — візьми будь-яку іншу 4read-книгу з кроку B і познач `pass
   (еквівалент, книга X)`.

## 8. Відомі обмеження лінії (не вважати багом gate)

- **Firestore PERMISSION_DENIED у логах debug-збірки — очікуваний шум**, не
  блокер: у проєкті не увімкнений Firestore API; локальний gitignored
  `app/google-services.json` змушує debug-збірку ініціалізувати Firebase.
  Спільні метадані/профілі — fail-silent за дизайном (тест #431). Каталог і
  відновлення працюють через HTTP-адаптери, не Firestore — порожній Огляд
  не означає «заблоковано».
- **Сценарії 1–6 не позначай N/A через Firestore-логи** — минулий прогон
  зробив це помилково: каталог живе на HTTP-адаптерах.
- **Порожня таблиця `work_sources` після пошукового імпорту — давній
  пропуск, НЕ регресія** (те саме на origin/main): рядок Work→Source
  пишуть лише crawl/feed-двері. Блок «Джерела» працює через fallback.
- 4read-книг у медіатеці debug-інсталяції немає (базу стерто
  перевстановленням 2026-08-30) — їх створює крок B; `install -r` далі
  дані зберігає.
- `testRoomNativeSdk36` при першому локальному запуску тягне android-all
  SDK 36 і може виглядати як timeout — повтори з більшим таймаутом; остаточна
  зеленість партицій — CI.
- #431 покритий частково: читання verified-профілю ДО відкриття браузера і
  stale-логіка не імплементовані — recovery завжди йде браузером.
- Вердикт recovery — HTTP HEAD-проба, а не реальний запуск у Player
  (сценарій 3 перевіряє це з людського боку).
- `scripts/check-4read-stream.py` ще не оновлений під новий контракт
  (Wave F-4, після gate).
