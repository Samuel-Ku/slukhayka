## 3. Сценарії на новому smoke APK (йди по порядку)

Перед кожним: `$ADB -s <адрес> logcat -c`; після — `-d -s AudioPlayer:*`.

1. **Артефакт і підпис.** Завантажити smoke нового запуску CI,
   звірити SHA-256 з артефактом, сертифікат — з розділом 0.
   `install -r` поверх чинного release 1.3.9(d91c8968). Медіатека й
   прогрес мають лишитися (це ще один крок оновлення, уже без міграції).
2. **Швидкий дим людей.** Огляд → «Виконавці» → людина → Back.
   Код людей не мінявся після 9ad53c8c, але дотик дешевий.
3. **Сторінка книги (#552–555).** Відкрити книгу з довгою назвою
   циклу: повна обкладинка без обрізання, меню замість дубля дій,
   єдиний блок дій перед описом, мініплеєр двома рядками; перехід
   до автора/начитувача/циклу і Back з фокусом на посиланні.
4. **Відгуки після прослуховування (97030cf3).** Кнопка «Ваші
   враження» наприкінці списку розділів: форма розгорнута, зірки
   книги й озвучки незалежні, збереження/«Не зараз». Публікацію у
   Firebase перевіряти не треба (звіт мейнтейнера це прямо виключає).
5. **Реальне відновлення мертвого джерела** — досі відкритий пункт
   хвилі 551: мертвий стрім → чесна відмова → браузерні двері → та
   сама позиція. Дані вже пережили два оновлення.
6. **Інструментовані opt-in тести** (приватні маршрути
   `liveRouteTest=true`, перезапуск процесу, фокус): телефонний
   debug-пакет під ключем мейнтейнера, тому запускаються з середовища
   мейнтейнера або після його явного дозволу на заміну пакета.
   Окремо узгодити з користувачем; у звіті позначити, хто запускав.

Сценарії 2–4 на рівні коду вже покриті тестами мейнтейнера на тому
самому коді (97030cf3) — тут вони контрольні, на release-підписаному
пакеті.

## 4. Протокол і межі

- Результати допиши в `docs/audits/2026-09-06-139-gate-run.md`
  (новий розділ) з датою, збіркою (SHA), logcat-фрагментами при падінні.
- **Не пушити, не тегувати, не мержити.** Тег — людина після зеленого
  звіту.
- **Не міняти код.** Fail → нотатка в аудиті + окремий issue
  (`ready-for-human`); виправлення отримують новий коміт і власний
  зелений CI — тоді цей гейт повторюється на новому артефакті.
- У цьому дереві може працювати паралельний агент: перед `git add`
  перевіряй `git status`; чужі незакомічені зміни не чіпай.
