# «Слухайка» — реструктуризація вкладок від фактичного коду
### Поточна IA → цільова Netflix-подібна модель → конкретні рішення для `ListenScreen`, `HomeScreen`, `LibraryScreen`

_Оновлено: 2026-08-16. Основа цього документа — фактичний порядок блоків, який надано з Compose-коду, а не лише скриншоти._

---

## 0. Головний висновок

Проблема не в нестачі контенту й не в якості окремих карток. Проблема в тому, що **всі три вкладки намагаються одночасно бути головною, каталогом, рекомендаціями та бібліотекою**.

Зараз:

- **«Слухати»** починається правильно (Hero), але далі змішує 8 персональних робочих сценаріїв, каталогові новинки з кожного джерела та зовнішній промо-блок Sluhay.
- **«Огляд»** має правильні верхні входи (каталог/жанри/колекції), але руйнує discovery-ієрархію: нескінченний каталог стоїть **раніше** за персональні рекомендації, добірки за тривалістю та редакційні ряди 4read.
- **«Медіатека»** показує шість рядів керуючого UI до першої книги. Користувач приходить побачити колекцію, але спочатку бачить інструменти для керування нею.

Цільовий принцип:

> **Слухати = повернутися до свого. Огляд = знайти нове. Медіатека = знайти й керувати тим, що вже додано.**

Якщо кожен блок не відповідає на одне з цих трьох питань — він лежить не на своєму місці.

## 1. Поточний стан: що саме створює перевантаження

| Вкладка | Фактичний порядок зараз | Проблема ієрархії |
|---|---|---|
| **Слухати** | Hero → 8 персональних вертикальних повноширинних карток → «Нове на 4read» → «Нове з кожного джерела» → «Більше книг на Sluhay» | Після Hero користувач бачить довгу task-list, а не контентну вітрину. Вкладка змішує персональне, каталожне та промо-зовнішнє |
| **Огляд** | Каталог → Жанри → Колекції → Весь каталог (infinite paged feed) → Рекомендовано → За тривалістю → 4read: Новинки/Цикли | Найцінніше discovery заховане **після** безкінечної стрічки; до нього майже ніхто не доскролить |
| **Медіатека** | Header + 2 кнопки → Sub-tabs → Search → 7 чіпів → sort + layout → storage/delete → список | 6 рядів control chrome до першої книги; верх екрана виглядає як адмін-панель, а не як книжкова полиця |

### Діагноз за патернами стримінг-продуктів

Netflix-подібний інтерфейс має вертикальну логіку:

```text
1. Найімовірніша дія зараз
2. Особистий/кураторський ряд, який зменшує вибір
3. Ще один зрозумілий привід вибрати
4. Повний каталог — лише коли користувач свідомо хоче переглядати все
```

Поточна модель робить навпаки в двох місцях:

- у «Слухати» дає **8 великих спискових рішень** підряд;
- в «Огляді» ставить **все** раніше за кращі рекомендації.

## 2. Цільова інвентаризація контенту

### 2.1. Правило розміщення

| Тип контенту | Єдина правильна вкладка | Приклади |
|---|---|---|
| Книга, яку користувач уже почав або додав у чергу | **Слухати** | Продовжити, дослухати, наступна у серії |
| Книга, яку користувач зберіг/імпортував/завантажив | **Медіатека** | Усі, Слухаю, Завершені, Завантажені, Обране |
| Книга, якої ще немає у користувача | **Огляд** | Новинки 4read, колекції, жанри, ТОП 100, рекомендації |
| Глобальна дія | Шапка, контекстне меню або окремий екран | Пошук, імпорт, керування завантаженнями |
| Зовнішнє джерело/партнер | **Огляд**, найнижчий рівень | «Більше книг на Sluhay», джерельні ряди |

### 2.2. Наслідок для наявних блоків

| Поточний блок | Рішення | Нове місце |
|---|---|---|
| Hero «Продовжити слухати» | **Лишити** | «Слухати», найвище місце |
| 8 персональних блоків | **Злити до 4–5 поличок**, перетворити з full-width row на horizontal poster rail | «Слухати» |
| «Нове на 4read» | **Перенести** | «Огляд» → Новинки джерел |
| «Нове з кожного джерела» | **Злити** з «Новинки джерел»; перемикач джерела або секції всередині | «Огляд», нижче персональних/популярних рядів |
| «Більше книг на Sluhay» | **Прибрати з основного фіду**; лишити як компактний footer CTA/вихід до джерела | Низ «Огляду» або окремий Source Hub |
| «Весь каталог» (Paging) | **Лишити**, але перенести після всіх editorial/personalized rows | «Огляд», остання основна секція |
| «Рекомендовано для вас» | **Підняти вище каталогу** | «Огляд», позиція 1–2 |
| «За тривалістю» | **Лишити як ряд**, не як складний браузер | «Огляд», після рекомендацій |
| 4read Новинки / Цикли | **Лишити**, але зробити єдиним блоком «Від 4read» | «Огляд», після універсальних добірок |
| Рядок пам'яті + «Видалити» | **Винести** | `⋮` → «Завантаження та пам'ять» |

## 3. Нова вкладка «Слухати»

### 3.1. Її єдина робота

Користувач відкриває вкладку з думкою: **«Я хочу продовжити»**, а не «Покажи мені всі джерела, які оновили каталог».

Тому «Слухати» — не каталог і не агрегатор фідів. Це персональна стартова панель, де все відсортовано за близькістю до поточної дії.

### 3.2. Цільовий порядок

```text
🎧 СЛУХАТИ
│
├── 1. HERO: Продовжити слухати
│      Велика картка однієї поточної книги
│      Обкладинка · назва · автор · «Розділ 11 із 65» · progress · Play
│
├── 2. ПРОДОВЖИТИ
│      Горизонтальна полиця PosterCard
│      Усі початі, але не активні книги
│      На постерах: тонкий прогрес + «залишилось N год»
│
├── 3. ДОСЛУХАТИ ДО КІНЦЯ
│      Горизонтальна полиця, тільки залишок < 60–90 хв
│      Найсильніший “quick win” рядок
│
├── 4. ДАЛІ У СЕРІЇ
│      Горизонтальна полиця продовжень до початих циклів
│      Показується, лише якщо є релевантні дані
│
├── 5. ЩОСЬ КОРОТКЕ
│      Горизонтальна полиця «до 1 години»
│      Показується за наявності часу/доречності; не обов'язково завжди
│
└── 6. ВІД ВАШИХ АВТОРІВ
       Горизонтальна полиця; тільки нові/непочаті книги авторів з історії
```

### 3.3. Як саме перетворити 8 блоків

Не всі 8 блоків мають бути видимі одночасно. Вони — хороші **алгоритмічні сигнали**, але погані як 8 незалежних UI-секцій.

| Група алгоритму | Цільовий UI-рядок | Умова видимості | Максимум карток |
|---|---|---|---|
| `HERO` | Продовжити слухати | Є active/in-progress книга | 1 |
| `RETURN` / started books | Продовжити | Є інші незавершені | 8–12 |
| `ALMOST_DONE` | Дослухати до кінця | Залишок до 60–90 хв | 6–8 |
| `NEXT_IN_SERIES` | Далі у серії | Є наступна книга в серії | 6–8 |
| `SHORT` + `TRAVEL` | Щось коротке | Не менше 4 релевантних книг | 8 |
| `FAVORITE_AUTHORS` | Від ваших авторів | Є достатньо новинок | 8 |
| `RECENTLY_ADDED` | **Не рендерити тут** | — | — |

### 3.4. Важливий UI-фікс: вертикальні повноширинні картки → горизонтальні полиці

Поточний `ListenBlockBookRow` як full-width рядок доречний для:

- однієї Hero-картки;
- бібліотеки, де користувач сканує назви;
- результатів пошуку.

Він **не доречний** для 8 рекомендаційних секцій поспіль: це створює довгий «список задач», а не відчуття медіасервісу.

Цільовий компонент:

```text
PosterRail(title, items)
├── SectionHeader: «ДОСЛУХАТИ ДО КІНЦЯ»                   [Усі →]
└── LazyRow(contentPadding = horizontal 16dp)
    └── PosterCard × N
        ├── Cover: 112×168dp, ratio 2:3, radius 12dp
        ├── ProgressTrack: 3dp, по нижньому краю обкладинки
        ├── Title: 2 рядки max
        └── Meta: «44 хв лишилось» / «Книга 2»
```

**Постер-ряд дає Netflix-відчуття не тому, що він горизонтальний сам по собі, а тому, що:**

1. він дозволяє швидко впізнати обкладинку периферійним зором;
2. показує 3–4 варіанти без відчуття зобов'язання прочитати кожен рядок;
3. зберігає вертикальний скрол для різних причин слухати, а горизонтальний — для вибору всередині причини.

### 3.5. Дедуплікація на рівні екрана

Ввести `visibleWorkIds: MutableSet<WorkId>` під час складання фіду:

```text
Hero             → reserve 1 workId
Продовжити       → exclude visibleWorkIds
Дослухати        → exclude visibleWorkIds
Далі у серії     → exclude visibleWorkIds
Щось коротке     → exclude visibleWorkIds
Від авторів      → exclude visibleWorkIds
```

Пріоритет фіксований: Hero > Продовжити > Дослухати > Серія > Коротке > Автори.

Результат: «Трохи ненависті» може бути або Hero, або в «Продовжити», але не повторюється тричі на одному екрані.

## 4. Нова вкладка «Огляд»

### 4.1. Її єдина робота

«Огляд» відповідає не на «де мої файли?», а на: **«Що я захочу слухати наступним?»**

Тому вертикальний порядок має йти від найкоротшого шляху до вибору до найбільшого простору дослідження. Нескінченний каталог — це режим *я готовий довго шукати*, а не верхня частина discovery-екрана.

### 4.2. Цільовий порядок

```text
🧭 ОГЛЯД
│
├── AppBar: «Слухайка»                                  [🔍]
│
├── Search pill: «Назва, автор, читач…»
│
├── Швидкі входи (NavChip row)
│      [ТОП 100] [Автори] [Виконавці] [Серії]
│
├── ЖАНРИ (один-єдиний рядок FilterChip)
│      [Усі] [Фентезі] [Роман] [Жахи] [Драма] →
│
├── РЕКОМЕНДОВАНО ДЛЯ ВАС
│      PosterRail (лише коли є історія)
│
├── НОВИНКИ
│      PosterRail, крос-джерельний, дедупліковані Work
│
├── ПОПУЛЯРНЕ ЗАРАЗ
│      PosterRail; сюди може живити ТОП 100
│
├── ЗА ТРИВАЛІСТЮ
│      [До 1 год] [1–5 год] [На вихідні] →
│      один PosterRail, який змінюється за вибором
│
├── ВІД 4READ
│      Sub-tabs/segment: [Новинки] [Цикли]
│      PosterRail
│
├── ВІД ІНШИХ ДЖЕРЕЛ
│      Лише коли реально є щонайменше 6 якісних позицій
│
└── ВЕСЬ КАТАЛОГ
       [Сортувати ▾] [Фільтри ▾]
       Paginated grid: 2 колонки (mobile) / WorkCard
```

### 4.3. Що кардинально змінюється

#### A. «Весь каталог» переїжджає вниз

Зараз `Paged feed` лежить перед «Рекомендовано для вас», «За тривалістю» і розділами 4read. Це означає, що нескінченна стрічка — візуально головніша за якісний вибір.

**Рішення:** `Весь каталог` — остання секція. Він все ще доступний, але користувач спочатку отримує 3–5 зрозумілих причин натиснути Play.

Якщо потрібна дуже швидка дорога до всього каталогу — `Увесь каталог →` має бути дією справа в заголовку «Новинки»/«Популярне» або окремим NavChip, а не раннім безкінечним блоком.

#### B. «Рекомендовано» стає верхньою персональною полицею

Після пошуку, навігації й жанрів це має бути перший контентний рядок. Він бере на себе Netflix-роль «For You».

Якщо історії нема — рядок не показується. Замість нього «Новинки» автоматично піднімаються на його місце. Не показувати placeholder із фальшивими персональними рекомендаціями.

#### C. Джерела не мають керувати IA

«Нове на 4read» та «Нове з кожного джерела» — це внутрішня модель отримання контенту, а не модель мислення користувача.

Правильний порядок:

```text
користувацька причина → джерело як метадані
```

а не:

```text
джерело → рядок контенту → користувач сам здогадується, чому він тут
```

Тобто: «Новинки», «Популярне», «Цикли» — назви секцій. `4read` — маленький source badge на WorkCard або нижній рівень «Від 4read».

### 4.4. Колекції: коли вони корисні

`Колекції` не повинні бути ще одним рядком кнопок без конкретного результату. Вони мають бути редакційними дверима з однією зрозумілою обіцянкою:

| Добре | Слабко |
|---|---|
| «Фентезі на довгі вечори» | «Колекції» |
| «Українська класика» | «Добірка 4read #12» |
| «Книги до 5 годин» | «Категорії» |
| «Почати нову серію» | «Цикли» без пояснення |

Залишити entrypoint «Колекції» у швидких входах лише якщо це повноцінний каталог редакційних наборів. Інакше перетворити поточні колекції на конкретні `PosterRail` всередині Огляду.

## 5. Нова вкладка «Медіатека»

### 5.1. Її єдина робота

Медіатека — це **інструмент пошуку й керування власною колекцією**, але не панель налаштувань. Книга повинна з'являтися на екрані якомога раніше.

### 5.2. Від шести рядів chrome до «progressive disclosure»

#### Зараз

```text
1. Заголовок + [Додати аудіо] [Папку]
2. [Книги] [Закладки] [Статистика]
3. Пошук
4. 7 filter chips
5. Сортування + layout toggle
6. Пам'ять + Видалити
7. Перший рядок книги
```

#### Цільовий стан

```text
📚 Медіатека                                      [⋮]
[Книги (167)] [Закладки (1)] [Статистика]

🔍 Пошук у моїх книгах…

[Усі] [Слухаю] [Нові] [Завершені] [Завантажені] [♥] →
Сортування: Нещодавно слухані ▾                         [☷]

──────────────────────────────────────────────────────
[Обкладинка] Трохи ненависті                     [⋮]
             Джо Аберкромбі
             ▓▓▓▓░░░░░░ · залишилось 14 год

[Обкладинка] Жертва з космосу                     [⋮]
             Роберт Шеклі
             ▓▓▓▓▓▓▓▓▓▓ · Завершено
```

Умовно це чотири ряди до контенту, але перші два дуже компактні. Головне: **пам'ять, імпорт і режим відображення перестають займати постійне місце**.

### 5.3. Де повинні жити нинішні елементи

| Елемент | Нове місце | Причина |
|---|---|---|
| «Додати аудіо» + «Папку» | FAB/іконка `＋` у top bar або `＋ Додати` як один компактний CTA; натискання → bottom sheet «Файл / Папка» | Дві великі кнопки не потрібні постійно; це одна дія з двома шляхами |
| Sub-tabs Книги/Закладки/Статистика | Лишити вгорі як `PrimaryTabRow` | Це зміна режиму, не фільтр |
| Пошук | Лишити | Єдина control-дія, яка має бути постійно видима |
| 7 фільтрів | Скоротити базові до: Усі / Слухаю / Нові / Завершені; Завантажені + ♥ — у горизонтальному хвості або `Фільтри` sheet | Базові стани читаються миттєво; рідкісні не мають тиснути на список |
| Сортування | Лишити одним рядком (`Нещодавно слухані ▾`) | Важливо, але компактно |
| Grid/list toggle | У `⋮` або поруч з сортом лише якщо grid реально потрібен | Не давати контроль, який 90% користувачів не міняють, постійно |
| Пам'ять + «Видалити» | `⋮` → «Завантаження та пам'ять» | Це сервісний екран; «Видалити» не може маскуватися під безпечний utility-рядок |

### 5.4. Чому Медіатека не має бути Netflix-стрічками

Netflix-естетика не означає робити кожен екран горизонтальними постерами.

| Екран | Переважний патерн | Чому |
|---|---|---|
| Слухати | Hero + PosterRail | Вибір за ситуацією, емоційний контент |
| Огляд | PosterRail + фінальна grid | Discovery, обкладинка важливіша за точні деталі |
| Медіатека | Щільний ListRow, за бажанням grid toggle | Користувач шукає конкретну річ, сканує назву, стан і прогрес |

Тобто Медіатека має відчуватися як **«Моя колекція в Netflix»**, а не як копія Home. Там допустимі щільні рядки та більше інформації на елементі.

## 6. Компонентні контракти для Compose

### 6.1. Не створювати новий дизайн для кожного блока

Потрібно всього чотири базові компоненти.

```kotlin
HeroContinueCard(
    work: Work,
    progress: ListeningProgress,
    onPlay: () -> Unit,
    onOpen: () -> Unit
)

PosterRail(
    title: String,
    subtitle: String? = null,
    items: List<Work>,
    itemMeta: (Work) -> String?,
    onSeeAll: (() -> Unit)? = null
)

CatalogWorkCard(
    work: Work,
    sourceCount: Int,
    onOpen: () -> Unit
)

LibraryWorkRow(
    work: Work,
    progress: ListeningProgress?,
    source: Source?,
    onOverflow: () -> Unit
)
```

### 6.2. Компонентний словник

| Контекст | Компонент | Не використовувати |
|---|---|---|
| Одна активна книга | `HeroContinueCard` | Повторну велику картку нижче |
| Рекомендація/добірка | `PosterRail` | `ListenBlockBookRow` × 8 вертикально |
| Весь каталог | `CatalogWorkCard` у `LazyVerticalGrid` | Повноширинні картки з надлишком метаданих |
| Особиста колекція | `LibraryWorkRow` | Poster rails як основний вигляд |
| Серія | `SeriesCard` (обкладинка + «7 книг») | Розсипати всі томи серії впереміш із рештою за замовчуванням |

## 7. Ранжування: що показувати, а що ховати

### 7.1. Правила показу секції

Секція не рендериться, якщо вона не має мінімально достатньої якості:

| Секція | Мінімум для показу | Якщо не виконується |
|---|---|---|
| Продовжити | 1 інша незавершена книга | Приховати |
| Дослухати | 2 книги з залишком < 90 хв | Приховати або злити в «Продовжити» |
| Далі у серії | 2 релевантні продовження | Приховати |
| Щось коротке | 4 якісні книги | Приховати |
| Від авторів | 4 нові книги | Приховати |
| Від джерела | 6 якісних новинок | Приховати; не показувати порожній «фід» |

Це вирішує проблему восьми секцій: алгоритм може формувати 8 кандидатних груп, але UI показує лише ті 4–6, які реально варті місця на екрані.

### 7.2. Загальний ліміт вертикального фіду

- «Слухати»: Hero + до 5 `PosterRail`.
- «Огляд»: search/nav/genre chrome + до 5 `PosterRail` перед «Весь каталог».
- «Медіатека»: 3–4 control rows, далі одразу список.

Це не обмежує сам каталог; це обмежує **кількість причин, за якими інтерфейс змушує користувача думати за один екран**.

## 8. Послідовність впровадження

### P0 — змінити IA без переробки даних

1. У `HomeScreen`: перенести `Рекомендовано для вас`, `За тривалістю`, `4read Новинки/Цикли` **вище** `Весь каталог`; paged feed залишити останнім.
2. У `ListenScreen`: прибрати з вкладки `Нове на 4read`, `Нове з кожного джерела`, `Більше книг на Sluhay`; новинки перенести у `HomeScreen`.
3. У `LibraryScreen`: перенести пам'ять/видалення в `⋮` і залишити у видимій області тільки таби, пошук, короткі стани, сортування.
4. Скоротити видимі персональні блоки «Слухати» до максимум шести через мінімальні пороги з розділу 7.1.

### P1 — привести патерн до Netflix-полиць

1. Замінити `ListenBlockBookRow` у recommendation-секціях на `PosterRail` + `PosterCard`.
2. Запровадити `visibleWorkIds` для дедуплікації екрана «Слухати».
3. Уніфікувати картки Огляду: `WorkCard` показує обкладинку, назву, автора, тривалість/джерело; почата книга — progress strip.
4. Злити «Нове на 4read» і «Нове з кожного джерела» у крос-джерельні «Новинки» з source badges.

### P2 — якість персоналізації

1. Підняти «Рекомендовано для вас» як найпершу полицю Огляду, лише якщо є історія.
2. Реалізувати персональний заголовок: «Бо ви слухали „Пан“», «Продовжити фентезі».
3. Додати time-aware перестановку: ввечері «Щось коротке» вище; за наявності дороги/офлайну — «У дорогу» вище.
4. Згортати серії у Медіатеці й виводити `SeriesCard`.

## 9. Контрольний список після змін

- [ ] Після відкриття «Слухати» Play для поточної книги доступний без скролу.
- [ ] У «Слухати» немає жодного рядка «Нове з джерела» чи зовнішнього промо.
- [ ] На одному viewport «Слухати» немає двох карток тієї самої книги.
- [ ] Кожна персональна секція — горизонтальна полиця, не вервечка full-width row.
- [ ] У «Огляді» «Рекомендовано», «Новинки», «Популярне» видно **до** «Весь каталог».
- [ ] У «Огляді» жанри є лише в одному місці.
- [ ] У «Медіатеці» перша книга або empty state видно без подолання сервісного рядка пам'яті.
- [ ] «Видалити» не розміщене поруч із загальними фільтрами й завжди вимагає явного підтвердження.
- [ ] Кожен source-row має користувацьку назву («Новинки», «Цикли»), а джерело є метаданими, не головною навігацією.
