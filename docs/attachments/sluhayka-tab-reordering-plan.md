## 0. Діагноз: три структурні проблеми, видимі тільки з коду

| # | Проблема | Де | Наслідок |
|---|---|---|---|
| **P-A** | Персональні блоки рендеряться **вертикальними повноширинними картками** (`ListenBlockBookRow`, L397), а не горизонтальними полицями | Слухати | 8 блоків × ~1 книга на екран = ~4–5 скролів, щоб побачити все. Головна перешкода «Netflix-відчуття» — воно тримається саме на горизонтальних полицях |
| **P-B** | Каталогові фіди живуть усередині «Слухати»: «Нове на 4read» (L201–214), «Нове з кожного джерела» (L224), «Більше книг на Sluhay» (L253) | Слухати | Вкладка змішує два інтенти: «дослухати моє» і «шукати нове». Разом із 8 блоками це ~11 секцій на одному екрані |
| **P-C** | Нескінченна paged-стрічка «Весь каталог» (L413) стоїть **не останньою**: після неї — «Рекомендовано для вас», «За тривалістю», «Розділи з 4read» | Огляд | Все, що після нескінченного списку, **фізично недосяжне** — користувач ніколи туди не доскролить. Персональні рекомендації існують, але ніхто їх не бачить |
| **P-D** | 6 рядів хрому перед списком: заголовок+2 кнопки → суб-таби → пошук → 7 чіпів → сортування+вигляд → пам'ять+«Видалити» | Медіатека | Перша книга списку — нижче складки. Вкладка «мої книги» не показує книг без скролу |

**Залізне правило, яке звідси випливає:** нескінченний paged-список — завжди останній елемент екрана. Ніщо не стоїть після нього.

## 1. Слухати — diff

### Зараз (фактичний порядок)
```
1. Hero «Продовжити слухати»
2. 8 персональних блоків — ВЕРТИКАЛЬНІ повноширинні картки (ListenBlockBookRow, L397)
3. «Нове на 4read» — горизонтальні ряди (L201–214)
4. «Нове з кожного джерела» (L224)
5. «Більше книг на Sluhay» (L253)
```

### Цільовий порядок
```
1. Hero «Продовжити слухати»                     [без змін]
2. «Продовжити» — горизонтальна полиця           [конвертувати]
3. «Дослухати до кінця» (ALMOST_DONE)            [конвертувати]
4. «Далі у серії» (NEXT_IN_SERIES)               [конвертувати]
5. «Щось коротке» (SHORT)                        [конвертувати]
6. «Ваші автори: нове» (FAVORITE_AUTHORS)        [конвертувати]
   ── межа вкладки ──
   «Нове на 4read»            → Огляд            [MOVE]
   «Нове з кожного джерела»   → Огляд            [MOVE]
   «Більше книг на Sluhay»    → Огляд            [MOVE]
```

### Що саме робити в коді
- **Реюз, не новий компонент.** Горизонтальна полиця вже існує — та, якою рендериться «Нове на 4read» (L201–214). Винести її в спільний компонент `PosterShelf(title, books)` і застосувати до всіх персональних блоків замість `ListenBlockBookRow` (L397). Одна зміна компонента закриває P-A для всіх 8 блоків.
- **Скоротити 8 блоків → 5 полиць** (порядок вище). TRAVEL злити з SHORT («Щось коротке · у дорогу»), RECENTLY_ADDED — це і є «Нове на 4read» → йде в Огляд. Це закриває LOW-баг «8 блоків замість 5» з ревізії через UI-рішення, а не через суперечку спек.
- **Дедуплікація видимості:** hero-книга не з'являється в жодній полиці нижче; книга з «Дослухати до кінця» не дублюється в «Продовжити».
- **Прогрес-смуга на постері** (2–3dp по низу обкладинки) для всіх початих книг у полицях — це візуальний маркер «незавершеного», як у Netflix Continue Watching.
- Порядок полиць: прогресні (продовжити → дослухати → серія) **завжди вище** рекомендаційних (коротке → автори).

### Логіка порядку
- **Персональне вище об'єктивного, об'єктивне вище нескінченного.** «Рекомендовано для вас» — найцінніший рядок вкладки; його місце — одразу після навігаційного каркаса (пошук/каталог/жанри), на першому-другому екрані скролу.
- **Фіди джерел зі «Слухати»** — це чистий дискавері-контент, тут їхнє природне місце. Заодно «Слухати» розвантажується до слухацького інтенту.
- **«Весь каталог» останнім** — користувач, який не знайшов нічого в кураторських рядках, провалюється в повний каталог з фільтрами. Це і є Netflix-модель: ряди → нескінченне.
- «Рекомендовано для вас» показувати лише за наявності історії; без історії — ховати рядок (не показувати порожній стан).

## 3. Медіатека — diff: хром 6 рядів → 3

### Зараз
```
1. Заголовок + «Додати аудіо» + «Папку»
2. Суб-таби (Книги / Закладки / Статистика)
3. Пошук
4. 7 фільтр-чипів
5. Сортування + перемикач вигляду
6. Пам'ять пристрою + «Видалити»
7. → список (нижче складки)
```

### Цільовий
```
1. Заголовок «Медіатека»  [+ Додати]  [⋮]        ← 2 кнопки імпорту злити в одну
│                                                 primary «+ Додати» → sheet
│                                                 («Файли» / «Папку», SAF);
│                                                 пам'ять і «Видалити» → ⋮ →
│                                                 «Завантаження та пам'ять»
│                                                 (з діалогом підтвердження)
2. [Книги (167) | Закладки | Статистика]         ← суб-таби без змін
3. [Усі][Слухаю][Нові][Завершені][♥] … [▦/☰]    ← чипи (7→5) + перемикач вигляду
│                                                 в ОДНОМУ рядку: чипи скролляться
│                                                 горизонтально, перемикач притиснутий
│                                                 праворуч; пошук — іконкою в рядку 1
│                                                 (розгортається в поле)
4. → список (перший рядок видимий без скролу)
```

### Нотатки
- **Чипи 7 → 5** за статусною моделлю Smart ABP: Усі / Слухаю / Нові / Завершені / Обране. «Завантажені» — у ⋮ або як другий рівень фільтра; «Нещодавно слухані» — це сортування, а не фільтр (зараз воно і там, і там). Заодно закриває LOW-баг «чипи ≠ спеці».
- **Пошук іконкою** в заголовку (як у Play Books): тап → розгортається поле. Постійне поле пошуку на всю ширину — розкіш, яку Медіатека не може собі дозволити з 6 рядами хрому.
- **«Видалити»/«Очистити» з головного поля зору** — одночасно UI-фікс і закриття HIGH-бага з ревізії (стирання всіх офлайн-книг без підтвердження): у ⋮-меню воно отримує діалог з обсягом файлів.
- **Опція (фаза 2):** collapsing toolbar — рядки 1–2 згортаються при скролі вниз, чипи (ряд 3) лишаються sticky. Тоді навіть довгі списки не втрачають контекст фільтра.
- **Серії згортаються** в один рядок списку з бейджем-лічильником («Епоха божевілля · 7») — розгортається на сторінці серії.

## 5. Acceptance criteria (перевірка на OnePlus 8 Pro)

- **Слухати:** ≤ 6 секцій на екрані; усі персональні блоки — горизонтальні полиці; жодного джерельного фіду; hero-книга не повторюється нижче.
