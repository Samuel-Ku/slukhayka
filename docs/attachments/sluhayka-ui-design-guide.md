# «Слухайка» — UI Design Guide
### Візуальна ревізія та дизайн-система для 3 вкладок застосунку
_Дата: 2026-08-16_

> Цей документ фокусується виключно на **UI-шарі**: компоненти, ієрархія, кольори, типографіка, spacing, стани. Функціональні/дата-баги (дублікати книг, небезпечне видалення) згадані лише там, де вони впливають на вигляд екрана.

---

## 1. Дизайн-принципи (фундамент, який тримати завжди)

1. **Один головний акцент на екран.** Помаранчевий (`#F5A623`-подібний) — тільки для: play-кнопки, активного таба, активного фільтра, прогрес-бару. Все інше — нейтральне.
2. **Обкладинка — головний герой.** Великі, чіткі, без зайвих рамок навколо неї.
3. **Менше контейнерів — більше повітря.** Зараз майже кожен блок обведений або має фон-картку. Треба ввести ієрархію: не все потребує бордера.
4. **Один компонент — одна форма.** Списки книг мають виглядати однаково у всіх трьох вкладках.
5. **Текст — за розміром важливості**, а не за тим, скільльки інформації хочеться показати.

---

## 2. Кольорова палітра (уніфікація)

| Токен | Значення | Використання |
|---|---|---|
| `bg.base` | `#0B0B0F` | Фон екрана |
| `bg.surface` | `#17171C` | Картки, bottom sheet, mini-player |
| `bg.surfaceElevated` | `#1F1F26` | Модалки, активні картки, sticky-хедери |
| `accent.primary` | `#F5A623` (наявний помаранчевий) | Play, активний tab, progress, primary CTA |
| `accent.primaryMuted` | `#F5A623` @ 30% opacity | Progress track (незаповнена частина), hover |
| `text.primary` | `#F5F5F0` | Заголовки, назви книг |
| `text.secondary` | `#9A9AA5` | Автори, метадані, підписи |
| `text.tertiary` | `#6B6B75` | Таймкоди, службові підписи |
| `danger` | `#E5484D` | Тільки для деструктивних дій (видалення) |
| `divider` | `#26262E` | Тонкі розділювачі списків (1px, не бордер картки) |

**Проблема зараз:** помаранчевий використовується одночасно на іконках плеєра, тексті «ЗАРАЗ ЗВУЧИТЬ», прогресах, чіпах жанрів, бейджах джерел і кнопках — акцент «розмивається» і не показує пріоритет.

**Правило:** якщо на екрані вже є 2 помаранчеві елементи — третій має бути нейтральним (сірим/білим).

## 3. Типографічна шкала

| Стиль | Розмір / вага | Де |
|---|---|---|
| `display` | 24sp / SemiBold | Назва книги в плеєрі та hero-картці |
| `title` | 18sp / SemiBold | Назва книги в списках, заголовки секцій |
| `subtitle` | 15sp / Medium | Автор, назва серії |
| `body` | 14sp / Regular | Описи, метадані другого рівня |
| `caption` | 12sp / Regular | Таймкоди, лічильники, бейджі |
| `label` | 11sp / SemiBold, uppercase, +letter-spacing | Заголовки секцій типу «КАТАЛОГ», «ЖАНРИ» |

**Зараз:** заголовки секцій («ПРОДОВЖИТИ СЛУХАТИ», «КАТАЛОГ») уже виглядають як `label` — це добре, зберегти. Але у деталях книги забагато рівнозначних за вагою рядків тексту підряд (назва, By/Narrated, жанри, рейтинг, пілюля джерела) — немає явного «другого плану».

**Виправлення:** у `BookDetail` тримати тільки 2 рівні ваги — `title` (назва) і все інше `body`/`caption`, без проміжних напівжирних рядків.

## 4. Spacing та ритм

| Токен | Значення | Застосування |
|---|---|---|
| `space.xs` | 4dp | Між іконкою та текстом |
| `space.sm` | 8dp | Між елементами всередині картки |
| `space.md` | 16dp | Горизонтальні поля екрана, між карткою і карткою в списку |
| `space.lg` | 24dp | Між секціями («Слухати» → «Нещодавно слухали») |
| `space.xl` | 32dp | Над hero-блоком, під шапкою |

**Проблема:** у медіатеці й «Огляді» відступи між блоками нерівномірні — деякі секції притиснуті одна до одної (жанри → весь каталог), інші мають забагато повітря (hero-картка). Треба звести до `space.lg` як стандартного міжсекційного відступу — без винятків.

## 5. Компонентна бібліотека (те, що треба звести до 1 варіанту кожен)

### 5.1 Картка книги — 3 варіанти, більше не створювати нових

**A. `PosterCard`** — горизонтальні стрічки («Нове», «Популярне»)
```
┌───────────┐
│           │
│ Обкладинка│  ← aspect ratio 2:3, radius 12dp, без бордера
│           │
└───────────┘
Назва (title, 2 рядки max)
Автор (caption, 1 рядок)
```
- Без фонової картки навколо — сама обкладинка є візуальною межею.
- Тінь (elevation) мінімальна або відсутня — тримає темну естетику.

**B. `ListRow`** — медіатека, каталог, розділи, персони
```
[64x64 обкладинка]  Назва книги (title)              [▶]
                     Автор · метадані (caption)
                     ▓▓▓▓▓▓▓░░░░░░░░  ← тонкий прогрес 2dp
```
- Фон: `bg.surface`, без бордера.
- Розділювач між рядками: 1px `divider`, не рамка навколо кожного рядка.
- Прогрес-бар — тонка лінія під текстом, а не товста плашка з відсотком поруч (як зараз у медіатеці).

**C. `HeroCard`** — «Продовжити слухати» на «Слухати»
```
┌─────────────────────────────┐
│  [обкладинка]  Назва книги  │
│                Автор        │
│                Розділ 11/65 │
│                ▓▓░░░ прогрес│
│                             │
│         [ ▶ Продовжити ]    │
└─────────────────────────────┘
```
- Це єдина картка на екрані, яка може мати `bg.surfaceElevated` + легку тінь.
- Одна кнопка дії всередині, без дублювання іконки play і тексту «Продовжити».

**Що прибрати:** зараз одна і та ж книга з’являється у 2–3 картках різного стилю на одному екрані «Слухати» (hero + «нещодавно слухали» + «щось коротке»). Візуально це виглядає як три різні книги через несхожий дизайн карток. Уніфікація стилю + дедуплікація видимості вирішує це одразу.

### 5.2 Чіпи (`FilterChip` / `NavChip`)

Зараз чіпи жанрів зустрічаються у двох формах на одному екрані «Огляд» — це головна UI-проблема.

Ввести чітке розділення форми:

| Тип | Вигляд | Де |
|---|---|---|
| `NavChip` | Прямокутна pill, `bg.surface`, без бордера, для навігації до розділу | Верхній ряд «КАТАЛОГ» / «ЖАНРИ» на Огляді |
| `FilterChip` | Менша pill, з бордером 1px `divider`, активний стан — заповнений `accent.primaryMuted` фон + текст `accent.primary` | Фільтри всередині «Весь каталог», Медіатека |

Різниця у формі (заповнена vs обведена) дозволяє оку одразу відрізнити «перейти» від «фільтрувати», навіть якщо текст на чіпах однаковий (наприклад «Роман»).

### 5.3 Кнопки

| Компонент | Вигляд | Використання |
|---|---|---|
| `PrimaryButton` | Заповнена `accent.primary`, radius 28dp (pill), текст `bg.base` | Одна на екран: Play, Продовжити, Додати |
| `SecondaryButton` | Обведена, прозорий фон, текст `text.primary` | Download, Bookmark |
| `IconButton` | Без фону, тільки іконка `text.secondary`, активна — `accent.primary` | Транспорт у плеєрі, навбар |
| `DestructiveButton` | Текст `danger`, без заповнення, завжди з підтвердженням | Видалити, Очистити |

**Критично:** кнопка «Очистити» в медіатеці зараз виглядає як звичайна `SecondaryButton` поруч із нейтральним рядком пам’яті — вона має бути `DestructiveButton` (текст `danger`, можливо з іконкою кошика), щоб оком одразу читалась як небезпечна дія, а не «оновити кеш».

### 5.4 Прогрес-бари

Уніфікувати до одного компонента `ProgressTrack`:
- висота 2–3dp,
- закруглені кінці,
- заповнена частина — `accent.primary`,
- фон — `accent.primaryMuted` (не суцільний темний, легкий натяк на трек).

Зараз у плеєрі два прогреси (розділ/книга) виглядають добре, але в hero-картці та в медіатеці прогрес товщий і має інший колір фону (`divider`-подібний сірий без прозорості) — звести все до одного вигляду.

### 5.5 Bottom sheets (швидкість, таймер, розділи, закладка)

Уже добре стандартизовані — тримати:
- ручка (grabber) зверху 4dp,
- заголовок `title` зліва,
- контент з відступом `space.md`,
- висота — тільки під контент, без зайвого порожнього простору знизу.

Єдине зауваження: `ChaptersSheet` і таб «Chapters» у деталях книги показують один і той же список у двох різних UI-обгортках (шит vs таб-лист). Візуально варто зробити їх ідентичними по стилю рядка (той самий `ListRow`), навіть якщо контейнери різні.

## 6. Екран за екраном — UI-фокус

### 6.1 Слухати

**Зараз:** 8 блоків, різні стилі карток, повторення однієї книги.

**UI-виправлення:**
- Hero — єдиний `HeroCard` зверху, без сусідніх дублів тієї ж книги.
- Секції нижче — тільки `PosterCard` у горизонтальному скролі, однаковий розмір обкладинок у всіх рядках (зараз пропорції відрізняються між секціями).
- Заголовки секцій — суворо `label`-стиль (uppercase, caption-розмір, `text.secondary`), без вертикальних варіацій жирності, які зараз є.
- Прибрати сирі заголовки з емодзі («🎧слухати онлайн українською») — навіть тимчасово, до фікса даних, обмежити рядок `maxLines=1` + `ellipsis`, щоб UI не «ламався» довгим сирим текстом.

### 6.2 Огляд

**Зараз:** пошук, два ряди жанрів, змішана сітка.

**UI-виправлення:**
- Пошук — завжди першим елементом, повна ширина, `bg.surface`, radius 16dp, іконка лупи зліва (не праворуч, як типово для мобільних списків).
- Ряд «КАТАЛОГ» (Топ/Автори/Виконавці/Жанри) — `NavChip`, іконка + текст, однаковий розмір.
- Прибрати другий ряд «Жанри» одразу під ним — залишити жанри тільки у фільтрах каталогу нижче, як `FilterChip`.
- Картки каталогу — строго `PosterCard`, однаковий aspect ratio для всіх джерел (зараз обкладинки різних розмірів через різні джерела/API — потрібен `contentScale = Crop` + фіксований контейнер).
- Додати бейдж джерела/тривалості прямо на картку (нижній лівий кут, маленький `caption` на напівпрозорому фоні) — зараз ця інформація ховається аж у деталях книги.

### 6.3 Медіатека

**Зараз:** багато кнопок і чіпів у верхній частині, важкі картки.

**UI-виправлення:**
- Замінити 2 кнопки («Додати аудіо» / «Папку») на 1 `PrimaryButton` «Додати» → bottom sheet з опціями.
- Чіпи фільтрів — `FilterChip`, в один рядок з горизонтальним скролом, не переносити на другий рядок.
- Рядок «Пам'ять пристрою: 0 MB · 0 аудіокниг offline» + «Очистити» — перенести в overflow (⋮) або окремий екран «Завантаження»; на головному екрані медіатеки цей рядок візуально конкурує з книжковим списком і не повинен там бути постійно видимим.
- Список книг — суворо `ListRow`: менше вертикального padding (зараз картки виглядають «роздутими»), прогрес — тонка лінія, без товстої плашки з відсотком.
- Бейджі джерела («4read», «Sound-Books») — зменшити до `caption`, приглушений фон `bg.surfaceElevated`, не яскраво-помаранчевий текст, який зараз конкурує з акцентом кнопок.

### 6.4 Деталі книги

**Зараз:** багато рівнозначного тексту підряд, дубль-картки.

**UI-виправлення:**
- Обкладинка зверху — по центру, фіксований розмір (не full-width, як зараз, це виглядає надто масивно для екрана деталей).
- Під обкладинкою: `title` (назва) → `subtitle` (автор) → одна лінія `caption` з жанрами через «·» → бейдж джерела окремо, менший.
- Рейтинг (★ 4.6) — інтегрувати в той самий caption-рядок, не окремою плашкою.
- Кнопка «Продовжити з …» — `PrimaryButton`, на всю ширину, одразу під метаданими, до опису.
- «Що кажуть джерела» — секція нижче, чітко відділена заголовком-`label` і карткою `bg.surface`.
- Таби Chapters/Bookmarks — стандартний Material tab-indicator помаранчевим підкресленням (уже є, зберегти саме цей стиль).

### 6.5 Плеєр

**Найсильніший екран — мінімальні зміни:**
- Обкладинка — зберегти великий розмір і скруглені кути.
- Прибрати дрібний підпис читача другим рядком під автором (перенести в info-меню ⋮), щоб під назвою залишався лише один рядок метаданих.
- Кнопки транспорту (15/30 сек) — додати цифру всередині іконки контрастнішим кольором, зараз цифра «15»/«30» злегка губиться на темному фоні іконки.
- Головна кнопка Play/Pause — трохи збільшити відносно сусідніх кнопок (зараз різниця в розмірі мала, тому вона не читається як «головна»).

## 7. Мова та мікротекст (UI-рівень)

Зараз змішані мови в одному потоці (`Playing`, `Download`, `Chapters (65)`, `Duration:`, `Narrated by`, поряд з українськими «Розділ», «Глава», «Читає»). Для UI це виглядає як недороблений переклад навіть якщо функціонал коректний.

Рекомендація:
- Все українською, без винятків для службових лейблів.
- Уніфікувати «Глава» → «Розділ» усюди (зараз використовуються обидва варіанти в різних екранах).
- Виправити плюралізацію: «1 книга», «2–4 книги», «5+ книг» — окрема utility-функція, застосувати до всіх лічильників (книги, розділи, хвилини).

---

## 8. Чеклист перед релізом UI-оновлення

- [ ] Один стиль картки книги на кожен контекст (poster / row / hero)
- [ ] Жанрові чіпи не дублюються на одному екрані
- [ ] Помаранчевий колір — не більше 2–3 елементів у зоні видимості одночасно
- [ ] Усі прогрес-бари мають однакову висоту й колір треку
- [ ] «Очистити» / деструктивні дії візуально виділені кольором `danger`
- [ ] Немає змішування мов у лейблах одного екрана
- [ ] Плюралізація українських лічильників коректна
- [ ] Відступи між секціями уніфіковані до `space.lg`
- [ ] Обкладинки мають однаковий aspect ratio в межах однієї стрічки
