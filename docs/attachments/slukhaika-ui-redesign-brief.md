# Слухайка — UI Redesign Brief

> **Фокус цього документа:** не просто «пофіксити екрани», а привести інтерфейс до однієї зрозумілої системи: спокійної, аудіо-first, мобільної, української та передбачуваної.
>
> **Продуктова мета:** людина має за 1–2 секунди розуміти, що зараз слухає, як продовжити, де знайти наступну книгу та як керувати своєю медіатекою.

---

## 1. Дизайн-напрям

### Принцип

**Слухайка — це не каталог з плеєром. Це плеєр, навколо якого існує каталог.**

Головний сценарій користувача:

1. Відкрити застосунок.
2. Одразу побачити поточну книгу й прогрес.
3. Натиснути «Продовжити».
4. За потреби швидко знайти наступну книгу, розділ або завантаження.

Інтерфейс має відчуватися як сучасний аудіосервіс: темний, тихий, тактильний, з одним теплим акцентом. Поточна палітра вже має хорошу основу: майже чорний фон, холодні графітові поверхні та бурштиновий акцент. Проблема не в стилі, а в **ієрархії, щільності та непослідовності патернів**.

### Візуальна теза

- Темний фон — простір і концентрація
- Бурштиновий — дія, прогрес, активний стан
- Обкладинка — головний візуальний носій емоції
- Текст — короткий, чистий, без технічного шуму
- Картки — тільки там, де вони створюють окремий інтерактивний об’єкт
- Списки — пласкі й швидкі для сканування

## 2. UI-система

### Кольори

Не варто додавати багато нових кольорів. Потрібна дисципліна використання наявних.

| Роль | Рекомендований токен | Використання |
|---|---:|---|
| Canvas | `#101116` | Базове тло екрана |
| Surface | `#1D212B` | Мініплеєр, bottom sheet, вибрані картки |
| Surface raised | `#252B37` | Hero-картка, активний рядок, modal/card |
| Stroke | `#343B4B` | Межі карток, неактивні контури |
| Text primary | `#F2F0EA` | Назви, ключові значення, заголовки |
| Text secondary | `#B8B2A9` | Автор, метаінформація, пояснення |
| Text muted | `#817D77` | Неактивні мітки, технічні дані |
| Accent | `#F3A72E` | Primary CTA, play, активний tab, прогрес |
| Accent subdued | `#5A431B` | Бейджі джерел та пасивні акцентні підкладки |
| Danger | `#F1A7AA` | Незворотні дії, видалення |

### Правила акценту

- Бурштиновий використовується лише для **дії**, **поточного стану** або **прогресу**.
- На одному екрані має бути одна головна action-зона.
- Не фарбувати акцентом декоративні елементи, якщо вони не клікабельні.
- Іконка play, активна вкладка, поточна глава та primary CTA можуть бути акцентними одночасно — але не кожна кнопка в списку.

### Типографіка

Поточний UI місцями виглядає як суміш системних стилів: українські заголовки, англійські `Duration`, російські `Глава`, технічні метадані. Потрібен один мовний і типографічний контракт.

| Стиль | Розмір / вага | Використання |
|---|---:|---|
| Display | 32sp / 700 | Великий заголовок екрана або книги |
| H1 | 26sp / 700 | Назва сторінки |
| H2 | 21sp / 700 | Назва секції |
| Title | 18sp / 650–700 | Назва книги / рядка |
| Body | 16sp / 400–500 | Автор, опис, основний текст |
| Label | 14sp / 600 | Чіпи, вкладки, кнопки |
| Meta | 13–14sp / 400–500 | Тривалість, джерело, статус |
| Overline | 12sp / 700 | Рідкісні службові мітки на кшталт «ЗАРАЗ ЗВУЧИТЬ» |

### Локалізація

UI має бути повністю українським. Зокрема:

- `Playing` → `Слухаєте` або `Відтворюється`
- `Download` → `Завантажити`
- `Duration` → `Тривалість`
- `Chapters` → `Розділи`
- `Bookmarks` → `Закладки`
- `Narrated by` → `Читає`
- `By` → `Автор`
- `Source` → `Джерело`

Не змішувати українську, англійську й російську в одному флоу. Якщо назви глав приходять із джерела російською, це дані контенту; але системні елементи інтерфейсу мають бути українськими.

### Сітка, відступи, радіуси

- Базовий крок: **8dp**
- Горизонтальний відступ екрана: **20dp**
- Відстань між великими секціями: **32dp**
- Відстань між заголовком секції та контентом: **12–16dp**
- Відстань між рядками списку: **0dp**, розділяти divider-лінією або повітрям
- Радіус великих контейнерів: **24dp**
- Радіус малих кнопок / чіпів: **14–16dp**
- Мінімальна touch target: **48 × 48dp**

## 3. Інформаційна архітектура

Нижня навігація вже правильна: **Слухати · Огляд · Медіатека**. Її треба зробити єдиною стабільною рамкою продукту.

### 3.1 Слухати — домашній екран

Це головний екран. Він не має бути нескінченним каталогом і не повинен дублювати однакові книги у трьох різних блоках.

#### Рекомендована композиція

```text
[Header: Слухати                         profile/settings]

[Continue listening hero]
  cover | Назва книги
        | Автор · Розділ 11 із 65
        | progress bar
        | 2 год 35 хв прослухано · 14 год 5 хв лишилось
        | [Продовжити]

[Нещодавно слухали]                                      [Усі]
  horizontal compact cards

[Наступне для вас]                                       [Усі]
  horizontal compact cards

[Завантажено] — показувати лише якщо є офлайн-книги

[Mini player]
[Bottom navigation]
```

#### Що прибрати або об’єднати

- Не показувати більше **3 контентних секцій** під hero на першому екрані.
- «Щось коротке», «Повернутися до», «Для дороги», «Улюблені автори», «Нещодавно додані» — не повинні всі існувати одночасно.
- Рекомендований MVP-набір: `Нещодавно слухали`, `Наступне для вас`, `Завантажено`.
- Якщо hero-книга є у «Нещодавно слухали», або приховувати її з ряду, або показувати з меншою вагою лише після кількох інших позицій.

#### Hero-картка

Hero має бути найсильнішим елементом екрана, але не гігантською карткою. Рекомендована структура:

- Обкладинка 96–112dp зліва
- Праворуч: назва максимум у 2 рядки
- Автор — один рядок
- Розділ / прогрес — один компактний рядок
- Один тонкий progress bar
- Primary CTA: іконка play + `Продовжити`

Не показувати `0%`, якщо прогрес менше 1%. Краще: `Почато щойно` або просто прибрати відсоток на ранній стадії.

### 3.2 Огляд — пошук і відкриття

Поточний екран має дублювання: жанри з’являються і як навігаційний ряд, і як фільтри каталогу. Потрібно розвести **навігацію** та **фільтрацію**.

#### Рекомендована композиція

```text
[Слухайка                                      search icon]

[Search field: Пошук книг, авторів і читців]

[Швидкий перегляд]
[Топ 100] [Автори] [Виконавці]

[Популярні жанри]
[Роман] [Фентезі] [Детектив] [Класика] [Жахи] →

[Для вас]                                             [Усі]
  horizontal cards

[Новинки]                                             [Усі]
  horizontal cards

[Усі книги]
[Фільтри] [Сортування]                    [кількість книг]
vertical Work cards / grid toggle
```

#### Правила

- Жанрові чіпи показувати **один раз**: у блоці «Популярні жанри» або у full-screen filter sheet, але не в обох місцях одночасно.
- `ТОП 100`, `Автори`, `Виконавці` оформити як однакові навігаційні кнопки, а не як чіпи, що виглядають як фільтри.
- Фільтри каталогу не мають займати два ряди. Використати одну кнопку `Фільтри` з лічильником активних фільтрів, наприклад `Фільтри · 2`.
- Сортування — окремий control, не чіп в одному ряду з жанрами.
- Пошук має бути першим елементом після шапки: це ключова функція каталогу.

### 3.3 Медіатека — власний контент

Медіатека має відповідати на три питання: що я слухаю, що збережено офлайн і що вже завершив.

#### Рекомендована композиція

```text
[Медіатека]                              [more]

[Search field: Пошук у медіатеці]

[segmented tabs]
Усі | Слухаю | Завершені | Завантажені

[Sort: Нещодавно слухані]                 [filter icon]

[book rows]

[Mini player]
[Bottom navigation]
```

#### Імпорт

Кнопки `Додати аудіо` і `Папку` не повинні конкурувати з контентом у верхній частині екрана.

Рекомендація:

- Винести їх у одну action-кнопку в шапці: `+ Додати`.
- По натисканню відкривати bottom sheet: `Файли`, `Папка`, `Завантаження`.
- Якщо бібліотека порожня — в empty state показувати дві великі CTA-кнопки.

#### Небезпечне очищення

`Очистити` біля рядка пам’яті виглядає як очищення кешу, але видаляє офлайн-книги. Це не лише функціональна проблема, а й UI-помилка.

Новий патерн:

```text
Завантаження
3 книги · 1,8 GB                                  [Керувати]
```

На екрані `Керувати завантаженнями`:

- Показати список файлів і розмір кожного
- Дати видаляти по одному або обрати кілька
- Для `Видалити все` показувати destructive bottom sheet:

```text
Видалити всі завантаження?
Буде видалено 3 книги (1,8 GB). Їх можна буде завантажити знову.

[Скасувати]  [Видалити]
```

### 3.4 Деталі книги — рішення перед стартом

Екран книги має відповідати на питання: «Що це, чи хочу я це слухати, з якого джерела й з якої точки продовжити?»

#### Рекомендована композиція

```text
[Back]                         [favorite] [more]

                [Cover]

            Трохи ненависті
              Джо Аберкромбі
             Читає Рік Санчез

[Фентезі] [Пригоди]     16 год 41 хв · 65 розділів

[Продовжити з 2:35:41]   secondary: [Завантажити]

[About]
Короткий опис, максимум 4 рядки + «Показати більше»

[Джерела]
4read · рейтинг 4,6 · Українська
[Відкрити джерело]  [Інші джерела]

[Розділи] [Закладки]
```

#### Ключові зміни

- Прибрати дубль-сутності: одна книга = одна detail-сторінка, незалежно від кількості джерел.
- Не показувати сирі URL як основний контент. URL — технічна деталь, її можна винести в меню `Ще` або під кнопку `Відкрити джерело`.
- Бейдж `4read.org Source` замінити на людський: `4read` або `Джерело: 4read`.
- Не змішувати `By`, `Narrated by`, `Source` з українським UI.
- Кнопка play має бути первинною. Download — вторинною.
- Якщо книга вже грає, primary CTA: `Продовжити`; якщо не починали: `Слухати`.

### 3.5 Розділи — один патерн

Зараз є щонайменше два способи побачити розділи: у деталях книги та як sheet у плеєрі. Це нормально, якщо вони використовують одну візуальну модель.

#### Рекомендований рядок розділу

```text
11   Глава 11                                  18:01
     Слухаєте · 08:49
     ━━━━━━━━━━━━━━━━●━━━━━━━━
```

- Номер — маленький, у нейтральному колі лише для поточного або вибраного рядка
- Назва — основний текст
- Тривалість — праворуч, secondary
- Поточний прогрес показувати тільки для активної глави
- Play на кожному рядку не обов’язковий: натискання на весь рядок запускає главу
- Довгі списки мають підтримувати пошук по номеру/назві, якщо є реальні назви

### 3.6 Плеєр — еталонний екран

Плеєр уже найпослідовніший за структурою. Його варто використати як візуальне джерело правди для решти продукту.

#### Що залишити

- Велика обкладинка
- Чітка назва та автор
- Два рівні прогресу: глава й книга
- Велика центральна кнопка паузи/play
- Швидкі дії внизу: швидкість, таймер, закладка, розділи

#### Що покращити

- Додати явні accessibility labels до `−15 с` і `+30 с`.
- Замість окремих рядків `Розділ` / `Книга` можна використати компактні мітки над progress bar, щоб зменшити вертикальний шум.
- Відокремити загальний прогрес книги від індикатора поточної глави контрастом, а не тільки розташуванням.
- Кнопка закладки має показувати стан: контурна до створення, заповнена після створення.
- Bottom sheet для таймера, швидкості й розділів має мати спільну шапку, радіус, drag handle і правила відступів.

## 4. Компоненти та патерни

### Book row

Використовувати в медіатеці, результатах пошуку, списках жанрів, серіях і Top 100.

```text
[cover 64×64]  Назва книги                         [more]
                Автор
                65 розділів · 16 год 41 хв
                progress bar + Залишилося 14 год 5 хв
```

Правила:

- Не вкладати кожен рядок у важку підняту картку.
- Для списків краще плаский рядок з 12–16dp вертикальних відступів.
- Повну картку використовувати для hero, горизонтальних рекомендацій або явно окремого об’єкта.
- Назва: максимум 2 рядки. Автор: 1 рядок з ellipsis.
- Не показувати одночасно рейтинг, джерело, серію, тривалість, глави, формат і статус — залишити до 2 мета-рядків.

### Compact book card

Для горизонтальних рядів на «Слухати» й «Огляд».

```text
[cover 120×160]
Назва — до 2 рядків
Автор — 1 рядок
```

- Не додавати на кожну картку великий play-трикутник: він візуально засмічує ряд.
- Play показувати на long press, hover недоступний на touch; отже основна взаємодія — tap по картці, що відкриває деталі.
- Для швидкого старту застосувати невеликий floating play лише на hero-картці або на card після тапу/фокусу.

### Чіпи

Є три різні типи, їх не можна стилізувати однаково.

| Тип | Приклад | Поведінка |
|---|---|---|
| Navigation chip | `Топ 100`, `Автори` | Веде на окремий екран |
| Filter chip | `Фентезі`, `Завантажені` | Змінює список, має selected state |
| Metadata chip | `65 розділів`, `4read` | Не клікабельний або відкриває деталі метаданих |

- Navigation chips: filled dark surface, стрілка або очевидний контекст переходу.
- Filter chips: outlined у default, filled accent/subtle в selected state.
- Metadata chips: менші, приглушені, без вигляду кнопки.

### Bottom sheets

Всі sheets мають один шаблон:

```text
[drag handle]
Заголовок                         [close]
Коротке пояснення — за потреби

[список опцій]

[primary / destructive action — лише якщо потрібна]
```

- Не змішувати діалог і sheet для одного типу задачі без причини.
- Вибір швидкості, таймера, розділу — sheet.
- Небезпечне видалення — confirmation dialog або destructive sheet.
- Створення закладки — sheet, якщо потрібна нотатка; quick bookmark без нотатки може бути миттєвою дією зі snackbar `Закладку додано`.

### Мініплеєр

Мініплеєр — постійний контекст, а не ще одна велика картка.

- Висота 68–76dp
- Обкладинка 44–48dp
- Назва + глава, максимум по одному рядку
- Play/pause і next
- Тонкий progress indicator по верхній межі
- Tap на будь-якій області, крім controls, відкриває full player

## 5. План впровадження

### Етап 0 — безпечність і консистентність

1. Додати підтвердження перед видаленням усіх офлайн-файлів.
2. Виправити дублікати книг і нормалізацію SEO-заголовків.
3. Прибрати змішані мови з системних UI-елементів.
4. Додати українські plural forms для книг, розділів, годин і хвилин.
5. Уніфікувати `source`, `author`, `narrator`, `duration`, `chapters` у view model до рендеру UI.

### Етап 1 — foundations

1. Створити `AppTheme` з токенами кольору, типографіки, spacing, shape та elevation.
2. Створити спільні компоненти: `BookRow`, `BookCover`, `ProgressBar`, `FilterChip`, `MetadataChip`, `MiniPlayer`, `SectionHeader`, `AppBottomSheet`.
3. Уніфікувати top app bar, bottom navigation та mini-player.
4. Задати один формат метаданих: `65 розділів · 16 год 41 хв`.

### Етап 2 — ключові екрани

1. Перебудувати «Слухати» навколо одного hero і максимум трьох секцій.
2. Перебудувати «Огляд»: пошук → навігація → жанри → curated rows → каталог.
3. Перебудувати «Медіатеку» як щільний список із сегментованими табами.
4. Перебудувати detail-екран: сильна обкладинка, один primary CTA, чисті джерела, один патерн розділів.

### Етап 3 — polish

1. Motion: 180–240ms для появи/зникнення, 280–320ms для переходів між екранами.
2. Додати skeleton loading для каталогів і shimmer тільки для обкладинок/рядків.
3. Додати empty/error states для пошуку, медіатеки, завантажень і недоступних джерел.
4. Перевірити TalkBack: кожна кнопка має змістовний `contentDescription`.
5. Перевірити контраст тексту, 200% font scaling і довгі українські назви.

## 6. Acceptance checklist для UI

### Глобально

- [ ] На всіх екранах є однакова горизонтальна сітка та один масштаб відступів
- [ ] У системному UI немає змішування української, англійської та російської
- [ ] Акцентний колір означає дію, прогрес або активний стан
- [ ] Немає двох різних компонентів для одного призначення без чіткої причини
- [ ] Усі деструктивні дії мають явне підтвердження
- [ ] Кожна інтерактивна зона має touch target від 48dp

### Слухати

- [ ] Hero одразу пояснює, що продовжити і скільки лишилося
- [ ] Під hero не більше трьох секцій на першому екрані
- [ ] Одна й та сама книга не домінує у кількох рядах поспіль
- [ ] Сирі SEO-назви не потрапляють у UI

### Огляд

- [ ] Пошук видно без прокрутки
- [ ] Жанри не дублюються у двох однакових чіп-рядках
- [ ] Навігаційні, фільтраційні та мета-чіпи візуально відрізняються
- [ ] Каталог має простий контроль `Фільтри` та окреме `Сортування`

### Медіатека

- [ ] Фільтри відповідають реальним задачам: усі, слухаю, завершені, завантажені
- [ ] Імпорт доступний, але не домінує над контентом
- [ ] Управління завантаженнями пояснює, що саме буде видалено
- [ ] Кожна книга має один чистий рядок без дубля через джерело

### Деталі та плеєр

- [ ] У книги один головний CTA: `Слухати` або `Продовжити`
- [ ] URL не є центральним елементом екрана
- [ ] Джерела читаються як вибір людини, а не технічний запис БД
- [ ] Розділи в деталях і плеєрі мають один і той самий патерн
- [ ] 15-секундне перемотування, таймер, швидкість і закладка доступні через зрозумілі підписи для accessibility

## 7. Коротка дизайн-формула

> **Менше контейнерів. Менше повторів. Більше ієрархії.**
>
> Користувач повинен бачити одну головну дію, одну поточну книгу й один зрозумілий наступний крок. Все інше — доступне, але не конкурує за увагу.
