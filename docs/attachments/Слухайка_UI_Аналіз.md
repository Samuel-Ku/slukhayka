# UI-аналіз застосунку «Слухайка»

> Фокус документа — виключно на інтерфейсі: структура трьох головних вкладок, розташування об'єктів, ієрархія екранів і навігаційні паттерни. Функціональність (плеєр, бібліотека тощо) розглядається лише як контекст для UI-рішень.

---

## 1. Загальна архітектура навігації

Застосунок побудований на класичній **Bottom Tab Bar** з трьома вкладками:

| Вкладка | Іконка | Призначення | Роль в ієрархії |
|---|---|---|---|
| **Слухати** | навушники | «Домашня» вкладка — продовження прослуховування, персональні рекомендації | Точка входу №1 (default screen) |
| **Огляд** | компас | Каталог / відкриття нового контенту | Discovery-шар |
| **Медіатека** | стек дисків | Керування власною бібліотекою | Management-шар |

Крізь усі три вкладки наскрізно проходить **persistent mini-player** — плаваюча панель прямо над таб-баром (обкладинка, назва, глава, play/pause, next). Це правильне архітектурне рішення: користувач не втрачає контроль над відтворенням, переходячи між розділами. Проблема — на різних екранах цей mini-player має різну візуальну «вагу» (то з рамкою й тінню, то злитий з фоном), що трохи порушує відчуття єдиного persistent-компонента.

**Ієрархія рівнів екрана (глибина навігації):**

```
Bottom Tab (Слухати / Огляд / Медіатека)
 └─ Список / Каталог (рівень 1)
     └─ Деталі книги / серії (рівень 2)
         └─ Повноекранний плеєр (рівень 3, викликається з mini-player)
             └─ Bottom sheet «Розділи» / «Закладки» (рівень 4, модальний)
```

Чотири рівні глибини — це прийнятно, але перехід рівень 3→4 (плеєр → розділи) реалізований як bottom sheet, а рівень 1→2 (список → деталі) — як full push screen. Ця неоднорідність патернів навігації (push vs sheet) варта уваги нижче.

## 2. Вкладка «Слухати» (Home)

**Структура зверху вниз:**

1. **Hero-блок «Продовжити слухати»** — картка на весь ширину з великою обкладинкою (~35% ширини), заголовком, автором, індикатором «Розділ X із Y», відсотком і залишком часу, великою круглою кнопкою Play праворуч, тонким progress-бар знизу.
2. **Горизонтальна секція-шелф «Щось коротке»** — заголовок + підзаголовок-пояснення («менше години прослуховування») + іконка меню (3 крапки) для секції, нижче — вертикальний список карток (обкладинка-мініатюра 56×56, назва, автор, play-кнопка, крапка/номер розділу).

**Ієрархія уваги:** одна домінуюча картка (continue listening) → каскад менших однотипних рядків. Це правильна F-паттерн композиція, і саме такий hero-first підхід очікується від listen-first застосунку.

**UI-спостереження:**
- Прогрес-бар у hero-картці — це тонка лінія з двома крапками-маркерами по краях, без заповнення проміжного стану кольором до поточної позиції (%=0% показано, але бар виглядає порожнім) — це послаблює зчитуваність прогресу з першого погляду.
- Секція «Щось коротке» використовує іконку **X** для видалення елемента прямо в рядку — це нетиповий патерн для головного екрана (зазвичай delete ховають за свайп чи long-press), і він конкурує за увагу з play-кнопкою, бо обидві іконки однакового кола-формату та розміру.

## 3. Вкладка «Огляд» (Discovery / Catalog)

Це найскладніша з трьох вкладок за кількістю рівнів фільтрації, і саме тут накопичилась найбільша ієрархічна плутанина.

**Структура зверху вниз:**

1. **Header** — логотип + назва «Слухайка», іконка Refresh, іконка Search (праворуч).
2. **Секція «КАТАЛОГ»** — 3 pill-чіпси: ТОП 100 / Виконавці / Автори.
3. **Секція «ЖАНРИ»** — 5 pill-чіпсів: Казка / Вірші / Роман / Жахи / Драма.
4. **Секція «ВЕСЬ КАТАЛОГ»** — ще один ряд чіпсів сортування: Спочатку нові / За назвою / Усі джерела.
5. **Другий ряд чіпсів жанрів** — Усі жанри / Казка / Вірші / Роман... (дублює секцію 3 майже 1:1).
6. **Плаский список книг** — обкладинка, назва, автор, play-іконка справа.

**Головна UI-проблема цієї вкладки:** чіпси жанрів зустрічаються **двічі** (блок 3 і блок 5) з майже ідентичним набором значень, розділені лише секцією сортування. Візуально це виглядає як помилка компонування, а не як два різні функціональні шари (global genre nav vs local list filter). Користувач не отримує явного сигналу, чим один ряд чіпсів відрізняється від іншого — немає заголовка типу «Фільтр списку нижче» біля другого ряду.

Крім того, три блоки-секції («КАТАЛОГ», «ЖАНРИ», «ВЕСЬ КАТАЛОГ») мають однаковий caps-lock заголовок-стиль без вираженої вагової різниці (шрифт, колір, розмір ідентичні), тому оком важко зрозуміти, де закінчується один функціональний блок і починається інший — вони «зливаються» в одну довгу стрічку чіпсів.

**Список нижче (за назвою, за замовчуванням):** рядки книг тут не мають прогрес-барів чи статусу «слухаю» — на відміну від Медіатеки, тут це чисто каталожний, «безстатусний» рядок. Це логічно (це ще не твоя книга), але висота рядка й розташування play-кнопки збігаються 1:1 з елементами в Медіатеці — тобто типографічно два різні за змістом контексти (свій vs чужий контент) виглядають ідентично, і легко сплутати «додав до бібліотеки» з «просто в каталозі».

## 4. Вкладка «Медіатека» (Library)

Найбільш «інструментальна» вкладка — тут щільність контролів найвища.

**Структура зверху вниз:**

1. **Header** — заголовок «Медіатека» + підпис + дві кнопки-дії: «Додати аудіо» (заповнена, акцентний колір) і «Папку» (контурна, вторинна).
2. **Таби другого рівня** — Книги (63) / Закладки (1) / Статистика — це під-навігація *всередині* вкладки, окремий рівень від Bottom Tab Bar.
3. **Search bar** на всю ширину.
4. **Ряд фільтрів-чіпсів** — Усі / Слухаю / Завершені / Завантажено (обрізається за екран, натяк на горизонтальний скрол без явного індикатора).
5. **Рядок сортування + перемикач вигляду** — «Нещодавно слухані ▾» ліворуч, іконка grid/list праворуч.
6. **Storage-бар** — «Пам'ять пристрою: 0 МБ · 0 аудіокниг offline» + лінк «Очистити» (рожевим — colour-coded як деструктивна дія).
7. **Список книг** — обкладинка, назва, автор, серія/книга №, progress-бар кольоровий, «Залишилось X год Y хв», тег джерела (badge типу «4read», «Sound-Books»).

**Ієрархія тут набагато чіткіша, ніж в «Огляд»**: кожен рівень фільтрації має свою явну візуальну «доріжку» (Search → Chips → Sort → Storage → List), і жоден блок не дублюється. Це показує, що дизайн-система застосунку здатна на чистішу структуру — просто «Огляд» від неї відхиляється.

**Дрібні UI-нюанси:**
- Кнопка «Очистити» рожевим кольором поруч із нейтральною інформацією про пам'ять — колірний код деструктивної дії тут доречний, але сама кнопка не має обвідки/фону, через що на темному фоні виглядає слабшою за важливість дії (це can-be-destructive click, а візуальний вплив — як у другорядного лінка).
- Badge-теги джерела («4read», «Sound-Books», «4read.org Source») використовують тьмяно-жовтий/охристий фон з темним текстом — контраст нижчий, ніж у решти акцентних елементів (play-кнопки, progress-барів), тому джерело книги легко проґавити, хоча це важлива метадана для довіри до контенту.

## 5. Деталі книги (рівень 2) і повноекранний плеєр (рівень 3)

**Екран деталей книги:**
Верхній ряд — back-arrow, обрізана назва, і одразу 4 icon-actions в один ряд: heart (favorite), external-link, cloud-download, trash (delete). Це доволі агресивне групування — favorite (додавання) і delete (видалення) розташовані в одному ряду з однаковою візуальною вагою (однаковий розмір іконки, немає роздільника), що підвищує ризик випадкового тапу по деструктивній дії поруч з рутинною.

Нижче — три горизонтальні CTA-кнопки (Playing / Download / Bookmark+) різних стилів (заповнена / контурна / іконка-квадрат) — це навмисна візуальна пріоритизація: play — головна дія (заповнена), decision-actions — другорядні (контурні). Це вдале рішення.

Таби «Chapters (65) / Bookmarks (1)» — під-навігація в англійському UI, тоді як решта інтерфейсу українська — це помітна **мовна неконсистентність** (мікс лейблів «Playing», «Download», «Duration:» серед українських «Розділ», «Слухати» на інших екранах).

**Повноекранний плеєр:**
Ієрархія тут канонічна для аудіоплеєрів: велика обкладинка в центрі → метадані (назва, автор, диктор) → назва глави → **два окремі прогрес-бари** (Розділ і Книга, кожен зі своїм time-label зліва/справа) → transport controls (prev / -15s / play / +30s / next) → нижній ряд другорядних інструментів (швидкість, таймер сну, закладка, розділи).

Наявність двох прогрес-барів одразу (глава + книга) — сильне UX-рішення для довгого контенту (16+ годин), рідко зустрічається в масових плеєрах, і це явно продуманий, а не випадковий елемент дизайну.

## 6. Наскрізні UI-спостереження (по всій апці)

- **Акцентний колір** — теплий помаранчево-жовтий (амбер) використовується консистентно для: активного таба, play-кнопок, progress-барів, active-стану чіпсів. Це єдина найсильніша ниточка візуальної єдності застосунку.
- **Card-паттерн** (темно-сірий rounded rectangle на чорному фоні) повторюється для книжкових рядків, hero-картки, чіпсів-груп — гарна повторюваність форми, але недостатня диференціація radius/тіні між рівнями важливості (hero-картка й звичайний рядок списку мають майже однаковий візуальний «вес»).
- **Заголовки секцій** (КАТАЛОГ, ЖАНРИ, ВЕСЬ КАТАЛОГ) всюди виконані caps-lock, малим шрифтом, без розділових ліній між секціями — це основна причина «злиття» структури на вкладці «Огляд».
- **Мовна неконсистентність** (UA/EN мікс) з'являється саме на екранах деталей книги — сигнал, що це, ймовірно, різні джерела/розробники компонентів, не приведені до єдиного словника лейблів.

## 7. Пріоритетні рекомендації

1. **«Огляд»: об'єднати або чітко розділити два ряди чіпсів жанрів.** Або прибрати дублікат, або дати другому ряду власний заголовок («Фільтр списку нижче»), і додати роздільник (тонку лінію чи відступ 24px+) між секціями КАТАЛОГ / ЖАНРИ / ВЕСЬ КАТАЛОГ.
2. **Розвести favorite/delete по різних зонах** на екрані деталей книги — наприклад, delete в overflow-меню (3 крапки), а не в основному ряду швидких дій.
3. **Уніфікувати мову інтерфейсу** — прибрати «Playing / Download / Duration:» на екранах деталей, замінити на українські відповідники, що вже використовуються в інших частинах застосунку.
4. **Підняти контраст badge-тегів джерела** (4read, Sound-Books) — зробити колір фону насиченішим або текст світлішим, щоб метадана про надійність джерела не втрачалась.
5. **Додати заповнення прогрес-бару кольором до поточної позиції** навіть при 0%, або хоча б чіткий «пустий» vs «активний» стан — зараз 0%-прогрес візуально не відрізняється від «немає прогресу взагалі».
6. **Візуально виокремити mini-player** однаковою тінню/рамкою на всіх вкладках — зараз він то «плаває» над контентом з тінню, то виглядає вбудованим у список (як на скрін з Медіатекою).
