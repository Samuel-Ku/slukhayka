# Grilling v1.4: консистентність UI/UX усіх екранів

Дата: 2026-09-06. Мета: v1.4 — візуальне полірування та консистентність
інтерфейсу (Android). Метод: grill-with-docs — звірка кожного екрана з
ADR-0014 (UX-правила), ADR-0018 (таксономія компонентів), ADR-0015
(вісім полиць «Слухати») та UX-принципами CONTEXT.md, з рішеннями
трьох раундів грилінгу. Рішення грилінгу зафіксовано в ADR-0033;
план постачання — у спекі `2026-09-06-ui-consistency-v14.md`.

Результати #545–555 не переглядаються: геометрія (обкладинка, 48 dp,
фокус-контракти, 320 dp при 200% шрифту) вже перевірена на телефоні й
закрита. Цей аудит — про шар ВИЩЕ: чи всі екрани говорять однією
мовою компонентів.

## Знахідки (системні дефекти)

### S1. Заголовки секцій — канонічний компонент мертвий, живуть 5 стилів
`AppSectionHeader` (`DesignSystem.kt`) — єдиний заголовок, оголошений
канонічним, — використовується **тільки тестами**. На екранах живуть:
`CatalogRowHeader` (UPPERCASE, Огляд/індекси), `OverviewGroupHeader`
(«Для вас»/«Відкрити нове»), `ListenBlockHeader` (заголовок+причина+⋮),
«голі» `Text(titleMedium Bold)` (сторінка книги: «Інші начитки», «У
серії», «Можливо, Тебе зацікавить», «Відгуки»; пошук: «Автори»,
«У вашій медіатеці», «Усі джерела»; рейл «Нове від ваших авторів»).
Різні відступи (8/10/16/20/24 dp) і різні м'які сигнали ієрархії.

**Рішення (R1):** два рівні канонічного заголовка. Група = headlineSmall
Bold; секція = titleSmall Bold uppercase + опційний action-слот. Усі
ad-hoc стилі мігрують, включно зі сторінкою книги.

### S2. Чотири близнюки постерної картки + один аутсайдер
ADR-0018 дозволяє три типи карток. Реально: `CompactBookCard`
(Слухати; автор, прогрес-лінія, caption, ✕), `CatalogBookCard` (Огляд;
без автора, тривалість), `UnifiedCatalogCard` (пошук/новинки; без
обвідки, іконка завантаження), `CollectionBookCard` (колекції; мінімум).
Усі — 120×168, та сама типографіка, скопійована чотири рази.
`RecommendedBookCard` ламає ритм: 200 dp ширина, 224 dp обкладинка,
Card-обгортка, власне меню. Ландшафтні цикли: `CatalogSeriesCard`,
`PersonalCycleCard`, `SimilarCycleCard` — три копії однієї форми.

**Рішення (R2):** один `PosterCard` (120×168) із слотами
(автор/тривалість/прогрес/caption/✕/завантаження) і одна
`CycleCard` (ландшафт 132×78). «Нова варіація без колапсу»
заборонена — тепер і в коді.

### S3. Шість стилів рядків-списків; канонічний BookRow не існує
ADR-0018: «64 dp cover, thin progress hairline, divider not border».
Реально: `AudiobookListItem` (обвідка, 68 dp, RadiusPanel), `Top100Row`
(обвідка, 56 dp), `PersonRow` (обвідка, 14 dp), `LibraryBookRowContent`
(без обвідки, shapes.medium), `WorkFeedCard` і `GlobalSearchResultCard`
(без обвідки, власні геометрії). Жоден не відповідає записаному канону.

**Рішення (R3):** один `BookRow` — 64 dp обкладинка, тонкий роздільник
замість обвідки, слоти бейджів/дій (ранг, ▶, ⋮). Вся вертикаль (ТОП 100,
Виконавці/Автори, серія/жанр/персона, пошук, стрічка Огляду) на ньому.

### S4. MetadataChip: чотири реалізації
`LanguageBadge` (EN/UA), `SourceBadgePill` (назва джерела), `TagPill`
(жанр/розділи/тривалість на сторінці книги), причина-поверхні
рекомендацій («Схоже на …», бейдж джерела) — чотири окремі компоненти
з різними радіусами й тонами. ADR-0018 назвав тип, ніхто не збудував.

**Рішення (R4):** один `MetadataChip` (не-інтерактивний, muted): слоти
`language`, `source`, `plain`; причина рекомендації стає чіпом теж.

### S5. Шість варіантів порожніх/завантажувальних станів
`EmptyState` (56 dp), `EmptyStateRow` (40 dp), `IndexEmptyState` (48 dp
без дій), `SecondaryMessageState`/`SecondaryLoadingState`,
`EmptyCatalogState` (64 dp, власні кнопки), голі `Text`/`Box`
(закладки, відгуки, сторінка книги).

**Рішення (R5):** два стани — повний `EmptyState` (іконка+текст+дії) і
компактний `EmptyStateRow`. `IndexEmptyState`/`SecondaryMessageState`
стають фасадами над ними; голі стани мігрують.

### S6. Три шапки табів + два патерни пошуку
Шапки: Огляд — бренд-локап; Медіатека — заголовок+підзаголовок+CTA;
Налаштування — тільки headline; Слухати — нічого. Пошук: Огляд —
колапсуюче поле (🔍 → розгорнути, ✕/Back → очистити, US-2); Медіатека —
завжди видиме поле.

**Рішення (R6):** одна модель шапки таба (заголовок + опційна дія;
«Додати» лишається), Медіатека успадковує колапсуючий патерн пошуку.

### S7. Локалізація — хардкод української в продуктовому коді
Зафіксовано в #549/#550 як «відомий борг». Хардкод: блок заголовків і
підписів Медіатеки («Медіатека», «Всі книги — в одному місці», «Додати»,
«Фільтр», «Люди»), сторінка книги (порожні стани, «джерела і слухачі»,
«Поточна», «Тільки стрімінг», підписи джерел, «Ваші зірки…», діалог
видалення оцінки начитки), плеєр («ЗАРАЗ ЗВУЧИТЬ», «Прибрати з
обраного»), таймер (опції), Слухати (parts of empty state), rails
(«Новинки», «Швидкі переходи», «Для вас», «Відкрити нове», «Нове від
ваших авторів/виконавців», кнопка «• N нові»).

**Рішення (R7):** v1.4 завершує міграцію на ресурси (`values-en`,
381-ключова парність уже існує — поповнюємо), бо змішана мова хрому —
дефект консистентності, не окрема i18n-історія.

### S8. Магічне число нижнього відступу
`contentPadding = PaddingValues(bottom = 120.dp)` повторюється ~12
разів (усі списки над мініплеєром) без токена. Дрібниця, але саме вона
ламається першою при зміні висоти мініплеєра.

**Рішення (R8):** токен `AppDimens.SpaceAboveMiniPlayer` + перевірка
геометрії в snapshot-тесті.

### S9. Два входи до відгуків на сторінці книги
«Ваші враження» після списку розділів (`BookFeedbackEntry` + ADR-0032,
з відкладеним запитом після завершення) і кнопка «Написати» в блоці
«Відгуки». Обидва ведуть в одну систему оцінок — конкуруючі входи.

**Рішення (R9):** один вхід — блок «Відгуки» (зірки + текст + тег
начитки). Після завершення книги форма відкривається сама (ADR-0032
не змінюється). Кнопка після розділів зникає.

### S10. П'ять форматів лічильників
Лічильники: вкладки «Книги (12)», заголовки «Відгуки (3)», «У вашій
медіатеці (12)», окремі рядки «12 книг у жанрі» / «12 авторів»,
«• 3 нові». Множини правильні всюді (BUG-006 закрито) — формат
розкиданий.

**Рішення (R10):** лічильник — частина канонічного заголовка
(«Розділи · 12», «12 книг у жанрі» як підзаголовок заголовка);
окремі рядки-лічильники зникають.

## Захищені рішення (не переглядаються)

- **ADR-0015** (вісім блоків «Слухати») — поважається; chrome скорочується
  одним пунктом «Керувати полицями», механіка reorder/hide не змінюється.
- **ADR-0018** (3 картки, 3 чіпи, глибина навігації) — нарешті
  виконується кодом, а не тільки папером.
- **Деструктивні дії** (трирівневе видалення книги, ClearCacheConfirmDialog,
  видалення відгуків/закладок/оцінок) — усі підтверджені з точною сферою,
  не чіпаються.
- **Чесні дані** (ADR-0014, ADR-0022) — тривалості/лідери/середні
  рендеряться тільки з реальних чисел; уніфікація не додає жодного
  «заповнювача».
- **a11y-контракти** (panes, headings, focus-restore, 48 dp) — переносяться
  в канонічні компоненти як обов'язкові, не опційні.
- **Зірки-закладки людей (★/☆)** — явний виняток користувача з
  компонентного колапсу (2026-09-07): `PersonBookmarkButton` і індикатор
  закладки в рядках людей лишаються як є; міграція рядків зберігає
  видимий індикатор закладки.

## Межі аудиту

- Код прочитано статтю; телефонних прогонів у межах цього аудиту не
  було — рішення перевіряються phone-тестами у спеку постачання
  (ADR-0017: видимий дельта закриває тікет).
- Веб-клієнт (`web/`) поза v1.4 — ті самі контракти переносяться туди
  окремою спекою.
- Повний набір тестів не запускався (AGENTS.md); Roborazzi-піни
  оновлюються разом із компонентами.
