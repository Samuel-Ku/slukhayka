# Кандидат 1.3.9.2: повний фікс 4read

## Причина

Опублікований 1.3.9.1 (`957d4067`) містив лише ранню зміну User-Agent
(`7b33d860`). Повний фікс `97981247`, після якого слухач підтвердив звук
у debug, залишився локальним. Це пропуск коміту під час підготовки релізу.

На 2026-09-08 два однакові запити до сторінки «Ім’я вітру» відрізнялися
лише заголовком: без X-Requested-With — HTTP 200, із назвою release-пакета
com.slukhayka.audiobooks — HTTP 403. Точне правило WAF без журналів
власника 4read невідоме.

## Перевірка на OnePlus 8 Pro

1. Встановлено опублікований APK 1.3.9.1. «Надзвичайний хтось», глава 1,
   двічі завершується «Не вдалося відновити відтворення». MediaSession:
   ERROR, Source error. Контрольна сума старого APK збігається з релізом.
2. Встановлено підписаний 1.3.9.2 поверх нього. Та сама книга відновилася;
   MediaSession PLAYING, позиція змінилася з 14078 до 47107 мс.
3. Перехід до глави 2 — PLAYING із метаданими глави 2. Перемотування
   вперед і пауза — PAUSED, 58618 мс. Після примусового завершення процесу
   й явного запуску Activity продовження почалося з глави 2, 58000 мс.
4. Друга книга «Цей химерний світ» — глава 1, PLAYING, 34835 мс.
   Згодом автоматично перейшла до глави 2: PLAYING, 40518 мс.
   Падінь AndroidRuntime під час завершальної перевірки не зафіксовано.

Wi-Fi, DNS, проксі та автоповорот телефона не змінювалися. Запуск — через
явний am start, без monkey. Бінарні докази й сирі журнали залишені поза git.

## Як уникнути повторення

Перед релізом звіряти коміт саме підписаного APK з комітом виправлення
і тестувати оновлення release-пакета. Успіх окремо встановленого debug
не підтверджує склад майбутнього релізу. Доданий workflow кандидата
створює підписаний артефакт без публікації тега, щоб виконати цей контроль.
