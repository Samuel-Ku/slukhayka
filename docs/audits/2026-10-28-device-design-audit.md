## 0. Метод, пристрій, обмеження

**Пристрій.** OnePlus 8 Pro (IN2023), Android 14, 1440×3168 px при `wm density 560` → **411.4 × 905.1 dp, 3.5 px/dp**. Мова застосунку — українська; тема — «Папір»; щільність — «Зручно»; «Плеєр завжди темний» — увімкнено; системна тема під час base-pass — темна (це важливо: саме вона виявляє #1530).

**Як міряли.** Два джерела, які не суперечать одне одному:
1. `adb exec-out screencap` (1440×3168) + семантичне дерево (`mobile_list_elements_on_screen` / `uiautomator dump`) — геометрія в px ÷ 3.5 = dp, кольори — вибірка пікселів ImageMagick у точках екрана;
2. код `origin/main` у чистому worktree (`.worktrees/design-audit`, детач на `27f64f40`) — `file:line` для кожної знахідки. Рядки цитовано **за origin/main**, не за робочим деревом (воно на чужій гілці).

**Що знято/перевірено на пристрої (28.10, дві сесії):** «Слухати», «Огляд», «Медіатека» (список), «Друзі» (порожній стан), «Налаштування» (верх/низ), сторінка книги, плеєр (обидві конфігурації системної теми), пошук із порожнім результатом, міні-плеєр, стан #1530. ## 1. Executive summary

Застосунок **на півдорозі міграції**, і це видно на кожному екрані. Дві системи — legacy v1.4 (M3-графіт/янтар, 16 dp поля, 15 типоролей) і напрям «Папір і голос» (папір/чорнило, 20 dp, Literata/Onest) — співіснують не лише між екранами, а **в межах одного екрана**: на «Огляді» паперовий хедер стоїть над legacy-пошуком, legacy-банером оновлення й legacy-чипами; на «Налаштуваннях» паперовий хедер із 34 sp сусідить із M3 `TopAppBar` 21 sp на вкладених екранах. Це не «недомалювання», а дві різні мови на одному полотні, і саме вона створює більшість знахідок нижче.

**Два блокери** (обидва — у конфігурації «примусова тема ≠ системна тема», яку користувач увімкнув сам):
1. **#1530** — кореневі вкладки «Слухати»/«Огляд» ігнорують примусову тему: заголовки малюються `chalk` на папері (**1.05:1**), поля/чипи/банер — темні. Фікс у PR #1531, тому тут — лише фіксація й перевірка, без дублювання.
2. **Системні бари** не знають про вибрану тему: іконки статусбара білі на папері (**1.05:1**), а смуга під ними — legacy-папір `#FAF6EE` замість `#F1EEE4` (**1.08:1** до фону). #1531 цього не закриває (підтверджено з коду: `enableEdgeToEdge()` без `SystemBarStyle`).

**Головні системні знахідки:**
- **Стан вибору невидимий.** `primaryContainer` (#DCE8DE) на папері = **1.09:1**, у «Чорнилі» #24382F на #0E1411 = **1.49:1**. Це стосується активної вкладки навбару та сегментів теми/щільності (бейдж «слухаєш» і play-диск рядка — окремі випадки, F3b). WCAG 1.4.11 вимагає 3:1 для стану — тобто зараз вибір тримається лише на відтінку, який не читається.
- **Бурштин як текст** = **3.80:1** на папері (потрібно 4.5:1). У палітрі вже є правильний `LampInk #7A4E00` (**6.20:1**), але він **не замаплений у жодну роль** — тому будь-який `tertiary`-текст автоматично провалює AA.
- **«Огляд» витрачає 2/3 екрана до першого контенту.** Від верху до першого постеру — **≈703 dp** із 905 dp із банером оновлення (без нього — ≈575 dp): хедер 104 + поле пошуку 69 + legacy-банер ≈90 + чипи 48 + два заголовки поспіль без контенту. Ціль спеки — перший рядок ≤ 350 dp.
- **Плеєр відстав від спеки, і обкладинка — МЕНША за старий дизайн.** Виміряно на пристрої: **198×297 dp (48 % ширини)** проти **208×315 dp** у v1.4 і **272×408** у спеці. Причина — `coverHeight.coerceAtMost(maxHeight)` стискає обкладинку по висоті (слот ≈297 dp), а не по ширині. Глиф play — **40 dp** замість 28–30; перемотка — **дзеркальний `Replay` + підписи «15 с»/«30 с»** замість `rew15`/`fwd30`; на екрані два майже однакові прогреси й **дубльований час `00:14`**.
- **Hero «Слухати» показує заглушку замість обкладинки.** Найпомітніша картка застосунку рендерить паперову плитку з літерою «Т» (`PaperInkCover`), хоча та сама книжка має реальний арт на «Огляді», у «Медіатеці», на сторінці книги й у міні-плеєрі.
- **Медіатека: список книг досі без обкладинок.** Рядок «Книги» — legacy dense-row із timeline-крапкою, 0 обкладинок; до першого рядка **≈400 dp** (ціль ≤240). Плюс хедер із трьома діями, дві з яких — тональні диски, а шестерня гола.
- **Сторінка книги не мігрована:** центрована обкладинка ≈130×202 dp замість компактного героя 118×177 поруч із назвою; у метаданих видно «15 15 розділів» (дубль числа); «Завантажити» — голий текст, «Додати закладку» — outlined-кнопка.
- **Іконки — 84 різні гліфи, 234 місця, 13 різних розмірів (12–40 dp), 100 % родини Material Filled.** Але всередині «однієї» родини оптична вага гуляє від суцільних плям (`Person`, `Star`, `Favorite`) до тонких контурів (`Language`, `Translate`, `SdCard`) — у списку «Налаштувань» це видно як рваний ритм. Це головна причина, чому іконки «виглядають старими»: вони не утворюють мови.

**Що працює добре і чіпати не треба:** «Слухати» (hero → полиці) — найбільш цілісний екран напряму; паперовий рядок книги й плакат; типографіка Onest+Literata; палітра; плитка/полиця без карточок. Обкладинку плеєра **не зменшувати**: зараз вона 198×297 dp — **менша** за старий дизайн (208×315), тож її треба підняти до 272, а не назад.

## 3. Тема, системні бари, матеріал

### F1 — blocker — кореневі вкладки ігнорують примусову тему (#1530)

**Стан:** тема «Папір», системна тема темна. **Скріншот:** [`01-overview-forced-paper-system-dark-theme-bug.png`](assets/2026-10-28-device/01-overview-forced-paper-system-dark-theme-bug.png).

Причина (код): корені «Слухати»/«Огляд» обгорнуті в `PaperInkTheme`, чий `darkTheme` береться з `isSystemInDarkTheme()`, а не з вибору користувача.

```kotlin
SelectedTab.LISTEN -> PaperInkTheme { ListenScreen(...) }
SelectedTab.EXPLORE -> PaperInkTheme { HomeScreen(...) }

// PaperInkTheme.kt:44–49
fun PaperInkTheme(darkTheme: Boolean = isSystemInDarkTheme(), ...)
```

Виміряно з пікселів: колір заголовка ≈ `#ECE8DB` (`chalk` — це `onBackground` схеми «Чорнило») на фоні `#F1EEE4` → **1.05:1**. Поле пошуку/банер — `surface`/`surfaceVariant` схеми «Чорнило» (`#161D19`/`#1E2721`).

**Фікс уже в PR #1531** (`origin/fix-1530-tab-theme`, заміна на `PaperInkThemedContent`) — **не дублювати**. Доказ «до/після» від fix-engineer — [`theme-fix-1531-before-after.jpg`](assets/2026-10-28-device/theme-fix-1531-before-after.jpg). Цей аудит фіксує лише те, що знахідка відтворена на пристрої, і що вона не єдина у своєму класі (див. F2).

### F2 — high — системні бари не знають про тему застосунку

**Скріншот:** [`02-settings-paper-top.png`](assets/2026-10-28-device/02-settings-paper-top.png). Угорі: `21:15`, іконки сповіщень, Wi-Fi, батарея — майже білі на світлій смузі. Двобічність дефекту видно й на [`theme-fix-1531-before-after.jpg`](assets/2026-10-28-device/theme-fix-1531-before-after.jpg) (від fix-engineer): після #1531 іконки лишились системними.

Два різні дефекти в одному місці:

1. **Колір іконок** статусбара береться із системної теми, а не з вибраної в застосунку. Замір: `#FDFCF9` (майже білий) на `#FAF6EE` → **1.05:1**. Користувач зі світлою системою й примусовим «Чорнилом» отримає зворотну проблему.
2. **Колір смуги**: статусбар-зона малює **legacy-папір `#FAF6EE`** (стара світла тема, `Color.kt`), а тіло екрана — новий папір `#F1EEE4`. Різниця **1.08:1** — це не «майже не видно»: на телефоні це чітка горизонтальна смуга іншого відтінку на всю ширину.

**Другий бік тієї самої проблеми (виміряно на плеєрі):** плеєр завжди «Чорнило» (правило напряму), але при системній світлій темі статусбар малює **темні** іконки на нічному фоні: `#231B17` на `#1F1814` = **1.06:1**. Тобто дефект двобічний: світла система + темний екран так само нечитабельний, як темна система + світлий екран. Один фікс закриває обидва випадки.

Причина в коді:
- `MainActivity.kt:311` — `enableEdgeToEdge()` без аргументів. На Android 14 `SystemBarStyle.auto()` визначає «темні/світлі іконки» з `Configuration.uiMode` (**системної** теми).
- У всьому `app/src/main/java` немає жодного звернення до `WindowInsetsControllerCompat`, `isAppearanceLightStatusBars` чи `SystemBarStyle`.

**Рекомендація (окремий маленький PR):**
```kotlin
// у AudiobookTheme після обчислення darkTheme:
val view = LocalView.current
val window = (view.context as Activity).window
SideEffect {
    WindowCompat.getInsetsController(window, view).apply {
        isAppearanceLightStatusBars = !darkTheme
        isAppearanceLightNavigationBars = !darkTheme
    }
}
```
і для плеєра (він завжди «Чорнило», §2 правило 6): поки `showFullPlayer`, форсувати `isAppearanceLightStatusBars = false`, щоб іконки були світлі на нічному екрані. Плюс прибити `window.setBackgroundDrawable(ColorDrawable(Paper))` / колір `Scaffold` до палітри напряму, щоб зник legacy-папір смуги. **#1531 цього не закриває** — перевірено fix-engineer на пристрої.

| Елемент | Прототип (`app.css`) | Застосунок (виміряно) | Δ |
|---|---|---|---|
| Обкладинка | `.p-cover` 272×408 | **198×297** (48 % ширини) | **−74 dp** |
| Старий дизайн v1.4 | — | 208×315 (50.6 %) | застосунок **менший за старий** |

**Чому обкладинка 198, а не 243.** Код: `coverWidth = (maxWidth * 0.67f).coerceAtMost(272.dp)`, але далі `coverHeight = (coverWidth / coverAspect).coerceAtMost(maxHeight)` і розмір береться від `coverHeight`. Слот по висоті ≈297 dp — тому ширина падає до 297 × 0.667 = **198 dp**. Тобто обкладинка затиснута висотою, а не шириною; на екрані 411×905 вона виглядає меншою, ніж у старому дизайні.

**F7 — головна вимога користувача: обкладинку НЕ зменшувати, а підняти до 272.** Щоб 272×408 влізло у 905 dp, треба звільнити ≈110 dp хрому — і це саме ті надлишки, що вже є:
- прибрати read-only «лінійку книги» зверху (≈60 dp: час + ticks + 0 %) — за спекою лишається **один** seek;
- прибрати дубльований elapsed у рядку розділу (`00:14` вдруге) — 0 dp, але прибирає плутанину;
- швидкі інструменти — один рядок із підписом (зараз «1.0× / Швидкість» — два рядки, ламає базову лінію, F32) — економія ≈20 dp;
- прибрати один із двох міжрядкових проміжків ≈16 dp.
Разом ≈96–110 dp → 272×408 вміщається із запасом на 2-рядкову назву.

**F32 (med) — інші дефекти плеєра:**
- **Розділ пофарбований вердиґрисом** («Темна матерія-01» — світло-зелений), а спека §3.1/§4 каже «поточний розділ — лампа». Семантика кольору зламана: звук мусить бути бурштиновим.
- **Час `00:14` дублюється** у двох рядках прогресу (книга і розділ) — користувач бачить той самий час двічі.
- **Два майже однакові прогреси** (тонка лінія книги з 12+ поділками-ruler і 6 dp seek розділу) — спека вимагає один seek + read-only лінію з 3 поділками частин.
- **Швидкі інструменти**: «1.0×» + «Швидкість» двома рядками при однорядкових «Таймер/Закладка/Розділи» — базова лінія підписів різна.

### 5.2 Діагноз: сім конкретних неконсистентностей

1. **Одна родина — різна оптична вага.** Усі 84 — `Filled`, але гліфи в ній намальовані з різною щільністю: суцільні плями (`Person`, `Star`, `Favorite`, `Headphones`, `EmojiEvents`, `Whatshot`, `PlayArrow`) і майже контурні (`Language`, `Translate`, `Public`, `SdCard`, `Link`, `Cast`, `Bedtime`). У списку «Налаштувань» це читається як рваний ритм: перші три рядки «важкі», наступні два — «легкі».
2. **Немає шкали розмірів.** 13 значень від 12 до 40 dp; трапляються 13 dp (бейдж «завантажено»), 15 dp (бренд-хвиля), 21 dp (рядки налаштувань), 26 dp (перемотка), 40 dp (play). Сусідні Surface мають 18 і 21 dp в одному рядку.
3. **Дублі семантики з різними гліфами:** `ChevronRight` ↔ `KeyboardArrowRight` ↔ `ArrowForward` (три «далі»); `MenuBook` ↔ `AutoMirrored.MenuBook`; `Close` ↔ `Clear`; `CloudDownload` ↔ `Download`; `Tune` ↔ `FilterAltOff` ↔ `Sort`; `ArrowUpward/ArrowDownward` ↔ `KeyboardArrowUp/Down`; `PlayArrow` ↔ `PlayCircle`; `Timer` ↔ `Bedtime`.
4. **Дзеркалення як заміна гліфа.** Перемотка вперед — той самий `Replay`, повернутий `scaleX(-1)` (`PlayerScreen.kt:1787,1800–1820`), плюс зовнішній підпис «30 с». У прототипі — окремі `ic-rew15`/`ic-fwd30` з цифрою всередині (index.html:31–32).
5. **Мікроіконки.** 12–15 dp: хрестик «не цікаво» на плакаті (12), хмара «завантажено» в міні-плеєрі (13), хмара в рядку (14), бренд-хвиля (15). Нижче 16 dp гліф перестає читатись.
6. **Текст замість іконки.** `★` у рядках рейтингу: `PublicCollectionsRail.kt:44`, `PublishedCollectionsBlock.kt:107`, `PublicCollectionContent.kt:184`, `CollectionsWithBookBlock.kt:79`. Це рендериться шрифтом Onest (не іконка), вага/розмір не збігаються з `Icons.Default.Star` у сусідньому місці. Ще `→` у рядку «Категорія → Огляд» (`WebSourceBrowserScreen.kt:647`) — і текст захардкожений українською.
7. **Launcher випадає з мови.** Стара пара графіт+янтар (`#0D1117`/`#E9A13B`) описує «нічну бібліотеку» v1.4, а не «Папір і голос»; monochrome-шар — той самий кольоровий foreground, тому тематична іконка Android 13+ виглядає брудно.

### 5.3 Напрям: власна родина `PaperInkIcons` (свідома поправка до спеки §3.6)

**Рішення: іконки — власна SVG-родина прототипу, а не Material Symbols Rounded.** Спека §3.6 (26.10) писала «Material Symbols Rounded, `wght 400`, `fill 0/1`», але прототип того ж дня вже містив **39 власних гліфів** (`docs/prototypes/2026-ui-refresh/index.html:12–52`) зі stroke 1.8–1.9, round caps. Матеріалізація цієї родини:
- дає характер «чорнило пера», якого Material не дає (компас із залитою голкою, бібліотека як три корінці, хвиля з п'яти смуг, шестерня-контур);
- тримає **одну вагу** для всіх гліфів — проблему 5.2.1 неможливо вирішити в межах `Filled`-родини Material;
- дозволяє `rew15`/`fwd30` з цифрою всередині — Material такого гліфа не має (у першому PR — `Replay` без цифри, бо підписи «15 с»/«30 с» ще видимі; `rew15`/`fwd30` — у player-PR, узгоджено з `icon-engineer` 28.10);
- лишає `fill` як **семантичний стан** (play/pause/star/heart/bookmark), а не як «інший стиль» — це збігається з правилом спеки «активний стан — `fill 1`, не інший стиль».

Ціна рішення: ~30 нових гліфів доведеться намалювати (Tier 1) і замінити 234 місця поступово. Ризик «двох мов» під час міграції знімається правилом §5.4.7 (Tier 2 — тільки `Outlined`, ніколи не `Filled`).

### 5.4 Стильові правила (обов'язкові для `PaperInkIcons`)

1. **Сітка.** `viewBox="0 0 24 24"`; безпечна зона 2 dp (гліф у 2..22); оптичний центр (12, 12); залиті гліфи можуть виходити до 1.5 dp.
2. **Штрих.** База `stroke-width = 1.8`. `1.9` — шеврони, search, chevron (тонкі довгі лінії потребують +0.1, щоб не «худнути»). `1.7` — `rew15`/`fwd30` (щільна графіка з цифрою). `2.0` — тільки `plus`, `check`, `close` (короткі лінії). У межах одного ряду/списку — **одна** товщина.
3. **Кінці й з'єднання.** `stroke-linecap="round"`, `stroke-linejoin="round"` — завжди. Жодних `square`/`miter`.
4. **Заливка.** `fill` — тільки для семантичного стану: `play`, `pause`, `skip-back`, `skip-fwd`, `wave` (бренд), `star` (оцінка), `heart` (обране), `bookmark` (збережено), `flame` (серія), голка `compass`. Контур — для дій і навігації.
5. **Активна вкладка навбару — НЕ filled-варіант.** Як у прототипі (`assets/app.css:353–364`): та сама контурна іконка + тональна пігулка **50×30** + колір стану. Після F3 це не `primaryContainer` (1.09:1), а: папір — пігулка `Verdigris` + іконка `OnVerdigris`; чорнило — пігулка `VerdigrisNight` + іконка `OnVerdigrisNight`. Неактивна — `onSurfaceVariant`, без пігулки.
6. **Оптичні розміри** (рендер, не сітка): 20 dp — інлайн/чипи/дрібні дії; 22 dp — дії хедера (`.icon-btn svg` 22); 23 dp — навбар; 24 dp — шапка/інструменти; 28 dp — транспорт плеєра (прототип 30; дозволено 28–30, але **один** вибір); 30 dp — play у плеєрі (не 40). Один гліф малюється раз у 24-сітці й масштабується; фізична товщина штриха тоді 1.5→2.1 dp — це узгоджено зі шкалою тексту (20 ↔ 12–13 sp, 28 ↔ 21 sp).
7. **Tier-правило для хвоста.** Іконки, яких немає в родині (≈25: `BugReport`, `ContentCopy`, `Cast`, `SdCard`→`Storage`, `Today`, `FilterAltOff`, `RemoveCircleOutline`, `SettingsBackupRestore`…), тимчасово беруться з `Icons.Outlined.*` — **не** `Filled` — у тих самих 20/24 dp. Правило «ніколи не змішувати `Filled` і `Outlined` в одному списку/рядку» непорушне. Debug-overlay (`PlayerDebugOverlay`) — поза системою (Tier 3), не чіпати.
8. **RTL/дзеркалення.** Дзеркаляться лише напрямні: `chevron-left/right`, `arrow-right`, `undo`, `open-in-new`. У Compose — `Modifier.scale(-1f, 1f)` або окремі `AutoMirrored` гліфи; **не** дзеркалити `rew15`/`fwd30`, `play`, `skip` (вони напрямні за семантикою, але мають власні гліфи з цифрами і в RTL лишаються як є — зафіксувати в коді коментарем).
9. **Колір.** Іконки успадковують `currentColor` (`tint`); ніяких hardcoded `fillColor="#FFFFFFFF"` (зараз у 4 drawable).
10. **API (узгоджено з `icon-engineer`, PR #1534).** Без third-argument-магії:
```kotlin
object PaperInkIcons { val Play: ImageVector; … val All: List<ImageVector> }   // чисті ImageVector
object PaperInkIconSizes { Inline 20.dp; Chrome 22.dp; Navigation 23.dp;
                           Header 24.dp; Transport 28.dp; Play 30.dp }
@Composable fun PaperInkIcon(imageVector: ImageVector, contentDescription: String?,
                             modifier: Modifier = Modifier,
                             size: Dp = PaperInkIconSizes.Header,
                             tint: Color = LocalContentColor.current)
```
`ImageVector`-константи — робочий контракт (працює з `Icon`, `NavigationRailItem`, Canvas); `PaperInkIcon` — зручний хелпер; **тач-таргет лишається на контейнері**, хелпер його не змінює.

### 5.6 Стани: активний/неактивний/вибраний

| Компонент | Візуально | Семантика |
|---|---|---|
| Навбар, вкладка | активна: пігулка 50×30 + контурна іконка 23 dp кольором стану; неактивна: без пігулки, `onSurfaceVariant` | `selectable(selected = …)`, `role = Tab`, підпис завжди видимий 11 sp; `contentDescription = null` на іконці (підпис уже в дереві) |
| Сегмент (тема/щільність) | вибраний: заливка `Verdigris` + `OnVerdigris` + галка 16 dp; невибраний: `LineStrong` 1 dp контур | `selectable(role = RadioButton)`; **не** залежати від відтінку (F3) |
| Кнопка play/pause | filled-гліф; колір `tertiary`/`OnLampSoft` | `stateDescription` «відтворюється/пауза», `role = Button` |
| Закладка/обране/зірка | filled-гліф = увімкнено | `toggleable` + `stateDescription` |
| Прогрес | кільце/смуга `Lamp` на `Track` (контраст ≥3:1) | `progressBarRangeInfo` |

**Канонічні пари стану (узгоджено з `icon-engineer` 28.10):** `Heart` (контур) ↔ `HeartFilled` (обране), `Bookmark` ↔ `BookmarkFilled` (збережено), `Star` / `StarOutline` / `StarHalf` (рейтинг), `Play` / `Pause` (завжди filled). `icon-map.tsv` у колонці `target` може називати базову семантику (`Star`, `Bookmark`, `HeartFilled`) — це та сама пара, не розбіжність; канонічні імена — у коді `PaperInkIcons`.

### 5.7 Доступність (обов'язково)

1. **`contentDescription`:** кожна іконка-дія має опис українською з ресурсу (`a11y_*`); декоративні — `null`. Зараз у коді лише **8 із 234** icon-вузлів несуть опис у самому рядку, **36** — явний `null`, решта отримують опис від контейнера (`IconButton`/merged semantics). Вибірково перевірено: контейнери хедера/навбару/міні-плеєра описи мають; у нових `PaperInkIcons` правило — опис на інтерактивному контейнері, не на гліфі.
2. **Тач-таргет:** 48×48 dp мінімум, навіть якщо гліф 20–23 dp. Візуальна пігулка/чип може бути 36 dp.
3. **Масштаб тексту:** підпис навбару 11 sp не капати (F13).
4. **Не покладатись лише на колір** (F3).
5. **TalkBack-порядок** = візуальний; у навбарі — 4 вузли `role = Tab`.
6. **Опис іконки не повторює підпис:** кнопка «Пошук» → «Пошук», а не «Іконка пошуку».
