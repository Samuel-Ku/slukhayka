# План: #1482 — прибрати флейк `BrowserDnsProxy.close()`

`scripts/test-changed.sh` на воркері впав на чужому PR: `BrowserDnsProxyTest`
кинув `NoSuchElementException` у `BrowserDnsProxy.close()` (рядок 130,
`sockets.toList().forEach(::closeSocket)`). Причина: `close()` ітерує
колекцію сокетів, поки `closeSocket()` (і воркер-потоки) видаляють з неї
елементи — ітерація по колекції, що змінюється. Під навантаженням це
нестабільно червонить будь-який PR.

## Рішення

1. **Виділити реєстр сокетів в один маленький клас `TrackedSockets`** (internal,
   той самий файл): усі операції — `track`, `forget`, `drain` — під одним
   `synchronized`-локом; `drain()` робить **snapshot-and-clear** і повертає
   кожен сокет рівно один раз. Закриття сокетів відбувається ПОЗА локом, тож
   повільний `Socket.close()` не тримає реєстр.
2. **Прапорець `closed` у реєстрі:** сокет, який намагаються взяти на облік
   після `close()`, одразу закривається (`track` → false). Це закриває гонку
   «accept встиг до close, але додався після snapshot» — інакше такий сокет
   лишався б живим після закриття проксі.
3. `BrowserDnsProxy.close()` = `listener.close()` + `sockets.drain().forEach { it.close() }`
   + `workers.shutdownNow()`; жодного `toList()` по колекції, яку хтось
   змінює.

## Межі (названі)

- публічна поведінка проксі не змінюється (CONNECT/plain-HTTP/502 шляхи,
  direct-route відмова, DNS через app resolver — наявні тести);
- реєстр не знає про протокол — лише «набір сокетів + закрити всі»;
- `closeSocket` у проксі = `forget` + `close`, як і раніше.

## Перевірка

- `TrackedSocketsTest` (чистий JVM): `drain` повертає кожен сокет рівно раз і
  чистить реєстр; повторний `drain` порожній; сокет, доданий після `drain`,
  одразу закривається і не повертається; `forget` прибирає з майбутнього
  `drain`; конкурентний молот (кілька потоків `track`/`forget`/`drain`) не
  кидає винятків і не втрачає сокети мовчки.
- `BrowserDnsProxyTest` — наявні 6 тестів зелені (поведінка не змінена).
- Мутації: (а) прибрати `closed = true` у `drain` → тест «доданий після drain»
  червоніє; (б) прибрати `sockets.clear()` → тест «повторний drain порожній»
  червоніє.
- Цільові: `:app:testPureJvm` для двох класів; повний матрикс — CI.
