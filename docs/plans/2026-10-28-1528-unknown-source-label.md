# План: #1528 — probed-картка не показує сирий маркер «unknown»

Після #1487 зріз 2 у медіатеці є картки, імпортовані зі сторінки **невідомого**
хоста під внутрішнім маркером `UNKNOWN_SOURCE_ID` (`"unknown"`). Медіатека його
ховає (provenance-чіп), але **сторінка книги** рендерить рядок джерела:
`sourcesForBook` віддає `WorkSourceRow(sourceName = sourceDisplayName("unknown"))`,
а `sourceDisplayName` для незареєстрованого id повертає сам id — тобто
літеральне «unknown» у секції «Джерело»/«Джерела».

## Рішення

1. **Маркер не є джерелом — рядок не рендериться.** `SourceCatalog.sourcesForBook`
   відфільтровує `UNKNOWN_SOURCE_ID` так само, як уже відфільтровує scam-джерела
   (ADR-0037). Секція «Джерела» в `BookDetailSourceSection` уже ховається при
   порожньому списку — жодного порожнього заголовка не буде.
2. **Не чіпаємо показ відомих джерел** і не вводимо людську назву-псевдонім:
   «Веб-сторінка» виглядала б як зареєстроване джерело й мусила б локалізуватися
   (uk/pl/en), тоді як фактичне джерело — сама сторінка (URL лишається в даних).
3. **Той самий маркер ховаємо всюди, де це вже зроблено:** медіатека
   (`LibraryModel`), provenance-чіпи; зміна лише в одному резолвері «Джерел».

## Межі (названі)

- це display-шар: імпорт, плейбек, дедуп не змінюються;
- legacy-рядок без `workId` (fallback через `sourceIdForUrl`) теж не показує
  «unknown» — фільтр стоїть на обох шляхах;
- інші невідомі id (не маркер) не фільтруються: фільтр — точна рівність
  `UNKNOWN_SOURCE_ID`, а не евристика.

## Перевірка

- `WorkSourcesRepositoryTest`: post-merge Work із `work_sources.sourceId =
  "unknown"` → `sourcesForBook` порожній; pre-merge рядок із URL невідомого
  хоста → порожній; наявні тести відомих джерел зелені.
- Мутація: прибрати фільтр → новий тест червоніє.
- Цільові: `:app:testRoomRobolectric -Ptest.selectedClasses=…WorkSourcesRepositoryTest`;
  повний матрикс — CI.
