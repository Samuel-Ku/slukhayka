# План: #1553 — заголовок live-пошуку не показує «(0)», поки пошук триває

`SearchResultsContent` рендерив заголовок «Знайдені книги (N)» одночасно зі
статусом «Шукаємо в усіх джерелах»: під час польоту N = 0, тож людина бачила
дві суперечливі заяви про один пошук. Web у цей момент заголовка з числом не
рендерить (`Catalog.tsx:628-629`), а ADR-0014 вимагає, щоб лічильник
оновлювався лише після факту.

## Рішення

1. Заголовок `all_sources_header` (тег `search_sources_header`) рендериться
   лише коли `liveSearchActive && !isGlobalLoading`. Під час польоту лишається
   чесний `GlobalSearchStatus`; після завершення заголовок повертається з
   фактичним числом.
2. Два нові тести: (а) у польоті заголовка й тексту «Знайдені книги (0)» немає;
   (б) число попереднього запиту не показано як поточний результат (під час
   польоту, з карткою, що вже є на екрані).
3. Порожні стани, локальна секція, retry, `GlobalSearchStatus`, web — без змін.

## Перевірка

- `:app:testRoomRobolectric -Ptest.selectedClasses=…SearchResultsContentTest`
  — зелено (наявні + 2 нові).
- Мутація «прибрати `!isGlobalLoading` з умови» → новий тест «у польоті» і
  «попереднє число» червоніють.
- Снапшот-еталони не змінюються: у статичних станах (не loading) заголовок
  той самий; CI — вичерпний гейт.
