# План: #1563 — повернення фокуса на шестерню не залежить від мови

Web обіцяє: вийшов із «Налаштувань» — фокус повертається на шестерню. Але
fallback (`App.tsx:592-595`) шукав її за українським літералом
`aria-label === "Налаштування"`, а aria-label локалізований (`t("tabSettings")`).
Коли `settingsFocusRef` вказує на відключений вузол (шестерня перемонтована),
в українському інтерфейсі фокус повертався, в англійському — губився.
Тест пінив контракт лише українською.

## Рішення

1. Шестерня отримує стабільний `data-settings-entry="true"`; fallback шукає
   `[data-settings-entry]` і не залежить від локалі.
2. Новий EN-тест: `setUiLocale("en")`, відкрити Settings, натиснути
   «← Back», дочекатися `document.activeElement` з `aria-label="Settings"`.
   Наявний uk-тест не змінений.
3. Контракт (вибір вкладки, Back, очищення) не переписується.

## Межі

- змінюється лише селектор fallback + один атрибут кнопки; логіка
  `openSettings`/`settingsFocusRef` не чіпається;
- Android не зачіпається; `npm run typecheck` і `vitest` — вичерпні для web.

## Перевірка

- `npx tsc --noEmit` — exit 0;
- `npm test -- src/ui/appLayoutPanes.test.tsx` — наявні + новий EN-тест;
- мутація «повернути пошук за літералом `Налаштування`» → EN-тест червоніє,
  uk-тест лишається зеленим (доводить, що саме мова була дефектом).
