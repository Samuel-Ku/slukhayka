# План: #1576 — два resume-модулі стають одним

`PlaybackResume` (рішення: який рядок прогресу відновити й чи відновлювати)
і `PlaybackResumption` (адаптер до `MediaSession.MediaItemsWithStartPosition`)
жили двома об'єктами в одному пакеті: перший кликав другий, обидва мали власні
KDoc про той самий #805-контракт. Це два імені для одного знання.

## Рішення (deletion test першим)

1. **`PlaybackResume` — єдиний модуль.** `itemsFor` переїхав у нього як тонкий
   Media3-адаптер над `resumeMostRecent`; разом переїхали `ITEM_WAIT_MS`,
   `currentItems`, `awaitItems`, док-коментарі про bounded wait і позицію з
   стану менеджера (а не з двигуна).
2. **`PlaybackResumption.kt` видалено.** Друге ім'я зникло з прод-коду;
   `PlaybackService` кличе `PlaybackResume.itemsFor(...)`, коментарі
   посилаються на єдиний модуль.
3. **`@file:androidx.annotation.OptIn(UnstableApi::class)`** на об'єднаному
   файлі (той самий патерн, що в `AudioPlayerManager`) — два `UnsafeOptIn`
   записи lint-baseline для видаленого файлу прибрано (baseline може лише
   скорочуватись); запис для `PlaybackService.onPlaybackResumption`
   лишається чинним.
4. **Тести:** `PlaybackResumptionTest` перейменовано в
   `PlaybackResumeItemsTest` (той самий набір, той самий сценарій), виклик —
   `PlaybackResume.itemsFor`. `PlaybackResumeTest` не змінений.
5. Поведінка не змінюється: жоден рядок рішення/очікування не переписаний,
   лише переміщений.

## Межі

- у межах PR немає рефакторингу `PlaybackService`/`AudioPlayerManager`; лише
  перенесення адаптера, видалення другого імені й оновлення посилань;
- widget/in-app tile лишаються на тому самому `resumeMostRecent`;
- `lint-baseline` зменшується лише на два записи видаленого файлу.

## Перевірка

- `:app:testRoomRobolectric -Ptest.selectedClasses=…PlaybackResumeTest,…PlaybackResumeItemsTest`
  — зелені (ті самі сценарії, нове ім'я класу).
- Мутація: замінити `restored -> awaitItems(player)` на `restored -> emptyList()`
  → тест «returns the restored item and the saved position» червоніє (межа
  «чекаємо появи item, а не віддаємо порожньо») — доводить, що перенесений
  код справді виконується.
- CI: Pure JVM/Robolectric/Lint зелені; lint-baseline не виріс.
