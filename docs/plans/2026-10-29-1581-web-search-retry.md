# План: #1581 — failed-пошук у web не глухий кут

Коли пошук у web-каталозі падає, людина бачила лише
«Джерело не відповіло спробуйте пізніше.» без жодної дії: pill «Оновити»
схований у режимі пошуку (`Catalog.tsx:457` рендериться лише для
`query < CATALOG_SEARCH_MIN_CHARS`), а повторний той самий запит — свідомий
no-op у сесії (`sameIntent` без `forceRefresh`). Android у цьому стані має
«Спробувати ще раз» (`SearchResultsContent.kt:121-126`).

## Рішення

1. **Дія в failed-стані:** `EmptyStateRow` отримує кнопку
   «Спробувати ще раз» (наявний рядок `retry`), що викликає `retrySearch()`.
2. **Справжній повтор:** `retrySearch` використовує наявний explicit-refresh
   механізм — `forceRefreshRef.current = true` + `refreshNonce++` → ефект
   `setIntent({source, query, forceRefresh})` створює НОВИЙ generation, тож
   повторення того самого запиту не є no-op.
3. **Uk-рядок виправлено:** «Джерело не відповіло — спробуйте пізніше.»
   (пунктуація як в EN; дія не змінює сенсу).
4. Решта станів (searching, порожній успішний, часткові збої, «Оновити» для
   стрічки) не змінені; сесія не переписується.

## Межі

- змінюється лише failed-стан пошуку та один uk-рядок; Android не
  зачіпається;
- web — вичерпні гейти `tsc --noEmit` + `vitest`; goldens/Android не
  зачіпаються.

## Перевірка

- `npx tsc --noEmit` — exit 0;
- `npx vitest run src/ui/catalogSearchReturn.test.tsx` — наявні + новий тест
  (перший пошук падає → дія є → клік → запит повторено, результати з'явились,
  `workSearch` викликаний двічі);
- мутація «кнопка retry нічого не робить» → новий тест червоніє.
