# План: #1653 — пінити книжковий guard overlay-у (F1/F2 огляду #1651)

## Що не так

Оглядач PR #1651 показав: новий steady-state тест `PlayerDurationFactsTest`
передає `liveBook = null` в обох `assertSame`, тож терм
`liveBook != currentBook` (`PlayerDurationFacts.kt`) не піниться. Його
мутація «прибрати цей терм» **survived** (7/7 green); та сама мутація з
`liveBook = sameBook` — **killed** 7/1. Отже діра суто в тесті (F1).

Другий `assertSame` (F2) після виправлення перевіряє той самий шлях, але з
іншим початковим станом (`original` із `total=0`, а не з новим `total`) —
лишаємо обидва з точними назвами: один пінить «нове total + рівні рядки»,
другий — «сирий стан + структурно рівна книга».

## Рішення

Тест-only правка (без змін продуктивного коду):
- перший `assertSame`: `liveBook = sameBook` (екземпляр уже в `withNewTotal.currentBook`);
- другий: `liveBook = original.currentBook` (той самий інстанс);
- рядок плану #1650 узгоджено з тим, що тест реально пінить.

## Перевірка

- pure-jvm 7/7.
- Мутація M1 (`live.durationSeconds !=` → прибрати) — killed (як і раніше).
- Мутація M2 (`liveBook != currentBook` → прибрати) — тепер **killed** 7/1.
- CI: звичайний гейт (тест-only; Compose+Roborazzi, Room-ноги).

## Межі

- Нічого не змінює поведінку; лише розширює захист тестом. Названа межа:
  мутаційний свідок M2 виконується локально на dragonborn, у CI мутації не
  запускаються (стандартна практика репо).
