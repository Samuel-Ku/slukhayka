# План: #1657 — PATH env-файла патруля має переживати mise upgrade

## Симптом (виміряний)

`systemctl --user status ui-ux-patrol.service` → **failed (status=2)** 28, 29 і
30 жовтня. `journalctl --user -u ui-ux-patrol.service`:
«не прочитав наявні тікети патруля: не знайдено виконуваний файл: gh»,
«агент не надрукував контрактний рядок результату … код 1, вердикт: немає».

## Причина

`write_env_file()` генерує `~/.config/slukhayka/ui-ux-patrol.env` з PATH,
де бере `Path(shutil.which("gh")).parent` — **версійний** каталог
`…/installs/gh/latest/gh_2.102.0_linux_amd64/bin`. `mise` оновив gh
(`latest -> 2.103.3`), старий каталог зник → таймер (який не читає
`~/.bashrc`) не бачить `gh`, а без нього патруль не створює тікетів і падає
на контракті. Стабільні `~/.local/bin` (симлінк gh) і
`~/.local/share/mise/shims` у PATH не потрапляли.

## Рішення

1. `stable_tool_dirs(home)` — існуючі стабільні каталоги: `~/.local/bin`,
   `~/.local/share/mise/shims`.
2. `patrol_path_dirs(...)` — стабільні каталоги **першими** (активна версія
   перемагає мертвий шлях), далі версійні (dsh/gh/python3), далі системні;
   дедуп зберігається.
3. `write_env_file()` використовує `patrol_path_dirs()`; `render_env_file`
   не змінюється (той самий формат, 0600, GH_TOKEN опційний).

## Перевірка

- `python3 -m unittest scripts/tests/test_ui_ux_patrol.py` → 59 тестів (+3 нові):
  стабільні каталоги першими; відсутні стабільні не вигадуються; мертвий
  версійний каталог лише fallback після shims.
- Локальна операційна перевірка на hub: env-файл оновлено стабільними
  каталогами, `env -i … gh auth status` → автентифікований (keyring бачиться);
  наступний нічний прогін має пройти (03:20 за таймером).
- CI: script unit tests (єдина нога, що покриває `scripts/`).

## Межі

- Це лагодить генерацію env-файла, а не сам таймер: якщо `gh`/`dsh` знову
  зникнуть зовсім, потрібен `install`. Таймер не зачіпається.
- Env-файл на hub оновлено окремо (ops), щоб патруль не чекав мерджу PR.
