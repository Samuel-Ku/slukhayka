# План: #1664 — пінимо fchmod-порядок у write_env_file

Не-блокуючий ніт повторного огляду PR #1663 (#1662).

## Що не так

`write_env_file` для **наявного** env-файла з правами 0644: `os.open(flags,
0o600)` не змінює режим існуючого файла, тож без окремого `fchmod` секрет ліг
би у світ до фінального `chmod 0600`. Фікс (#1662) додав
`os.fchmod(fd, 0o600)` одразу після open, але **тест цього не пінив**: єдиний
тест перевіряв фінальні права, а не режим у момент запису. Оглядач довів
порядок spy-скриптом, не тестом.

## Рішення

Тест-only правка `scripts/tests/test_ui_ux_patrol.py`:
`test_fchmod_makes_existing_env_private_before_write`:
- створює `~/.config/slukhayka/ui-ux-patrol.env` із 0644 у тимчасовому HOME;
- підмінює `patrol.os.write` spy-функцією, яка фіксує `fstat(fd).st_mode`;
- викликає `write_env_file(...)` і перевіряє: режим **у момент запису** =
  0600, фінал = 0600, ключ у файлі.

Мутація «прибрати `os.fchmod`» має вбивати цей тест.

## Перевірка

- `python3 -m unittest scripts/tests/test_ui_ux_patrol.py` → **71 тест**.
- `bash scripts/mutate.sh --patch <fchmod-off> --python
  scripts/tests/test_ui_ux_patrol.py::ModelKeyTest` → **killed** (run-id у
  коментарі огляду/PR).
- CI: script unit tests.

## Межі

- Тест перевіряє саме порядок «режим 0600 до запису», не вміст env-формату;
  формат/поведінка прод-коду не змінюються. Spy замінює `os.write` лише
  навколо виклику, тож інші тести не зачеплені.
