# План: #1666 — `bootstrap-worker.sh --check` не падає на `pgrep -c`

Знахідка звіту #1504: гілка `t1416-swarm-doctor` (PR #1437 злито) рухалася далі,
і коміт `c8c59c3f` «--check більше не бреше про dsh і не падає на pgrep»
**не потрапив у main**. У main досі живий перший дефект цього коміта.

## Причина

`pgrep -c` друкує «0» **і** виходить з 1, коли збігів немає. Старий рядок
`running=$(pgrep -fc … || echo 0)` додавав ДРУГИЙ нуль, і
`[ "${running:-0}" -eq 0 ]` друкував «[: 0\n0: мало бути використано ціле
значення»; перевірка «немає активних dsh» фактично не виконувалась (лише не
валила `--check`, бо помилка в умові `if`).

Друга частина того коміта (PATH до перевірок) у main уже покрита іншим
рішенням: `--check` підхоплює `~/swarm/env.sh` перед `command -v dsh`, тож із
коміта беремо лише pgrep-фікс.

## Рішення

```bash
running=$(pgrep -fc '[d]sh --profile headless' 2>/dev/null) || :
```
(і `${running:-0}` лишається) — той самий фікс, що в `c8c59c3f`.

Семантика не змінюється: dsh-процеси — норма під час задачі; рапортуємо факт.

## Тест

`scripts/tests/test_swarm_bootstrap_check.py`: `--check` у тимчасовому
`$HOME/$SWARM_ROOT` з фейковим `pgrep`, який друкує «0» і виходить з 1.
Вимоги: stderr без «мало бути використано ціле значення»; stdout містить
«немає активних dsh»; код виходу — сума справжніх FAIL-ів, не 2 від bash.
Фейкові `gh`/`env.sh`/credentials роблять тест герметичним (без мережі й
справжнього gh).

**Red/green доказ:** тест на старому рядку падає (`FAIL: 'немає активних dsh'
not found … dsh-процесів: 0\n0`), на виправленому — зелений.

## Перевірка

- `python3 -m unittest scripts/tests/test_swarm_bootstrap_check.py` → OK.
- `bash -n scripts/swarm/bootstrap-worker.sh` — чисто (pre-commit hook).
- CI: script unit tests.

## Межі

- Тест не запускає справжній `--check` на робочій машині (немає JDK 21/SDK у
  тимчасовому корені — тому очікувані FAIL-рядки, головне — відсутність
  bash-помилки і коректний рядок про dsh).
- Гілку `t1416-swarm-doctor` після мерджу може прибрати координатор: її
  pgrep-робота вже в main цим PR (решту коміта покриває main).
