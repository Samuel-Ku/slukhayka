# План: #1668 — `--check` не вмирає на `df`/`pipefail` при неіснуючому REPO_DIR

Знайдено під час огляду PR #1667 (#1666), існувало до нього.

## Симптом

`bash scripts/swarm/bootstrap-worker.sh --check` має друкувати по рядку на
складову й повертати `bad`, якщо хоч одна зламана. Але при **неіснуючому**
`$REPO_DIR` (клон ще не зроблено / `SWARM_ROOT` вказано на іншу теку) скрипт
умирає на рядку диска:

```bash
free_gb=$(df -BG --output=avail "$REPO_DIR" 2>/dev/null | tail -1 | tr -dc 0-9)
```

`df` на неіснуючому шляху виходить з 1, `set -o pipefail` робить це фатальним
для всього скрипта — решта перевірок (dsh, gh auth, ключ, клон) навіть не
друкується. Тест #1666 цього не бачив, бо створював `repo/.git`.

## Рішення

```bash
free_gb=$(df -BG --output=avail "$REPO_DIR" 2>/dev/null | tail -1 | tr -dc 0-9) || free_gb=""
```

Рядок диска лишається FAIL («диск (?G вільно)»), а `--check` іде далі.

## Тест

`scripts/tests/test_swarm_bootstrap_check.py` рефакторено на спільний
`_run_check`; додано `test_check_reports_all_lines_when_repo_dir_is_missing`:
`$REPO_DIR` **не** створюється; вимоги — порожній stderr, код 1, у stdout є
«диск (», «клон репозиторію» і «немає активних dsh», тобто перевірки ПІСЛЯ
диска справді виконались.

**Red/green:** зі старим `df`-рядком обидва тести падають (другий — на
відсутності «диск (» і «немає активних dsh» у stdout); з фіксом — OK.

## Перевірка

- `python3 -m unittest discover -s scripts/tests -p "test_swarm_bootstrap_check.py"` → 2 OK.
- `bash -n scripts/swarm/bootstrap-worker.sh` — чисто.
- CI: script unit tests (повний `discover -s scripts/tests`), решта Android-ног.

## Межі

- Це `--check` (діагностика), не установка: логіка bootstrap не змінена.
- `df` усе ще не єдине джерело правди про «диск вільний»: на неіснуючому
  шляху він назве FAIL — і це правильно, але сама перевірка лишається
  наближенням до `$REPO_DIR`.
