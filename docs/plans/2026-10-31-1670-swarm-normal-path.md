# План: #1670 — повернути normal-path покриття `--check` + пінити FAIL диска

Два не-блокуючі ніти незалежного огляду PR #1669 (#1668).

## 1. Нормальний шлях `$REPO_DIR існує` лишився без піна

Рефактор #1668 на спільний `_run_check` робив фікстуру **завжди** без
`$REPO_DIR` (щоб пінити падіння на `df`). Наслідок: шлях «клон існує» і
успішний рядок диска («[check] ok диск (…G вільно)») більше не виконує
жоден тест — а issue #1668 п.3 спирався саме на це.

Рішення: `_run_check(raw, *, create_repo: bool = True)`; `repo/.git`
створюється для pgrep-тесту (нормальний шлях), а тест відсутнього клона
викликає `create_repo=False`.

## 2. Тест пінив «рядок надруковано», а не «рядок FAIL»

Мутація `|| free_gb=100` виживала: у тесті відсутнього `$REPO_DIR` рядок
диска ставав `ok диск (100G вільно)`, а assert лише `assertIn("диск (")`.

Рішення: `assertIn("[check] FAIL диск (", proc.stdout)` у тесті з
неіснуючим `$REPO_DIR`; у нормальному — `assertNotIn("диск (?", …)`, тобто
«?»-рядок означає, що `df` не порахував.

## Перевірка

- `python3 -m unittest discover -s scripts/tests -p "test_swarm_bootstrap_check.py"` → 2 OK.
- Red/green (обидві мутації вбиті):
  * M1 `free_gb=100` → тест відсутнього клона падає на `FAIL диск (`;
  * M2 `create_repo=False` у pgrep-тесті → падає на відсутності
    `ok клон репозиторію`;
  * на вихідному коді — 2 OK.
- `test_fixture_environments.py` → 20 OK (ключі сканера `_run_check: gh|pgrep`
  не змінились); `bash -n` скрипта не потрібен — скрипт не змінюється.
