# План: #1680 — перевіряти PR-snapshot і під час довгого CI

Два колізійні випадки за 2026-10-30 (#1673→#1676/#1677, #1675→#1679/#1678):
резервування не завадило іншій сесії відкрити паралельний PR на той самий
тікет; #1677 став дублікатом #1676 після ~45 хв CI-стіни, #1678 — дублікатом
#1679 після ~10 хв прогону.

`docs/agents/work-coordination.md` уже вимагає перевірити відкриті PR **перед**
стартом (і дає `scripts/pr-snapshot.py`), але не каже перевіряти **під час**
довгого очікування CI.

## Рішення

Додано підрозділ «Під час довгого CI — перевіряй ще раз (#1680)» у
`docs/agents/work-coordination.md`:
- один read-only виклик (`scripts/pr-snapshot.py` або `gh pr list --search`);
- якщо з'явився паралельний PR — не мержити свій, повідомити координатора
  фактами, закрити як superseded/дублікат, прибрати свої копи;
- рішення, який PR лишається, — за координатором;
- ціна: секунди запиту проти циклу CI+огляду.

## Перевірка

- docs-only: CI класифікує зміни як документацію, Android/Room-ноги — skipping;
  решта гейтів (Workflow timing, doc_numbers, script tests) без змін.
- `python3 scripts/doc_numbers.py` локально — exit 0.

## Межі

- Це не змінює резервування й не додає механізму блокування паралельних PR:
  координатор усе одно може вести тікет своєю сесією; правило лише змушує нас
  помітити це ДО мерджу й не палити CI далі.
