# План: #1684 — scrub імен: ідемпотентність за один запуск, зміцнити тести меж

Follow-up огляду PR #1683 (знахідки 3–5, не блокери).

## 1. Ідемпотентність за один запуск

`StoredMetadataScrub.scrubOnce()` жене title-цикли ПЕРЕД name-циклом, а
`MetadataAssertions.normalizeTitle` для Soundbooks-обгортки прибирає хвіст
« - <author>», порівнюючи зі збереженим `author`. Якщо автор ще encoded
(«Наталія Дев&#x27;ятко»), порівняння не збігається, і хвіст лишається до
**наступного** запуску.

**Рішення:** name-цикл переміщено **перед** title-цикли. Тоді title-правило
вже бачить декодований автор і знімає хвіст у тому ж проході; другий запуск —
0 змін. Порядок зафіксовано коментарем і тестом.

## 2. Зміцнити тести меж (test gaps з огляду)

- `a clean name keeps its spaces and punctuation byte-for-byte` — ім'я з
  подвійним пробілом і trailing-пробілом лишається байт-ідентичним (мутація
  «trim/бренд-скраб імен» тепер ловиться);
- `only the encoded column changes - the clean neighbour stays byte-identical` —
  один рядок змінює лише `author`, інший лише `narrator`; сусідній чистий
  стовпець байт-ідентичний (мутація «писати обидва стовпці на будь-який хіт»
  ловиться);
- `an encoded author in a Soundbooks suffix is cleaned in the same run` —
  червоний без #1 (на старому порядку title лишається з хвостом).

## 3. Межа `decodeEntities`

`decodeEntities` одно-прохідний: вкладена сутність (`&amp;#x27;`) декодується
один шар за запуск. Для title це пре-існуюча межа з #964; розширення на імена
її не погіршує. Названо в KDoc `StoredMetadataScrub` (не нова гарантія — чесна
межа, а не тихе обіцяння).
