# План: #1697 — свідки для історії плеєра й модальність форми відгуку

Follow-up огляду PR #1696 (#1688): поведінка перевірена, але частина гілок без
свідків; вкладена форма відгуку не мала власного Escape/trap.

## Рішення

1. **Спільний trap фокуса:** `web/src/ui/focusTrap.ts` (витягнуто з
   `PlayerSheet`); `PlayerSheet` і `ListenerReviewFormSheet` використовують один
   код. Це delete-менше, ніж друга копія, і дає формі власний trap.
2. **Форма відгуку — власний модальний шар:** `sheetRef` + `keydown` на
   документі: `Escape` викликає `onDismiss` (не закриває плеєр за нею), `Tab`
   тримає фокус у формі. Плеєр має nested-guard (#1688), тож Escape з форми
   більше не вилітає у плеєр і не губить чернетку.
3. **Коментар `playerOverlayHistory.ts`:** правдивий: App — єдиний
   власник/споживач (push/pop навколо `playerOpen`); модуль існує, щоб App і
   тести overlay ділили ОДНЕ визначення маркера й guard, а не переписували
   літерал. Тести `playerOverlayModal.test.tsx` імпортують
   `PLAYER_OVERLAY_MARKER`/`isPlayerOverlayState` і більше не порівнюють
   літерал `{dshPlayerOverlay:true}`.
4. **Свідки історії (`playerOverlayModal.test.tsx`):**
   - **push-guard:** Esc-закрив → реальний `history.forward()` у витрачений
     маркер (книга лишається) → перевідкрити плеєр → ОДИН ✕ закриває
     (повторний push не плодить другий маркер);
   - **stale-прапорець:** 1200→600 в одній задачі — відкладений pop не
     самозакриває overlay;
   - **pane-закриття (перший тест файлу, чистий стек):** книга під pane
     повертається, наступний Back — один крок, маркера немає.
5. **Свідки форми:** unit (`bookReviews.test.tsx`): Escape → `onDismiss` рівно
   раз, `isSaving` ігнорує Escape, фокус ззовні повертається Tab-ом; реальна
   інтеграція (`playerFinishPrompt.test.tsx`): Escape у формі всередині
   PlayerSheet закриває ЛИШЕ форму — діалог плеєра лишається, а `onClose`
   плеєра НЕ викликається. Ключова деталь: подія шлеться на
   `document.activeElement` (як у браузері — target = сфокусований H2 форми),
   інакше nested-guard `isNestedDialogTarget` не бачить target-елемента і
   чесний свідок перетворюється на фальшивий (мутація «знешкодити guard» його
   не валить).

## Мутації (усі відкочені, свідки червоні)

- прибрати push-guard → W5 «перевідкриття закриває одним ✕» червоний;
- прибрати stale-гілку → W9 «відкладений pop» червоний;
- прибрати pane-pop ефект → pane-закриття червоне;
- прибрати форму Escape → Escape-тест червоний; прибрати `trapFocus` у формі
  → Tab-тест червоний; прибрати `if (!isSaving)` → тест «ігнорує Escape під
  час збереження» червоний; знешкодити nested-guard плеєра → інтеграційний
  тест червоний (Escape на `activeElement` + `expect(onClose).not.toHaveBeenCalled()`).
