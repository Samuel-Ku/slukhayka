# #1702 — R8/minify for release, with evidence

Lane: `.worktrees/r8-release`, branch `fix/1702-r8-release`, base `origin/main`
`8e1e9b6b`.

## Goal

Close the gap named in #1702 with evidence, not a blind one-line flip: the
release build declares `proguardFiles` but runs with `isMinifyEnabled = false`,
so the NewPipeExtractor/Rhino rules are dead and the shipped APK pays the size
and cold-start cost of unshrunk code.

## Steps

1. Audit the effective R8/keep configuration (r8-analyzer skill, Path B because
   AGP is 9.1.1 < 9.3; keep-radius report from a temporary minified variant),
   and inventory code that needs keeping: NewPipeExtractor/Rhino reflection,
   Room, Coil/OkHttp, Media3/Cast, Firebase/Crashlytics, Compose, WebView JS
   bridges, Moshi, Chaquopy/TDLib JNI.
2. Add a `minifiedDebug` verification build type (`isMinifyEnabled = true`,
   `isShrinkResources = true`, debug signing, `.debug` applicationId suffix) so
   R8 can be exercised and installed without the release key.
3. Build `minifiedDebug` on dragonborn through the documented remote run flow,
   install it on `192.168.2.143:40917`, fix keep-rule crashes.
4. Enable `isMinifyEnabled = true` + `isShrinkResources = true` on `release`
   (`isCrunchPngs = false` documented), measure APK size and cold start before
   and after, run the smoke list (launch, Listen, player, Search, 4read cookie
   path, widget).
5. Add a CI-visible guard (minified debug assemble in a workflow job) and/or a
   release-smoke runbook step, scoped to the R8 gap.
6. Commit, push, open a PR that names the head SHA and `Closes #1702` only if
   smoke is green. No merge, no release package touched.

## Out of scope

Release signing, release publishing, merging, other lanes, the signed
`com.slukhayka.audiobooks` package.

## Результати (2026-10-31)

Збірки — на `dragonborn`, дим — OnePlus 8 Pro (`192.168.2.143:40917`),
пакет `com.slukhayka.audiobooks.debug`. Усі розміри включають E5-модель
(~130 MB у `assets`), тому абсолютні числа більші за «~211 MB» з issue,
яке міряли без неї; дельта від R8 від цього не залежить.

| Артефакт | Розмір APK | dex-методів (defined) | Cold start, медіана 3 |
|---|---:|---:|---:|
| `assembleDebug` (unminified, debuggable) | 297,382,422 B | 383,463 | 2041 ms |
| `assembleMinifiedDebug` (R8, не debuggable) | 257,716,014 B | 88,340 | 367 ms |
| `assembleRelease` unminified, non-debuggable, debug-підпис¹ | 282,362,734 B | — | 466 ms |
| `assembleRelease` (R8, справжній release) | 257,732,390 B | 88,387 | не ставився |

¹ Тимчасова копія baseline-дерева: `applicationIdSuffix = ".debug"`,
debug-підпис, `isDebuggable = false`, `assembleRelease` без R8. Потрібна, щоб
відокремити ефект R8 від різниці debuggable→AOT.

- Debug-пара: **−39.7 MB (−13.3%)**, dex **−77%**, cold start **2041 → 367 ms**
  (але це верхня межа: debug ще й debuggable/JIT-only).
- Чесна пара без debuggable-різниці: **466 → 367 ms (−99 ms, −21.2%)**.
- Release: **282.36 → 257.73 MB (−24.63 MB, −8.7%)**; dex 27.06 → 7.51 MB,
  res 7.42 → 2.96 MB, `resources.arsc` 2.23 → 1.64 MB; native libs
  (147.3 MB) не змінилися.

## R8-аудит

- AGP 9.1.1 < 9.3, тому `analyze*R8Config` (Path A) недоступний; аудит —
  з effective `configuration.txt` (1,735 рядків, 186 keep-правил) і
  `mapping.txt`/`seeds.txt`/`usage.txt` мініфікованої збірки.
- `android.enableR8.fullMode` не вимкнений (full mode — дефолт AGP 9);
  optimized resource shrinking увімкнений дефолтом AGP 9.
- Власні правила: Rhino (490 класів), NewPipeExtractor (480), TDLib (3,639).
  Перші два — рефлексія/JS-рушій, третій — AAR без consumer-правил
  (`RegisterNatives` + читання полів `TdApi` за іменами).
- Room, Coil/OkHttp, Media3/Cast, Firebase/Crashlytics, Compose, Glance,
  Chaquopy покриті consumer-правилами бібліотек; WebView JS-мостів у застосунку
  немає (`addJavascriptInterface` заборонений контрактом).
- `META-INF/services/javax.script.ScriptEngineFactory` — нешкідливий warning:
  `javax.script` немає на Android, Rhino-класи збережені.

## Дим

- Launch + Listen: полиця «Продовжити слухати» і «Нещодавно додані» рендеряться.
- Плеєр: «Ім'я вітру», розділ 06, `dumpsys media_session` →
  `state=PLAYING(3)`, позиція росте.
- Пошук: «Огляд» → `Rothfuss` → результати/чесний empty state.
- NewPipe: «Надіслати посилання» → YouTube URL → `NewPipeMetadata` дійшов до
  `YoutubeStreamExtractor` і віддав `ContentNotAvailableException`; жодного
  `NoClassDefFoundError`/`ClassNotFoundException`. Rhino не дійшов до
  deobfuscation, бо відео впало на playability check.
- 4read: на пристрої немає жодного 4read-видання (перевірено Room-дампом
  `sources`), а hydration 4read вимкнена як scam-джерело (ADR-0037/0041).
  Пункт зафіксований як not applicable у рунбуку, не як успіх.
- Віджет: `AudiobookGlanceWidgetReceiver` зареєстрований для `.debug`;
  примірника на робочому екрані не було, тому перевірена лише реєстрація.
- У crash-буфері немає падінь застосунку; `FATAL EXCEPTION` у логах належать
  `uiautomator`-шеллу, не `com.slukhayka.audiobooks.debug`.
- Release-пакет `com.slukhayka.audiobooks` не оновлювався (`lastUpdateTime`
  2026-10-29 15:59:26), `stay_on_while_plugged_in=15` збережено.

## Що лишається

- 4read-дим — на пристрої з уже імпортованим 4read-виданням; рунбук описує
  цю умову й забороняє вигадувати успіх.
- Rhino deobfuscation не прогнано end-to-end: потрібне доступне YouTube-відео,
  яке проходить playability check (на цьому пристрої/мережі — ні).
- Віджет — перевірити вручну, якщо він стоїть на робочому екрані.
