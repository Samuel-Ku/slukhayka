# Смуга edge-insets: #1711 + #1712

База: `origin/main` `bb9ddb8d`. Гілка: `fix/1711-1712-edge-insets`.
Власник: `dsh-web-edge-insets`, резервування `edge-to-edge`.

Обидві задачі — один edge-to-edge шар: нижній системний inset на EXPANDED і
IME. Одна PR, без редизайну.

## #1711 — загублений `navigationBars` inset на EXPANDED

- `MainActivity.AudiobookApp`: `bottomBar` емітить `Column` лише тоді, коли
  йому є що малювати — COMPACT (нижня навігація) або `bottomMiniPlayer`
  (смуга 600–839 dp). На EXPANDED без міні-плеєра лямбда не емітить жодного
  layout-вузла, тож M3 Scaffold бачить порожній список `bottomBarPlaceables`
  і застосовує `contentWindowInsets.bottom` до `innerPadding`.
- Міні-плеєр у провідній колонці (`AdaptiveNavigationLayout`) стоїть поза
  контентним Box-ом, який платить inset, тому отримує власний
  `navigationBarsPadding()`; рейка лишається на всю висоту.
- Міні-плеєр у `bottomBar` на 600–839 dp — остання лінія бару (рейка вже
  замінила `AppBottomBar`), тому `navigationBarsPadding()` отримує і він.
- Після `.padding(innerPadding)` хостовий Box додає
  `consumeWindowInsets(innerPadding)`: вкладені `Scaffold`-и
  (`IndexScreenScaffold`, `SettingsDestinationScaffold`) і `PlayerTopBar` не
  додають статус-бар/навбар удруге.

## #1712 — IME не підключений до edge-to-edge

- `AndroidManifest.xml`: `android:windowSoftInputMode="adjustResize"` на
  `MainActivity`.
- Один `imePadding()` на контентному Box-і хоста (після `padding(innerPadding)`
  і `consumeWindowInsets(innerPadding)`), а не на предку, чиї
  `contentWindowInsets` уже містять IME.
- `BookFeedback.kt` лишається як є: його `imePadding` у M3 sheet — нешкідливий
  no-op, не дублює хост.

## Межа

`WindowInsets.isImeVisible` на API 24–29 лишається ненадійним (платформне
обмеження; ADR-0058). `adjustResize` + `imePadding` дають коректну поведінку на
API 30+, а на 24–29 Back-політика ADR-0058 не стає гіршою за поточну. Це
записано в PR, а не приховано.

## Верифікація

- `WidePlayerPaneTest` (реальний корінь `AudiobookApp` на 840 dp): ін'єкція
  статус-бара 28 dp, 3-button навбара 48 dp та IME 300 dp у вікно тесту.
  - останній контент і міні-плеєр закінчуються над навбаром;
  - шапка панелі плеєра не зсунута на статус-бар удруге;
  - контент піднімається над клавіатурою.
- `scripts/test-changed.sh` для змінених шляхів; повний набір — CI.
- Goldens: геометрія на реальному пристрої не міняється, Robolectric-знімки
  мають нульові insets; очікування — жодного перезапису PNG. Якщо
  `scripts/goldens.sh verify` скаже інакше — перезаписати й покласти PNG в PR.
