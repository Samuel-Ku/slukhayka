# Прототип: редизайн Медіатеки (2026-09-15)

Одноразовий прототип, який відповідав на одне питання: **як має виглядати екран
Медіатеки?** Він не є продуктом і не має потрапляти в main як код — тут лежить
тільки те, що варто зберегти як первинне джерело рішення.

Спека, за якою зрештою зроблено редизайн:
`docs/specs/2026-09-15-media-library-redesign.md`. Реалізація — у
`LibraryScreen`, `LibraryFilterSheet`, `BookRow` (opt-in слоти) і
`ui/library/LibraryGridEntries.kt`.

## Що тут

| Файл | Що це |
|---|---|
| `variants-side-by-side.png` | Усі три варіанти поруч, очима за один погляд |
| `variant-a-continue.png` | **A «Продовжити»** — hero-картка, чипси в один рядок, однотапний play у рядку |
| `variant-b-shelves.png` | **B «Полиці»** — жодного чипса на екрані, бібліотека як полиці обкладинок |
| `variant-c-queue.png` | **C «Черга»** — щільний таймлайн-список без обкладинок і з сегментованим фільтром |
| `generator/*.kt.txt` | Той самий одноразовий Roborazzi-тест, яким ці кадри відрендерено |

Кадри зроблено реальними компонентами дизайн-системи (`AppTabHeader`,
`BookRow`, `MetadataChip`, `BookCoverImage`) на Pixel 8, темна тема, ті самі девʼять
книг-фікстур у кожному варіанті — щоб порівнювати можна було чесно.

## Що перемогло і чому

Переміг не жоден із трьох, а гібрид, і саме він реалізований:

- **основа — A**: hero «Продовжити» плюс один рядок статус-чипсів (замість
  трьох рядів) плюс книги, згруповані за станом;
- **з B — полиця «Нові»**: те, що не почато, вибирають очима, а не рядками;
- **з C — щільний режим**: коли ввімкнено статус-фільтр або пошук, екран стає
  щільним списком без hero, обкладинок і секційного хрому.

Три речі з прев'ю не дожили до релізу, і це варто знати, читаючи кадри:

1. **Кнопка play у рядку** (видно в A) прибрана після перегляду на пристрої:
   вісім однакових бурштинових дисків перетягували акцент з hero-CTA.
2. **Чипси лишились прикріпленими** під шапкою, а не скролились разом зі
   списком, як на кадрах A: так фільтр завжди під рукою.
3. **Полиця «Нові»** малюється наявною сітковою карткою, а не окремим
   саморобним тайлом.

## Як перегенерувати (за потреби)

Файл `generator/*.kt.txt` — це той самий тест у тестовому сорс-сеті. Поверніть
його як `PrototypeLibraryRedesignSnapshotTest.kt` у
`app/src/test/java/com/slukhayka/audiobooks/ui/snapshots/` і виконайте:

```
./gradlew testDebugUnitTest --tests "*PrototypeLibraryRedesign*" \
  -Proborazzi.test.record=true
```

Кадри зʼявляться в `app/build/prototype-preview/`.
