# Рецепт: реле-прототип на Cloudflare Workers

spec-38 T6 (#258). Реле — це **не дефолт** і не анонімність за замовчуванням:
це спосіб уже сьогодні провалідувати майбутній платний рівень крізь звичайну
маршрутну машинерію застосунку. Джерело бачить адресу реле, а не вашу; натомість
**оператор реле бачить усі URL, які застосунок fetching'е** — саморозгортання
означає «довіряєш собі», стороннє реле означає «довіряєш його оператору
повністю».

## ⚠️ Чесне попередження про ToS Cloudflare

Cloudflare **Self-Serve Subscription Agreement** (та історичний ToS §2.8)
обмежує сервінг непагінованого/нестандартного контенту й проксіювання через
Workers. Воркер, який за дизайн-ідеєю пересилає довільні запити до сторонніх
сайтів (реле), може порушувати ці умови — аж до відключення воркера чи акаунта.
Цей рецепт — **прототип для валідації**, не схвалення постійної експлуатації.
Для сталого використання дивіться Orbot/Tor (`orbot.md`) або власний VPS-варіант.

## Крок 1. Створюємо воркер

```bash
npm create cloudflare@latest slukhayka-relay
cd slukhayka-relay
```

## Крок 2. Код реле (`src/index.ts`)

Єдине правило протоколу: застосунок викликає `<base>?url=<encoded target>`,
воркер перевіряє ціль і повертає відповідь джерела як є (статуси — прозоро,
щоб чесна відмова маршруту в застосунку працювала без спеціальних гілок).

```typescript
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const secret = env.RELAY_SECRET; // з wrangler secret put RELAY_SECRET
    if (secret && request.headers.get("X-Relay-Key") !== secret) {
      return new Response("forbidden", { status: 403 });
    }
    const target = new URL(request.url).searchParams.get("url");
    if (!target || !/^https?:\/\//i.test(target)) {
      return new Response("bad url", { status: 400 });
    }
    // Дозволяємо лише домени книжкових джерел — відкритий проксі ніхто не платить.
    const host = new URL(target).host;
    if (!/(^|\.)sluhay\.com$|(^|\.)audiobookmp3\.(com|net)$|(^|\.)4read\.org$/.test(host)) {
      return new Response("host not allowed", { status: 403 });
    }
    try {
      return await fetch(target, { redirect: "follow" });
    } catch (e) {
      return new Response("upstream failed", { status: 502 });
    }
  },
};
```

## Крок 3. Деплой

```bash
npx wrangler secret put RELAY_SECRET   # опційно, але для публічного домену — так
npx wrangler deploy
```

Запишіть адресу виду `https://slukhayka-relay.<ваш-акаунт>.workers.dev`.

## Крок 4. Локальна перевірка (опційно)

```bash
npx wrangler dev        # слухає http://127.0.0.1:8787
```

Форма `http://127.0.0.1:8787` у налаштуваннях маршруту теж приймається — саме
для цього випадку (двері модуля приймають `http://`-бази, див. `NetworkPrivacy.parseRelayBase`).

## Крок 5. Увімкнення в застосунку

«Медіатека → ⋮ → Приватність мережі → Реле (прототип Workers)», вставте адресу,
«Застосувати». Некоректна адреса (без схеми, з query/фрагментом/credentials)
відхиляється з поясненням; нічого не зберігається наполовину.

## Що перевіряти (валідація рівня)

1. Каталог завантажується крізь реле (джерело в лозі воркера бачить запити).
2. Обкладинки їдуть тим самим маршрутом (спільний клієнт транспорту).
3. Недоступне реле → помилка списку, а не мовчазний прямий обхід.
4. WebView-сесії джерел чесно відмовляються під реле (переписування URL —
   транспортний шов, webkit-контролер його не має) — це задокументована
   межа прототипу, не баг.
