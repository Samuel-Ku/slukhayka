Статус: триває перевірка об’єднаного кандидата. Тег і GitHub Release ще
не створені. Усі завершені блоки з гілок зведено: відтворення/скачування,
люди, діагностика, мови, каталог, рекомендації та SoundBooks. Детальний
перелік і рішення щодо старих гілок — в
[аудиті інтеграції](../audits/2026-09-05-release-integration.md).

Спільна схема Room — 28. Перевірено оновлення з release26, people25,
people27 і popularity27: Room валідовує схему, рядки закладок і сигналів
популярності зберігаються. Старі варіанти 27 не можна просто підміняти
один одним.

Попередні фізичні перевірки й підтвердження чутного звуку стосуються
кандидата cdf458af, APK SHA-256
`d665ee64be203b11a058de1a6c0a1ce00f9e096a54a8d06ce69d1bd714962da6`.
Вони не є перевіркою нової інтеграції. Історія сценаріїв та обмежень —
в [аудиті відтворення](../audits/2026-09-05-playback-followup.md).

Повна доступність, CI та підписаний APK мають стосуватися точного нового
коміту. Перед релізом потрібна актуальна фізична перевірка. Приватні
маршрути й повернення мережі ще не підтверджено фізичним тестом.
Відновлення трьох втрачених старою збіркою карток на попередньому Xiaomi
також не підтверджене; поточний захист від такого об’єднання включено.

## Після push і зеленого CI

На основному комп’ютері спочатку збережіть власні незакомічені зміни.
Далі в чистому checkout цього репозиторію:

```sh
git fetch origin --tags
git switch --track origin/release/v1.3.9
git status --short
git log -1 --oneline
```

Якщо локальна `release/v1.3.9` вже існує, перейдіть на неї й оновіть через
`git pull --ff-only`. Не зливайте сюди `main`.

У GitHub Actions відкрийте `CI` для точного коміту гілки. Мають пройти всі
шість тестових частин, покриття, рекомендаційна оцінка й signed-smoke build.
Завантажте артефакт `slukhayka-v1.3.9-signed-smoke`, перевірте SHA-256 та
підпис. Ключ має бути тим самим, що у встановленої release-версії; не
генеруйте новий keystore.

Перевірений відбиток сертифіката опублікованого APK 1.3.8 (SHA-256):
`08587854ce382fb53dca906edf3eadca497506b1f9166cd8b6483b8f47d2783a`.
Контрольна сума самого завантаженого 1.3.8 збіглася з вкладенням релізу;
`apksigner verify --print-certs` підтвердив підпис. Для кандидата виконайте
цю саму команду Android SDK Build Tools й порівняйте SHA-256 сертифіката. Секрети підпису вже налаштовані в GitHub.

Кандидат слід перевірити як оновлення наявної release-версії без видалення.
Debug-перевірка використовує окремий пакет і сама по собі не підтверджує
оновлення даних release-пакета. Результати сценаріїв:
[аудит відтворення](../audits/2026-09-05-playback-followup.md).

## Публікація після завершення перевірок

Ці команди ще не виконувалися. Push тега автоматично створить публічний
GitHub Release, тому виконуйте їх лише для перевіреного коміту:

```sh
git tag -a v1.3.9 -m 'Слухайка 1.3.9'
git push origin v1.3.9
```

Workflow `Release` збере підписаний APK, додасть контрольну суму й текст із
`docs/releases/v1.3.9.md`. Перевірте вкладення та встановлення оновлення.
Якщо перевірка кандидата не пройшла, не створюйте тег: виправлення мають
отримати новий коміт і власний зелений прогін CI.
