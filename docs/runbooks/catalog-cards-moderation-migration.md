# Runbook: міграція наявних `catalog_cards` у чергу модерації (#840)

Одноразова операція. Виконується ботом/куратором із **Admin SDK** (правила його
не обмежують), поза цим репозиторієм. Тут описано, **як запускати, як
перевірити, як відкотити**.

## Навіщо

До модерації застосунок писав картки в `catalog_cards` напряму. Після появи
черги кожна наявна картка має пройти повторний розгляд куратора — але **не
зникаючи з каталогу**: інакше спільна база спорожніє на час перегляду.

## Правила відображення (єдиний контракт)

Чисте відображення картки в кандидата живе в репозиторії:
`CatalogCardModerationMigration.candidateFromCard(card)`.

- **ключ** = `sha256(canonicalUrl)`, де канонічний URL дає
  `SubmissionUrlCanonicalizer` (застосунок): `youtu.be/<id>` і
  `youtube.com/watch?v=<id>` — один документ;
- `state` = `pending`; `decidedAt`/`decidedBy` не пишуться;
- `playedAt` = **0**: у картки не було вердикту програвання, і вдавати його не
  можна;
- `createdAt` = `observedAt` картки (не час запуску) — саме тому повторний
  прогін дає **той самий** документ;
- `submitterHash` = `sha256("catalog-migration:" + canonicalUrl)` — синтетична
  позначка, бо слухача в цих карток немає;
- картка без `title` або `sourceUrl` **пропускається**, нічого не вигадується.

Форма документа — та сама, що в контракті з ботом: див. фікстуру
`app/src/test/resources/fixtures/submission-candidate.json` і тест
`SubmissionModerationContractTest`.

## Як запускати

1. Прочитати всі документи `catalog_cards` (пагіновано).
2. Для кожного застосувати правила вище й записати в
   `pending_submissions/{sha256(canonicalUrl)}` через `set` (не `add`).
3. `catalog_cards` **не чіпати** — картки лишаються читабельними, доки куратор
   не ухвалить рішення.
4. Нічого не видаляти й не переписувати в `catalog_cards` до рішень.

## Як перевірити

1. **Кількість до/після:** `catalog_cards` — без змін; `pending_submissions` —
   рівно стільки, скільки карток пройшло правило (`isMigratable`).
2. **Форма:** взяти будь-який створений документ і порівняти набір полів із
   фікстурою `submission-candidate.json` (набір мусить збігатися повністю).
3. **Ключ:** `sha256(canonicalUrl)` документа мусить дорівнювати його id.
4. **Ідемпотентність:** повторити прогін — кількість і вміст не змінюються
   (жодних дублів, `createdAt` той самий).

## Як відкотити

Операція **адитивна**: вона не змінює й не видаляє жодної картки. Відкат —
видалити створені документи `pending_submissions`, у яких `submitterHash`
дорівнює `sha256("catalog-migration:" + canonicalUrl)`. Після цього стан
спільної бази — точно як до запуску.

## Що робить куратор після

Рішення для мігрованих карток діє **так само**, як для нових: `approved` →
бот пише/лишає картку в `catalog_cards`; `rejected` → стан `rejected` плюс
запис у `rejected_submissions`. Деталі контракту — у #839.
