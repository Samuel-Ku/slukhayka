# Оновлення компонентів перед релізом

Деякі залежності ламаються самі, без нашого коду: YouTube періодично
змінює анти-бот перевірки, і тоді анонімне видобування (рушій NewPipe)
перестає працювати, а кожне вставлене YouTube-посилання — заводитись.
Цей рунбук описує, як оновлення приходять самі й як перед тегом
переконатися, що рушій живий.

Ключова ідея: не оновлювати все напередодні релізу (великий диф без часу
на відстій), а тримати безперервний потік дрібних PR і раннє попередження.

## Що оновлюється само

`renovate.json` у корені керує Renovate. Раз на тиждень (`before 6am on
monday`, Europe/Kyiv) він відкриває PR на:

- звичайні залежності з `gradle/libs.versions.toml`; AndroidX, Google і
  Firebase згруповані в один PR, щоб диф лишався читабельним;
- `NewPipeExtractor` — кастомним regex-менеджером: версії беруться з
  GitHub-релізів `TeamNewPipe/NewPipeExtractor` (теги `v0.26.x`), бо
  артефакт живе на JitPack, а не в Maven Central. Вбудований Maven-lookup
  для цього пакета вимкнено, щоб не було другого PR.

Одноразова дія: поставити застосунок [Mend
Renovate](https://github.com/apps/renovate) на репозиторій і дати йому
доступ до `Samuel-Ku/slukhayka`. Без цього файл конфігурації лежить
незадіяним. Dependency Dashboard з'явиться окремою issue.

`rangeStrategy` — `pin`: версії фіксуються точні, як у репозиторії вже
заведено.

## Живий YouTube-канарок

`YouTubeContractCanaryTest` — це не перевірка логіки, а проба живого
контракту: він бере закріплену версію рушія, тягне реальне публічне відео й
перевіряє, що назва і тривалість читаються, що player response несе прямий
аудіострім, і що підписаний URL віддає 2xx. Саме 403 на цьому URL — те, як
зазвичай проявляється злам poToken/підписів.

Тест навмисно Android-вільний (звичайний `HttpURLConnection`), тож біжить
як pure-JVM. Гейт — `-Dyoutube.canary`, тому PR CI його лише скіпає.

Workflow `youtube-contract.yml` запускає його щодня о 06:31 UTC і вручну.
Вручну, за потреби зі своїм відео:

```
./gradlew :app:testDebugUnitTest --tests "*YouTubeContractCanaryTest" \
  -Dyoutube.canary=1 -Dyoutube.canary.video=<watch-url>
```

Червоний канарок — час оновити рушій (Renovate уже відкрив PR на нову
версію).

## Гейт перед тегом

`scripts/pre-release.sh` — єдина точка входу; той самий скрипт кличе
workflow `release-readiness.yml` на кожен push у `release/**` і вручну.

```
./scripts/pre-release.sh
```

Він звітує про три речі:

| Перевірка | Вага |
| --- | --- |
| відкриті PR з лейблом `dependencies` | WARN — вирішує людина |
| закріплені вендорені компоненти (`vendor/*.lock`) | WARN |
| живий YouTube-канарок | FAIL — тег не ставимо |

## Вендорені компоненти

BotGuard-файл `po_token.html` (коли його буде портовано з NewPipe) — не
залежність, а скопійований файл: пакетний менеджер його не оновить. Кожен
такий файл описує `vendor/<name>.lock`:

| Поле | Значення |
| --- | --- |
| `repo` | upstream `owner/name` |
| `path` | шлях файлу в upstream |
| `ref` | гілка upstream, з якої тягнемо (`main`) |
| `dest` | куди класти файл у нас |
| `commit` | закріплений коміт upstream |
| `sha256` | хеш вмісту цього коміту |

Workflow `vendor-sync.yml` щотижня (і вручну) проганяє
`scripts/vendor-sync.py`: якщо upstream-коміт змінився, він перезаписує
файл, оновлює lock і відкриває PR. Доки жодного lock немає, скрипт просто
каже, що вендорених компонентів не закріплено.
