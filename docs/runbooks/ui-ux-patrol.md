# Нічний UI/UX-патруль

`scripts/ui-ux-patrol.py` — агент, який щоночі проходить інтерфейс і логіку
екранів застосунку та web-клієнта, знаходить дефекти й місця для покращення та
оформлює **готові до роботи тікети** (`ready-for-agent`). Він не виправляє код:
реалізацію беруть смуги сварму, а патруль лише ставить задачу так, щоб її можна
було взяти без питань.

Межа названа прямо: це **статичний аудит коду й документації**, а не QA на
пристрої. Скріншоти, Talkback на телефоні, жести й анімації тут не
перевіряються — для цього є `docs/accessibility/talkback-release-checklist.md`,
`docs/agents/qa-*-device-gate.md` і ручні проходи. Патруль шукає те, що видно з
коду: розбіжність із власними ADR, дублікати компонентів, touch-target,
відсутні стани, захардкоджені рядки, неузгоджений стан, розбіжність
web/Android.

## Навіщо локальний таймер, а не GitHub Actions

Агентові потрібні справжній репозиторій, `gh` і модель. У GitHub Actions це
означало б установлювати dsh і тримати ключ моделі в CI на кожен нічний прогін,
а ще — щоразу чекати на холодний старт. На hub уже є `dsh`, ключ моделі й
`gh`, тож таймер `systemd --user` виконує ту саму роботу без нових секретів у
репозиторії. Це той самий підхід, що в `branch-hygiene`
(`scripts/systemd/branch-hygiene.*`), і та сама межа: **машина мусить бути
ввімкнена**, інакше прогін доганяється наступного разу (`Persistent=true`).

## Установка (один раз на hub)

```sh
# з будь-якої гілки — скрипт бере свіжий origin/main сам
python3 scripts/ui-ux-patrol.py install --repo ~/Projects/slukhayka
```

Що робить `install`:

1. перевіряє `dsh`, `gh`, `git` і автентифікацію `gh`;
2. розгортає профіль `dsh --profile headless`, якщо його немає, і пише
   `~/.dsh/profiles/headless/cordis.patch.yml` із маршрутом
   `opencode-go`/`deepseek-v4.1-flash` (той самий, що в `scripts/swarm/bootstrap-worker.sh`);
3. робить димовий прогін `Reply with exactly: READY` — без робочого ключа
   моделі таймер не має сенсу;
4. створює мітку `ui-ux-patrol`;
5. пише `~/.config/slukhayka/ui-ux-patrol.env` (0600) з `PATH` і `GH_TOKEN`
   (щоб `gh` працював у таймері без розблокованого keyring). `--no-gh-token`
   лишає файл без токена — тоді токен треба додати вручну;
6. ставить `~/.config/systemd/user/ui-ux-patrol.{service,timer}` і вмикає
   таймер. `--no-enable` лише ставить файли.

Перевірка після установки:

```sh
systemctl --user list-timers ui-ux-patrol.timer
python3 scripts/ui-ux-patrol.py status --repo ~/Projects/slukhayka
```

`status` показує: чи є профіль, чи бачить `gh`, коли наступний запуск, останні
рядки логу й відкриті тікети патруля.

## Ручні прогони

```sh
# сухий прогін: агент шукає й описує, але НІЧОГО не створює
python3 scripts/ui-ux-patrol.py dry-run --repo ~/Projects/slukhayka

# бойовий прогін поза розкладом
python3 scripts/ui-ux-patrol.py run --repo ~/Projects/slukhayka

# довший бюджет, ніж типовий
python3 scripts/ui-ux-patrol.py run --repo ~/Projects/slukhayka --timeout-min 90
```

`run` робить `flock`: другий прогін паралельно не стартує (код 3). Логи й
промпти лежать у `<git-common-dir>/ui-ux-patrol/logs/` (тобто
`~/Projects/slukhayka/.git/ui-ux-patrol/logs/`): `YYYY-MM-DD.log` і
`prompt-YYYY-MM-DD.md` — промпт зберігається навмисно, щоб було видно, що саме
агент просив у ту ніч. Логи старші за 14 днів прибираються.

## Що відбувається за прогін

1. `git fetch` по HTTPS у `refs/remotes/origin/main` (локальний SSH-конфіг
   машини не використовується — він тут ламається, див. `branch-hygiene`);
2. виділена копія `.worktrees/ui-ux-patrol` скидається на `origin/main`;
3. збираються наявні тікети патруля (маркери дедупу) і звіт-issue;
4. тема дня обирається ротацією за порядковим номером дати — сім тем, кожна
   приблизно раз на тиждень: «Слухати», Медіатека, сторінка книги/плеєр,
   Огляд/каталог, налаштування/доступність, соціальний шар, web;
5. агент `dsh --profile headless` працює в копії до 60 хвилин (таймаут ріже
   групу процесів, а не лише PID);
6. після прогону раннер перевіряє контракт: копія патруля чиста, головне дерево
   hub не змінилося (авторство змін не встановлюється — порушення лише
   називається), нових тікетів не більше 5, у кожного є маркер, мітки
   `ready-for-agent` + `ui-ux-patrol`, розділ «Доказ» і хоча б один
   `file:line`; ключі не повторюють **відкриті**. Номери створених тікетів і
   звіту агент називає в контрактному рядку (`created=#12,#13 report=#5`), і
   раннер перевіряє **саме їх** — чужі issues, створені в ту саму годину, не
   рахуються тікетами патруля. У `dry-run` вимагається, щоб агент не
   задекларував жодного тікета й не лишив незадекларованих issues **з
   маркером** патруля. Названа межа: issue без маркера й без декларації не
   атрибутується нікому (це може бути чужа робота в ту саму годину), тому
   такий випадок не валить прогін — він видимий у загальному трекері, а не в
   лозі патруля.

Порушення контракту валить прогін (код 2) і лягає в лог. Тікети при цьому не
видаляються й не виправляються автоматично: нічна робота не має права
прибирати те, що вже опубліковано.

## Що агент перевіряє

Тема дня — лише точка входу; універсальні інваріанти перевіряються щоночі:

- ADR-0018/0033 — один словник компонентів, канонічні картки/чипси/заголовки,
  відсутність паралельних реалізацій і п'яти стилів заголовків;
- ADR-0044 — підлога touch-target 24 dp, 48 dp для транспорту й навігації;
- доступність — `contentDescription`, семантика, фокус, контраст,
  `docs/accessibility/talkback-release-checklist.md`;
- стани екранів — завантаження / порожньо / помилка в кожного, хто читає дані;
- логіка — неузгоджений стан (як у #1413), застарілий стан після навігації,
  `LaunchedEffect` без ключа, проковтнуті помилки, зашиті ліміти;
- i18n — захардкоджені рядки замість `strings.xml`, неповні `values-en/pl`,
  ріст `app/lint-baseline.xml`;
- ADR-0034 — паритет web/Android; для web — `ADR-0051`, `ADR-0059`.

Перед тікетом агент зобов'язаний перевірити дубль (`gh issue list --search`,
маркери патруля) і «вже вирішено» (`docs/audits/`, `docs/specs/`, ADR
`Rejected alternatives`). Знахідка без `file:line` не існує; кандидат без
доказів іде в звіт, а не в тікет.

## Звіт-issue

Один відкритий issue з маркером `<!-- ui-ux-patrol-report -->` (заголовок
`UI/UX-патруль — нічний звіт`) переписується щоночі, а не створюється заново:
правка issue не будить підписників. У звіті — тема, що перевірено, створені
тікети, кандидати без тікета й залишкові питання. Це місце, де видно роботу,
яку патруль **не** перетворив на тікет.

## Стеля й дедуп

- не більше **5** нових тікетів за прогін (`MAX_TICKETS` у скрипті);
- кожен тікет несе `<!-- ui-ux-patrol: key=<тема>/<slug> -->`; ключі з
  відкритих тікетів передаються агенту в промпті;
- нуль тікетів — нормальний результат, якщо знахідок немає: краще чесний звіт,
  ніж шум у трекері;
- закритий тікет із тим самим ключем **не блокує** новий: регресія після фіксу —
  законна робота. У промпті відкриті й закриті ключі розділені, а валідація
  звіряє лише відкриті; повторне відкриття регресії має бути назване в тілі як
  регресія, а не як нова знахідка.

## Вимкнення й розбір

```sh
systemctl --user disable --now ui-ux-patrol.timer
systemctl --user status ui-ux-patrol.service
journalctl --user -u ui-ux-patrol.service -n 200
```

Типові відмови:

| Симптом | Причина й що робити |
|---|---|
| `gh: не автентифіковано` | у `~/.config/slukhayka/ui-ux-patrol.env` немає `GH_TOKEN`; додай і `systemctl --user restart ui-ux-patrol.timer` |
| `dsh не знайдено в PATH` | у env-файлі `PATH` без теки dsh (mise/npm); перезапусти `install` |
| димовий прогін не дав `READY` | ключ моделі в `~/.dsh/.credentials.yaml` протермінований |
| `не прочитав наявні тікети` | мережа/GitHub API; прогін усе одно йде, але дедуп сліпий — перевір звіт |
| прогін падає з кодом 2 і «ПОРУШЕННЯ контракту» | агент вийшов за межі (створив зайве, змінив файли, тікет без доказу); деталі в лозі |
| таймер не запускається | `systemctl --user list-timers`: можливо, ввімкнено без `daemon-reload`, або машина спала й `Persistent=true` доганяє пізніше |

## Межі, названі прямо

- **Не QA на пристрої.** Патруль не запускає емулятор, не знімає скріншоти, не
  перевіряє жести, анімації, Talkback уголос і реальні дані джерел.
- **Не арбітр якості.** `ready-for-agent` ставить агент; помилковий тікет
  закриває людина або координатор, як і будь-який інший. Патруль не має права
  закривати чужі тікети чи ставити `wontfix`.
- **Не замінює ручні аудити.** `docs/audits/*` лишаються джерелом глибоких
  рішень; патруль читає їх, щоб не перевідкривати закрите.
- **Не безкоштовний.** Один прогін — це один запуск моделі на 30–60 хвилин
  роботи; витрати видно в лозі провайдера. Якщо потрібно дешевше — зменш
  `--timeout-min` або вимкни таймер на час.
- **Не гарантія повноти.** Це евристичний прохід: він знаходить те, що видно з
  коду й документації, і може пропустити дефект, який видно лише на пристрої.
