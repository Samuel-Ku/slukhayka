## Проблема (діагноз, підтверджено фактами)

«Я не бачу різниці після такої кількості тікетів UI/UX» — і це точно.

- Конвеєр рішення-спочатку (MAP #22: «Decisions, not deliverables»): ~25
  wayfinder-тікетів, 4 UX-ревізії, spec-27 (#184), ADR-0014..0016, ревізія
  екранів, баг-аудит, product-surfaces — і **нуль зміни коду UI** за 2026-08-16.
- Видимі редизайни (#38 плеєр, #39 бібліотека, #40 сторінка книги) вийшли
  08-08…08-14, але одразу після них пішов data-спринт (universe, editions,
  collections, feeds, widget) — 159 комітів, ~0 видимих для користувача.
- Реальні видимі дефекти лишаються незакритими: BUG-001 (втрата даних через
  «Очистити»), BUG-002 (дубль-картка з сирим SEO-заголовком), BUG-003 (емодзі-
  заголовки фідів), BUG-006 (плюралі), BUG-007 (дубль-чіпи жанрів).
- Дзеркало MAP у репо — копалина від 07-08 (#38/#39/#40 закриті, #34/#43
  відвантажені, #41 відкритий).

## Інтерв'ю (питання → рекомендована відповідь → закріплено)

**Q1. Що насправді сталося?**
→ Decision-vs-delivery gap: тікети закривалися «рішенням», а не «видимою
дельтою»; видимі редизайни потонули в невидимому data-спринті; дефекти
заплановані, але не виправлені. Сприйняття користувача точне. **Locked.**

**Q2. Що таке «видима різниця» для Слухайки?**
→ (b) виправлення дефектів аудиту — найшвидший видимий стрибок якості; потім
(c) видимі фічі фронтиру; (a) ребренд/новий дизайн — не потрібен (стадія 1
вже відвантажена). **Locked.**

**Q3. Порядок доставки?**
→ 1) Виконати spec-27 (#184): P0 → P1 → P2, кожен пункт з тестами і
phone-verify. 2) Верифікаційні тікети #185 (live-лічильники) / #186 (серія
«Епоха божевілля»). 3) Фолд ChaptersSheet → таб «Розділи» (рішення
product-surfaces вже закріплене). 4) #41 accessibility — безперервно, не
big-bang. 5) #29 Import preview — наступна велика видима фіча. **Locked.**

**Q4. Як запобігти повторенню?**
→ Close-критерій: UI-тікет закривається лише з відвантаженою, phone-verified
дельтою; рішення миттєво породжує delivery-тікет; сесія закінчується
встановленням збірки на телефон користувача. Фіксується в ADR-0017;
дзеркало MAP оновлено. **Locked.**

**Q5. Що з документами?**
→ ADR-0017 (процес), оновлене MAP-дзеркало, ця спека. CONTEXT.md не чіпаємо
зараз — «UX principles» додаємо під час виконання spec-27 (#184, рішення 10).
**Locked.**

**Q6. Що значить «готово»?**
→ Користувач бачить різницю на своєму телефоні в день виконання кожного
кроку (P0 — вже після першого білда). **Locked.**

## План виконання (після підтвердження)

1. **Spec-27 (#184) — P0.** BUG-001: «Видалити завантажені файли» +
  ConfirmDialog з точним обсягом («N книг, X ГБ»), деструктивний колір, юніт-
  тест на `clearAllAudioCache`. BUG-002: root-cause дубля — загартувати
  нормалізацію merge-ключа (обрізка `-`-суфіксів + SEO-скраб перед ключем),
  одноразова міграція злиття дублів Works із переносом прогресу/закладок,
  регресійні тести.
2. **Spec-27 (#184) — P1.** Одна жанрова поверхня в Огляді (BUG-007), один
  блок дій на деталях книги, ukPlural + локалізаційний прохід (BUG-006),
  cross-block dedup на «Слухати», «N джерел»-бейдж, UX principles у CONTEXT.md.
3. **Spec-27 (#184) — P2.** Одна CTA в Медіатеці, плеєрні мікрополіші
  (підписи «15 с»/«30 с» + contentDescription, toast закладки, BUG-012).
4. **#185/#186** — live-лічильник книг і пам'яті; резолюція серії «Епоха
  божевілля» (перевірка + тикет з логом).
5. **ChaptersSheet → таб** (product-surfaces) + фолд поверхні.
6. **Кожен крок:** JVM-тести + Roborazzi + збірка → установка на телефон
  (wireless ADB) → скріншот-доказ у `docs/phone-test/`.
