# Спека: приватність мережі — браузерна ідентичність і маршрут (spec-38 T1+T2)

> Дата: 2026-08-23. Батьківська ініціатива: #252 (анонімізація користувача і
> трафіку від джерел книг). Тікети: T1 #253, T2 #254. Ланець: #273.
> Гілки T3–T7 (#255–#259) — окремі тікети, тут не реалізовані.

## Що і навіщо

До цієї зміни весь транспорт ніс один підробний User-Agent на всіх
користувачів (`4read-Audio-Engine/1.0` у завантаженнях, жорстко вбитий
SM-S918B Chrome/120 у каталозі та обкладинках) — фінгерпринт «стая Слухайки»,
без жодного способу сховати IP.

Тепер застосунок виглядає як звичайний браузер на телефоні слухача:

1. **Браузерна ідентичність** — транспорт (спільний `HttpFetcher` і завантаження,
   та image-навантаження Coil) шле справжній системний WebView UA пристрою,
   зчитаний раз на процес; до першої відповіді (і в JVM) діє статичний
   генеричний фолбек без моделі пристрою й назви застосунку. Стандартні
   Accept/Accept-Language — у кожному запиті.
2. **Єдині двері мережевої приватності** — чиста логіка
   `data/privacy/`: налаштування → розв'язаний маршрут (прямо / власний
   проксі HTTP·SOCKS5 / Tor localhost:9050). Дефолт без збережених
   налаштувань — «прямо», поведінка ідентична доспековій.
3. **Секція налаштувань** — екран «Приватність мережі» з ⋮ меню Медіатеки;
   вибір переживає перезапуск (SharedPreferences, патерн PlaybackSettings);
   сміттєва адреса відхиляється з зрозумілою причиною, нічого не зберігається
   наполовину.
4. **Чесна відмова** — обраний маршрут, що не відповідає, валить запит:
   прямого з'єднання не відбувається ніколи (NO_PROXY замість системних
   дефолтів; DNS для SOCKS резолвиться на боці проксі через
   `createUnresolved`).
5. **Політика пейсингу** — діапазон пауз + burst-ліміт на домен живе за
   дверима (`PacingPolicy`), детерміновано тестується сідованим генератором.
   ЇЇ ЗАСТОСУВАННЯ до циклу завантажень — тікет #257.

## Рішення (дельти до ADR)

- **ADR-0006 (дельта):** присвячений UA завантажень `OFFLINE_USER_AGENT`
  видалено — усі двері несуть одну браузерну ідентичність. Правило ADR-0006
  «завантаження споживають спільний fetcher» не змінене.
- **Видимість помилки маршруту:** падіння крізь недоступний маршрут
  поверхаються наявними шляхами деградації (порожній результат каталогу /
  повідомлення про невдачу завантаження); лог розрізняє «privacy route active».
  Окрема помилка-канал у UI — предмет верифікації #259, не новий шов зараз.
- **Холодний старт:** поки WebView UA не прочитано, запити несуть фолбек —
  свідомий компроміс проти блокування старту.
- **Coil як частина транспорту:** обкладинки їдуть тим самим маршрутом та
  ідентичністю (OkHttp proxySelector + interceptor); хардкодні UA прибрані.
  Referer-правила джерел не змінені (SEC-004).

## Тестування

Чисті JVM-тести крізь двері: `NetworkPrivacyPolicyTest` (дефолт прямо,
парсер адрес, чесна відмова), `BrowserIdentityTest` (фолбек, репорт UA),
`PacingPolicyTest` (межі джитеру, burst, сідована детермінованість).
Проводка (Proxy у з'єднанні, OkHttp, SharedPreferences) — тонкий клей за
прецедентом репозиторію; поведінка на пристрої (Orbot тощо) — QA #259.
