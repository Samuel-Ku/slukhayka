# Спека: Слухайка Web — web app для iOS-слухачів (spec-43)

> Дата: 2026-08-25. Батьківська спека: #312. Тікети: T1 #314, T2 #315,
> T3 #317, T4 #318, T5 #319, T6 #316, T7 #320.
> Рішення: ADR-0023 (Progress Sync після свідомої прив'язки) і
> ADR-0024 (Web Transport — серверний парсинг, аудіо direct-first).

## Що і навіщо

У Слухайки немає версії для iOS — README прямо про це каже. Web Client (PWA)
закриває діру без нативного застосунку: огляд каталогу шести джерел,
сторінка книги, плеєр із керуванням з екрана блокування. Плюс те, чого не
мали навіть Android-слухачі: прогрес дзеркалиться між власними пристроями.

Приватність лишається фундаментом: поки слухач не ввів код відновлення,
web не надсилає нічого особистого; синхронізація несе тільки позицію, розділ,
завершеність і швидкість; останній запис виграє за серверним часом.

## Що вже реалізовано цією зміною

- **T2 (#315)** — каркас `web/`: Vite + React + TS PWA на Cloudflare Pages,
  тихий анонімний профіль (анонімна сесія одразу елевається до `.local`
  пари, як в Android), App Check reCAPTCHA v3, темна тема, заглушки трьох
  поверхонь MVP. Без конфігурації Firebase профіль деградує до `local-…`.
- **T6 (#316)** — Progress Sync в Android: колекція `listening_state`
  `{uid}_{editionId}` з правилами «лише власний uid під App Check» і
  серверним штампом часу; чиста політика LWW (`ProgressSyncPolicy`),
  сім стора з дефолтними методами політики (`ListenerProgressSyncStore`) і
  тонкий Firestore-клей; плеєр штовхає прогрес одразу на паузі/завершенні й
  у стриманому темпі під час слухання; перед відновленням хмара
  перевіряється і застосовується лише якщо вона суворо новіша. Перемикач —
  у ⚙️ Профіль. Текст приватності в README тепер говорить точну правду.
- **T1 (#314)** — валідаційний прототип Safari готовий до ручної проби на
  пристрої (вердикти прямого `<audio>` по кожному джерелу + тест
  блокування екрана); код свідомо поза репозиторієм.
