# Наступна цікава книга — завершене інтерв’ю

Статус: автономну сесію `/grill-with-docs` завершено 2026-09-05.
Користувач окремо підтвердив питання 1–11, потім доручив:
«далі проведи автономну сесію і обери усі рекомендовані».
Питання 12–35 закриті за цим дорученням. Це рішення про дизайн;
реалізація, публікація issues, deployment і ввімкнення збору даних
у цій сесії не виконувалися.

Канонічний результат — [цілісний дизайн](2026-09-05-personal-recommendations-design.md).
Цей документ зберігає питання, відповіді й підстави. Докладні правила
та числові параметри слід брати з цілісного дизайну, а не з проміжних
пропозицій у розмові.

## Рішення, підтверджені користувачем окремо

| № | Питання | Обрана відповідь |
|---|---|---|
| 1 | Що означає «як Spotify чи Netflix»? | Відкрити «Огляд», швидко знайти наступну цікаву книгу; смак, реакція на дії та відкриття нових авторів |
| 2 | Чи враховувати досвід інших слухачів? | Так, як додатковий шар; участь добровільна, локальні рекомендації працюють без внесків |
| 3 | Чи збирати списки прослуханого? | Так, у добровільному серверному профілі з можливістю видалення; початково книги, завершення й оцінки |
| 4 | Завершив книгу, але поставив одну зірку — що переважає? | Явна оцінка переважає завершення й прогрес; книга дає негативний сигнал |
| 5 | Послухав 20 хвилин і тиждень не повертався, оцінки немає — це dislike? | Ні; сама перерва нейтральна, причину система не вгадує |
| 6 | Як почати без історії? | Необов’язковий вибір 3–5 улюблених книг; можна пропустити; без публічного відгуку чи позначки «прослухано» |
| 7 | Що робити, коли людина не впізнає книги? | У тому самому кроці запропонувати улюблені жанри; це вподобання для порядку, а не фільтр каталогу |
| 8 | Скільки місця віддати відкриттям? | Початково вісім рекомендацій за відомим смаком і дві з обґрунтованою підставою для відкриття |
| 9 | Чи переставляти картки під час перегляду? | Ні; новий вхід або ручне оновлення враховують свіжі входи; повернення зі сторінки книги зберігає добірку й місце; приховування діє одразу |
| 10 | Чи рекомендувати ще не розпочаті книги медіатеки? | Так, із видимим статусом на картці |
| 11 | Який результат означає вдалий підбір? | Почав із рекомендацій і продовжив в інший день або завершив; низька оцінка переважає; відсутність повернення не створює dislike |

У питанні 3 початкова рекомендація агента була залишити історію лише
на пристрої, спираючись на попередній дизайн. Користувач звернув увагу
на цінність списків прослуханого. Після пояснення користі та компромісу
обрано добровільний серверний профіль. Це свідома зміна напряму,
зафіксована в [ADR-0030](../adr/0030-opt-in-server-recommendation-profiles.md),
а не мовчазне продовження старої заборони.

## Перевірені факти коду та наслідки

Перевірено читанням коду 2026-09-05; застосунок і тести майбутньої
реалізації в цій сесії не запускалися. У робочому дереві є сторонні
незавершені зміни плеєра, імпорту та UI; вони не редагувалися цією сесією.

| Факт | Наслідок для реалізації |
|---|---|
| `MainViewModel.currentSignals` передає улюблене, прогрес і завершення, але не власну оцінку або relisten | Підключити справжні сигнали через власні модулі, не вважати наявність поля доказом інтеграції |
| `signalFor`: 1 зірка -1.2 + completion 0.9 + свіжий progress 0.5 = +0.2 | Замінити просте додавання правилом пріоритету явної оцінки |
| Обидва шляхи кандидатів у MainViewModel передають назву, автора й серію, без жанру та опису | Виправити одну спільну проекцію також для кешованих векторів |
| Усі Library Entry зараз входять в `excludedWorkIds` | Замінити виключення на правила початого/завершеного Work і дозволити відкладені |
| `HomeScreen` напряму читає потік перерахованих рекомендацій | Додати доменну стабільну добірку, пояснення та відновлення місця |
| `PrivateRecommendationLearning.PRODUCTION_UPLOAD_ENABLED = false`; мережевого шляху п’яти ваг немає | Реалізувати новий контракт, а не просто ввімкнути старий прапорець |
| `RecommendationEval` ділить влучання лише на число fold; звіт містить Recall понад 1 | Старий звіт не підтверджує нову якість; потрібен пакет R1 з коректними метриками |
| Поточний webhook/Worker у веб обслуговує доступ до Source; є Firebase Auth і Progress Sync | Приватний рекомендаційний API має окрему відповідальність |
