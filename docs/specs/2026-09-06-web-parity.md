# Спека: Web Client 1:1 з Android (web parity)

Дата: 2026-09-06. Ініціатива: «довести web до 1:1 з Android-застосунком».
Рішення зафіксовано в ADR-0034 (базова лінія паритету) на основі
грилінгу 2026-09-06 (`docs/audits/2026-09-06-web-parity-grill.md`,
рішення R-W1…R-W14). Кожен тікет закривається device-перевіреною
видимою дельтою: еталон — iOS Safari (PWA на головному екрані),
desktop Chromium — другий (R-W6).

## Загальні правила

- Канонічна вокабулярія v1.4 з першого тікета (R-W2, ADR-0034):
  React-еквіваленти `PosterCard`, `CycleCard`, `BookRow`,
  `MetadataChip`, дворівневих заголовків (group/section + action-слот
  + лічильник), двох станів, однієї моделі шапки таба з колапсуючим
  пошуком. Власні web-картки (`CatalogCardRow` тощо) поглинаються й
  видаляються — «застарілих, але лишених» не буває.
- Кожен user-visible рядок — через `i18n/strings.ts` (парність uk/en
  на рівні типів уже існує). Новий хардкод = дефект.
- Чесні дані (ADR-0014/0022): лічильники, тривалості, середні — тільки
  з реальних чисел; деструктивні дії — червоні, з підтвердженням
  точної сфери.
- a11y-контракти Android переносяться ВСЕРЕДИНУ канонічних компонентів
  як обов'язкові: роли/heading-и, touch-target ≥ 48 px, повернення
  фокуса після sheet/діалогів.
- Верифікація тікета: `npm run test` + `npm run typecheck` + ручний
  device-прогін (iOS еталон). Unit-тести ядра — на `fake-indexeddb`.

## M0. Фундамент

### W0.1 Канонічні компоненти (`web/src/ui/components/`)
Порти PosterCard, CycleCard, BookRow, MetadataChip, SectionHeader,
EmptyState/EmptyStateRow, TabHeader (заголовок + опційна дія,
колапсуючий 🔍). Існуючі `CatalogCardRow`/ад-хок картки поглинаються.
Перевірка: unit-тести + візуальний прогін чотирьох майбутніх табів.

### W0.2 IndexedDB-модель даних (R-W8)
Порт домену: Work, Library Entry, Tombstone, Listening State, Person
Bookmarks. Listening State мігрує з localStorage; localStorage лишається
лише для дрібних налаштувань. Виселення сховища браузером = чесне
повідомлення з пропозицією прив'язки кодом відновлення, не «порожня
Медіатека». Спайк на початку тікета: поведінка eviction в iOS PWA.
Перевірка: теста на fake-indexeddb; ручний прогін «перевстановити PWA».

**Результат спайку eviction (виконано, WebKit 2026):** Home Screen Web
App отримує квоту як браузер — до 60% диска; eviction — LRU, цілком
origin-ова (всі stores разом, не вибірково); `navigator.storage.persist()`
надано евристично — зокрема коли сайт відкрито як Home Screen Web App.
Наслідки для коду: (1) на boot web запитує persistent mode; (2)
виселення все одно можливо — детектор «довга відсутність + існуючий
heartbeat + порожні stores» лишається задією страховкою; (3) офлайн-кеш
(W6.2) ділить ту саму origin-квоту — пріоритет Listening State.
Детектор та повідомлення реалізовано у цьому тікеті (`local/`),
heartbeat переживае перезавантаження в localStorage.

### W0.3 Розширення Progress Sync (R-W3, R-W13, ADR-0034)
Нова колекція `work_relationships` (`{uid}_{mergeKey}`): стан
`entry | tombstone | none`, LWW за серверним часом, нічиїна —
tombstone. Union-злиття локальних рядків при прив'язці. Sync Person
Bookmarks (обидві ролі, детерміновані id). ДВА боки: Android пише
Library Entries/tombstones/закладки у ті самі колекції (sync увімкнено
за замовчуванням, ADR-0023 п.1), web читає й пише після прив'язки.
Правила Firestore в існуючому App Check конверті; незв'язаний браузер —
write-nothing. Metadata Overrides — НЕ в цій поставці.
Перевірка: policy-тести; ручний прогін телефон↔браузер (обране,
приховування, закладки).

## M1. Медіатека + таб-структура

### W1.1 Чотири таби (R-W7)
Слухати / Огляд / Медіатека / Налаштування = `SelectedTab` дослівно.
«Профіль» (код відновлення, перемикач sync) стає напрямком
Налаштувань. До наповнення нових табів допустимий проміжний реліз з
меншою кількістю табів, але структура-ціль — чотири.
Перевірка: навігація, стан табів, «Профіль» у Налаштуваннях.

### W1.2 Список Медіатеки
BookRow з прогрес-хайрлайном; фільтри й сортування як на Android;
порожні стани канонічні; створення Library Entry — з Огляду й сторінки
книги («зберегти»); чесні лічильники в заголовках (R10-патерн).
Перевірка: дзеркалення з Android-телефону з'являється в браузері.

### W1.3 Видалення як на Android
Трирівневе видалення з точною сферою в підтвердженні; tombstone пише
в sync — приховане не воскресає після оновлення каталогу.
Перевірка: видалення → tombstone → книга не повертається в Огляд.

## M2. Слухати

### W2.1 Вісім полиць (ADR-0015 стоїть на web)
Порт блоків HERO, ALMOST_DONE, RETURN, NEXT_IN_SERIES, TRAVEL, SHORT,
FAVORITE_AUTHORS, RECENTLY_ADDED з причинами; reorder/hide/restore —
через один sheet «Керувати полицями»; порядок у IndexedDB (аналог
ListenPrefs). Дедуплікація: hero не повторюється в інших блоках.
Перевірка: reorder, persist після перезавантаження, a11y sheet.

### W2.2 «Не цікаво»
Дисміс з полиці = локальна Recommendation Preference
(`HIDE_WORK`/`REDUCE_SIMILAR`), local-only, без серверного профілю
(CONTEXT.md), у тому самому словнику, що Android.
Перевірка: дисміс зникає і не повертається; скасування в налаштуваннях
рекомендацій (M6).

## M3. Огляд повний

### W3.1 Полиці
Cross-source «Новинки» rail (Work-дедуп + бейдж джерела), «Цикли»,
«Колекції» (статичні JSON-активи, порт `CollectionJson`/`CollectionMatcher`
— match локально по mergeKey), live-списки (spec-37) через воркер,
TTL-кеш як на Android. Feed Snapshot-аналог — кеш воркера (TTL
новинки 6 год, каталог 24 год) + явна кнопка оновлення.
Перевірка: полиці в порядку #302-піна; офлайн-старт зі снапшота.

### W3.2 Індекси
Серії, Колекції, ТОП 100, Виконавці — спільне шасі push-екрана,
лічильники в заголовках, рядки на BookRow, порожні стани канонічні.
Перевірка: обхід індексів uk/en.

### W3.3 Жанрові фільтри
Контракт `WorkFacetFilter` (OR всередині виміру, AND між, порожній
вимір = без фільтра); фасети через воркер; sticky-тулбар як на Android.
Перевірка: комбінації фільтрів; лічильники чесні.

### W3.4 Глобальний пошук
Колапсуючий патерн у шапці таба (🔍 → розгорнути, ✕/Back очищає),
результати на BookRow, повернення зберігає місце.
Перевірка: пошук → книга → назад.

## M4. Сторінка книги

### W4.1 Повна сторінка
Обкладинка, метадані, чіпи MetadataChip, «У серії», «Інші начитки»
(є), «Можливо, Тебе зацікавить», блок «Відгуки»: спільна база
(`book_reviews`, `edition_ratings`) — читання і запис під App Check,
document identity `workId_uid` / `workId_uid_editionId` унеможливлює
двозначне голосування (ADR-0022/0023). Заголовний рейтинг — чесна
середня (ADR-0022).
Перевірка: відгук, залишений на web, видно на Android і навпаки.

### W4.2 Один вхід відгуків (R9-патерн)
Форма в блоці «Відгуки» — єдиний вхід; запит після завершення книги
(ADR-0032) відкриває ту саму форму. Жодних других кнопок.
Перевірка: завершення розділу/книги → форма.

### W4.3 Слоти без фейків
Слот ✕/download/тривалість рендериться тільки коли дія реальна на web
(завантаження немає — слота немає; «Не цікаво» — є).
Перевірка: сторінка книги uk/en; відсутні слоти не залишають дір.

## M5. Плеєр + Налаштування

### W5.1 Плеєр повний
Список розділів, таймер сну, закладки (порт), швидкість (є), Smart
Rewind (є), MediaSession (є) — все в sheet-геометрії Android.
Перевірка: блокування екрана iOS (є вже), таймер, закладка.

### W5.2 Налаштування
Напрямки: Профіль (є), Мови контенту (є), Рекомендації (M6),
Сховище (використання + явне очищення з підтвердженням). Мережа:
чесний стан без мертвих перемикачів — приватного маршруту на web
немає (ledger нижче), екран показує пояснення, не фейковий тумблер.
Перевірка: uk/en обхід, 200% шрифт.

## M6. Рекомендації + офлайн

### W6.1 Персональні добірки (R-W4)
Участь увімкнена → читається серверний Recommendation Profile
(ADR-0030/0031); без участі → локальна адаптація з Listening State
браузера. Полиці «Для вас»/«Відкрити нове» на тому ж словнику причин.
Перемикач участі — у Налаштуваннях, відкликання зупиняє внески.
Перевірка: добірки до/після участі; відгук участі.

### W6.2 Офлайн streaming-cache (R-W5)
Service worker тримає нещодавно слухане аудіо доступним офлайн:
дослухати поточну книгу без мережі. Без менеджера завантажень.
Перевірка: режим «у літаку» на свіжоз слуханій книзі.

## Платформенний ledger (дельти, які НЕ закриваються)

1. **Приватний маршрут** (Tor/проксі) неможливий у браузері (ADR-0024
   п.4) — сторінка запитів іде через воркер, аудіо напряму; у
   Налаштуваннях пояснення, не перемикач.
2. **BROWSER-джерела (4read)**: безшумної WebView-сесії немає (ADR-0026/
   0027); грають лише через Cross-resolve або явне «Відкрити на сайті»
   з чесним поясненням (R-W9).
3. **Фонове аудіо iOS**: Safari обмежує довге фонове життя вкладки;
   lock-screen керування через MediaSession є, гарантій фону — ні.
4. **Явні завантаження** (менеджер файлів, OPFS) — окремий тікет після
   паритету (R-W5).
5. **Android Auto, віджети** — поза браузером фізично.

Ledger живе в цій спецу і в README web/; в релізних нотатках v1.5 —
в секції «що не увійшло» (R-W12, R-W14).

## Реліз

Перший реліз паритету — **v1.5**: один продукт, одна версія; нотатки
несуть дельти обох платформ. Проміжні milestone-деплої Pages — без
власної версії web.

## Що не входить

- Нова функціональність поза Android-паритетом (нові джерела, полиці,
  зміни IA) — web наздоганяє, не випереджає.
- Metadata Overrides sync — окремий тікет після M1 (R-W3).
- Нативна iOS обгортка.

## Ризики

- **Firestore-колекції + правила**: security-рев'ю перед мерджем;
  все в App Check конверті, write-nothing для незв'язаних.
- **iOS eviction спайк**: якщо IndexedDB виселяється агресивніше за
  очікування, чесне повідомлення + прив'язка кодом стає ще важливішою
  (провірено в W0.2, не в кінці).
- **Обсяг: 7 milestones**: драбина «дані спершу» тримає кожен тікет
  малим; Медіатека раніше за все доводить sync до живої перевірки.
- **Два рантайми однієї логіки** (Kotlin/TS): політики портом
  (CollectionMatcher, WorkFacetFilter, LWW) з фікстурами Kotlin-тестів
  — як уже зроблено для адаптерів і Smart Rewind.
