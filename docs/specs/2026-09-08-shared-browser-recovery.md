# [Spec] Спільний рушій відновлення браузерних джерел — 2026-09-08

> **Status:** Proposed. Батьківське рішення: ADR-0036 (ревізія коду
> 2026-09-08, усі рішення зафіксовані там). Споріднені спеки:
> `2026-08-11-webview-pattern-sources.md` (джерела за сесією),
> `2026-09-08-sources-wave-47.md` (ukrainianaudiobooks — перший новий
> споживач профілю). Споріднені ADR: 0026 (порядок доступу, двері),
> 0027 (4read — єдиний релізний WebView-виняток).

## Problem Statement

Відновлення 4read (v1.3.7, #425/#426) — найскладніший потік застосунку:
схована сторінка за Плеєром, челендж-проба, обмежене вікно, верифікований
вердикт програвання, оновлення треків без форка ідентичностей. З приходом
ukrainianaudiobooks (спека 47) браузерних джерел стає три, і «достосувати
4read-механіку під нового провайдера» наївним шляхом означає третю копію
екрана і політик.

Ревізія коду (2026-09-08): механіка вже джерело-агностична —
`WebSourceBrowserScreen` і `BrowserRecoveryCoordinator` працюють для
будь-якого `SelectedWebSource`, поверхня `HIDDEN / CLOUDFLARE_ONLY /
FULL_BROWSER` — чиста функція, проба челенджу і cookie-гігієна спільні.
Знання про джерела, однак, твердо зашите в шість місць:

1. `BrowserGating.browserDestinationFor` — порівняння з `"4read"`;
2. `SourceBrowserPolicy.allowedHostsFor` / `allowsAudioHost` — `when` за id;
3. `MainViewModel.openBrowserRecovery` — форк на `open4ReadRecovery`;
4. вхідне оголошення про зміну методу — пришите до `sourceId == "4read"`;
5. захоплювальний JS у `importCurrentPage` — 4read-специфічний перетворювач
   `{v1}`-маніфестів безумовно для всіх джерел;
6. пошукова двері `fourReadSearchUrl` — знання поза адаптером.

## Solution

**Browser Recovery Profile** — декларація можливостей одного Browser джерела
біля його адаптера; спільний рушій читає профілі й більше ніде не гілкується
за `sourceId`:

- `pageHosts` — allowlist сторінок (переїжджає з `SourceBrowserPolicy`);
- `audioHosts` — спостережені хости аудіо (переїжджає звідти ж);
- `searchDoor: (query) -> String?` — URL пошукової двері; null = немає
  (в 4read — `fourReadSearchUrl`, в інших — поки null);
- `entryNotice` — текст вхідного оголошення; відсутній = не показувати;
- `manifestProbe` — чи захоплювальний JS збирає in-page маніфести
  (`file: "…m3u|txt|json"` + перетворювач плейсхолдерів на кшталт `{v1}`);
- `releaseBrowserDoor: Boolean` — двері браузера у release; true лише в
  4read (ADR-0027 тримається: зміна — окреме рішення, не конфігурація).

Слухач нічого не помічає: жодна спостережувана поведінка 4read не змінюється;
ukrainianaudiobooks підключається профілем + фікстурами без дотиків до UI.

## User Stories

1. Як слухач 4read, я хочу, щоб відновлення працювало як раніше, щоб моя звична поведінка не змінилася (регресійний захист хвилі).
2. Як слухач ukrainianaudiobooks, я хочу відновлювати вже імпортовану книгу крізь ту саму сховану механіку, що й 4read, щоб мій прогрес переживав зміну аудіо на сайті.
3. Як слухач debug-збірки, я хочу мати двері браузера sluhay/sluhayknigi/ukrainianaudiobooks, щоб розробка і верифікація лишалися можливими.
4. Як мейнтейнер, я хочу, щоб підключення нового браузерного джерела було профілем + фікстурами, щоб жоден екран не редагувався заради нового джерела.
5. Як мейнтейнер, я хочу, щоб релізні двері не вмикалися конфігурацією мовчки, щоб ADR-0027 залишався рішенням на кожне джерело, а не перемикачем.
6. Як мейнтейнер, я хочу, щоб маніфест-проби й оголошення були властивостями джерела, щоб 4read-специфіка не розмазувалася по спільному коду.

## Implementation Decisions

- **Профіль біля адаптера, без нового шва**: дані профілю живуть у
  source-пакеті поруч з адаптером (єдиний реєстр — adapters; споживачі:
  `BrowserGating`, `SourceBrowserPolicy`, `MainViewModel`).
- **Профіль — чисті дані** (JVM): тести гейтингу залишаються
  без Android-варіанта.
- **Захоплювальний JS**: маніфест-проба і перетворювач `{v1}` виконуються
  лише коли профіль оголошує `manifestProbe`; поведінка для 4read
  байт-у-байт.
- **Пошукова двері**: `open4ReadRecovery`'s фолбек «пошук із підставленою
  назвою» прочитує `profile.searchDoor`; джерела без двері фолбечать на
  збережений URL книги (наявна `BrowserRecoveryCoordinator.recoveryEntryUrl`).
- **Гейтинг**: `browserDestinationFor` читає `releaseBrowserDoor` профілю
  (debug → двері для всіх browser-джерел, release → лише прапорець);
  очікування `BrowserGatingTest` не змінюються.
- **Оголошення**: вхідна картка «Метод 4read змінився…» стає
  `profile.entryNotice` (4read лишається єдиним носієм тексту).

## Testing Decisions

- Чисті JVM-тести профілю: `browserDestinationFor` за профілями (обидва
  смаки, три джерела), відмова релізних дверей для ukrainianaudiobooks.
- Тест захоплювального JS-шва: маніфест-проба лише за профілем; для 4read —
  наявні фікстури без змін.
- Регресійний захист: усі наявні тести 4read-відновлення зеленіють без
  правок очікувань (поведінка не змінюється — цей критерій сам собі тест).
- Device check: 4read-відновлення на пристрої після рефакторингу.

## Out of Scope

- Увімкнення релізних дверей для sluhay/sluhayknigi/ukrainianaudiobooks
  (окреме рішення на кожне джерело, за потреби — ревізія ADR-0027).
- Нові механіки відновлення (черга відновлень, паралельні сесії) — рушій
  лишається як є.
- Web Client: браузерних сесій у воркера немає; профіль — Android-домен.

## Further Notes

- Перший новий споживач профілю — T4 спеки 47 (ukrainianaudiobooks): після
  цієї хвилі його підключення = профіль + фікстури.
- Це консолідація, не фіча: користувацьких змін немає, тому хвиля маленька.

## Tickets

- **T1 — Browser Recovery Profile + перенос знань** (task): чисті дані
  профілю в source-пакеті; `BrowserGating`, `SourceBrowserPolicy`,
  `openBrowserRecovery`, оголошення і маніфест-проба переходять на профілі;
  всі наявні тести зелені без правок очікувань. Блокує T2, T3.
- **T2 — регресійний захист 4read** (task): device check 4read-відновлення;
  фікстурні тести захоплювального JS за профілем. Блокується T1.
- **T3 — профіль ukrainianaudiobooks** (task): профіль нового джерела
  (хости з вердикту T1 спеки 47, `releaseBrowserDoor = false`); очікування
  `BrowserGatingTest` для трьох джерел. Блокується T1, розблоковує T4 спеки 47.
