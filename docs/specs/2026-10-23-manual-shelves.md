# Спека: Полиця — особисте групування книжок слухачем

> Status: accepted, 2026-10-23. Issue: #1401.
> Рішення: [ADR-0064](../adr/0064-shelves-are-listeners-own-grouping.md)
> (розвиває ADR-0063; уточнює межу з ADR-0012 і Series).
> Обсяг: Android, локально. Синхронізація й експорт — поза v1.

## Проблема

Медіатека вже особиста (ADR-0063), але згрупувати її слухач не може:
«Колекції» в Огляді — кураторські зовнішні списки, Series — бібліографія,
фільтри «Моїх книг» — запити без назви й порядку. Немає об'єкта, який слухач
створює сам і наповнює вручну.

## Модель даних

```text
shelves
  id TEXT PRIMARY KEY            -- стабільний локальний id (UUID)
  name TEXT NOT NULL             -- назва, яку задав слухач
  description TEXT NOT NULL DEFAULT ''
  createdAt INTEGER NOT NULL
  updatedAt INTEGER NOT NULL

shelf_entries
  shelfId TEXT NOT NULL          -- FOREIGN KEY → shelves(id) ON DELETE CASCADE
  bookId  TEXT NOT NULL          -- FOREIGN KEY → library_entries(id) ON DELETE CASCADE
  position INTEGER NOT NULL      -- порядок задає слухач; унікальний у межах полиці
  addedAt INTEGER NOT NULL
  PRIMARY KEY (shelfId, bookId)
  INDEX (shelfId, position)
```

Міграція: нова версія схеми + `Migration`, що створює обидві таблиці. Існуючі
дані не переписуються; порожній набір полиць — канонічний стан для наявних
установок.

## Правила

1. **Лише особисті записи.** Членом полиці може бути тільки Library Entry з
   `EXPLICIT_SAVE`/`EXPLICIT_IMPORT` (ADR-0063). DAO-шов відкидає неособистий
   запис і повертає явний відмовний результат; UI не показує «Додати на
   полицю» для технічної картки, поки її не збережено.
2. **Один жест — два факти.** «Додати на полицю» з картки поза бібліотекою
   робить `saveToLibrary` (Personal Intent) і додає членство в одній
   транзакції. Це не приховане авто-збереження: жест явний, і саме він
   створює особистий зв'язок (ADR-0064 §3).
3. **Порядок.** `position` — явне число; перестановка переписує позиції
   сусідів в одній транзакції. Жодного автоматичного сортування, що переграє
   вибір слухача.
4. **Видалення.** `DELETE FROM shelves` каскадно прибирає членства. `DELETE`
   Library Entry каскадно прибирає членства (зовнішній ключ на
   `library_entries`). Полиця ніколи не володіє книжкою й не має власного
   прогресу, закладок чи стану прослуховування.
5. **Порожній стан.** Порожня полиця не видаляється автоматично; «Полиць ще
   немає» — запрошення створити першу.
6. **Жодних правил/автоматики** в v1: полиця не наповнюється з імпорту,
   каталогу, серій чи нагород.
7. **Нагороди не вводяться.** Кількість полиць не є поступом (ADR-0060,
   ADR-0064 §8).

## Екрани й мова

- «Мої книги» → секція «Полиці» (горизонтальний ряд карток полиць + «Нова
  полиця»). Порожній стан бібліотеки вже має два входи (ADR-0063); секція
  полиць з'являється лише коли є хоча б одна полиця, щоб не додавати третій
  вхід на чистій інсталяції.
- Екран полиці: назва, опис (необов'язковий), список членів у порядку
  слухача, меню «Перейменувати», «Змінити опис», «Видалити полицю».
- Дії члена: «Прибрати з полиці», перетягування (або «вгору/вниз» для
  доступності).
- Мова: «Полиця», «Нова полиця», «Полиця порожня», «Додати на полицю»,
  «Прибрати з полиці», «Видалити полицю? Книжки залишаться в бібліотеці».
  `_Avoid_` у CONTEXT: «колекція», «тег», «папка», «плейлист».

## Критерії приймання

1. Слухач створює полицю, додає до неї книжки з «Моїх книг» і змінює порядок;
   порядок переживає перезапуск.
2. Додавання книжки поза бібліотекою робить її особистою (EXPLICIT_SAVE) і
   додає членство одним жестом; технічна картка без жесту членом не стає.
3. Видалення полиці не видаляє книжок; видалення книжки прибирає її з усіх
   полиць (каскад піниться Room-тестом).
4. Порожня полиця і відсутність полиць мають різні, зрозумілі порожні стани.
5. Полиці не з'являються в кураторських «Колекціях», Series, тріажі
   «Імпортоване» й не впливають на нагороди.
6. Нові рядки мають uk/en/pl; Android Lint зелений без росту baseline.
7. Room-міграція проходить на наявній БД; жодних переписувань легасі-рядків.

## Поза обсягом v1

Синхронізація полиць між пристроями, експорт/імпорт, розумні полиці за
правилами, теги, ієрархія тек, спільні полиці, нагороди за кураторство.

## Тести

- `ShelvesRoomTest`: створення/перейменування/видалення; порядок після
  перестановки; каскад при видаленні книжки; неособистий запис відкидається;
  один жест створює особистий зв'язок + членство.
- Compose: порожній стан, список полиць, drag-and-drop (semantics-перевірка
  порядку), доступність кнопок «вгору/вниз».
- Lint/partitions: нові класи автоматично потрапляють у відповідні партиції
  (`scripts/test_partitions.py`), нові рядки — uk/en/pl.
