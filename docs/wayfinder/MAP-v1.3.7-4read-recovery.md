### Правила паралельної роботи

- **Власність на файли:** Agent A — WebView/cookie/recovery-шлях;
  Agent B — координатор, каталог/пошук, сторінка книги. `SourceAdapter`
  (режим доступу) — тільки B; 403/404-семантика recovery — тільки A.
  Спільні місця типу DI composition root — мінімальними окремими комітами,
  інакше rebase-конфлікти з'їдять обох.
- **Без тестів немає PR** (TDD RED→GREEN), fakes > mocks, `runTest`.
  Табличні JVM-тести з fake clock/prober — як вимагають acceptance criteria.
- Кожен агент — власна гілка/worktree (`agent-a/427-…`, `agent-b/429-…`),
  rebasing на main перед кожним PR. Мержить людина.
- Готовий PR одразу мержити в main, щоб другий агент ребазився на нього,
  а не на зростаючий локальний стовп.

## Gate 1.3.7 — чекліст пристрою (зменшений, без download-recovery)

1. CI зелений: `testDebugUnitTest` + Kover gate + eval gate + accessibility
   API 35 (включно з `WorkSourceFkRegressionTest`).
2. Наявна книга 4read: відтворення ламається чесно → «Оновити через
   браузер» → точна сторінка у вбудованому WebView → Cloudflare пройдено →
   аудіо захоплено → повернення в Player на той самий Chapter і позицію.
3. Повторне відновлення тієї самої Edition не створює Work/Edition/Source
   дубліката.
4. Мертве аудіо після recovery **не** оголошується успіхом — браузер
   лишається відкритим із чесним повідомленням.
5. Рекомендована книга з прямим Source стартує без браузера
   (LOCAL → DIRECT → UNKNOWN → BROWSER, бюджет ~10 с).
6. Блок «Джерела» на сторінці книги: порядок = координатор, «Потрібен
   браузер» видно і озвучується TalkBack, рядки неклікабельні.
7. Cookie 4read не тікає на чужі хости; стороння навігація заблокована.
8. Той самий сценарій працює з вимкненим/недоступним Firebase.
9. Тап «Сни» не крашить (#388 регресія).

## Risks

- **Cloudflare нестабільний:** recovery-потік може ламатись незалежно від
  коду. Кожен пристрой-прогон фіксувати нотаткою в #434 (дата, книга,
  результат), щоб не плутати регресію з погодою на джерелі.
- **Спільний шов #429** чіпає всі адаптери — його мержити першим у Lane B
  і не починати нічого, що чіпає адаптери, до його green CI.
- **Два агенти в одному DI-графі** (MainViewModel/composition root) —
  головне джерело конфліктів; тримати DI-зміни в окремих міні-комітах.
