# Спайк: каталог sluhay.com — масштаб і сесійний sitemap (#725)

> Дата: 2026-09-11. Статус: **спайк-гейт пройдено** (поріг ~4 000
> унікальних книг; виміряно **5 826**). Рішення A1/B1 ухвалено того ж дня,
> реалізацію зроблено в цій гілці (розділ нижче).

## Метод

Cloudflare на sluhay.com віддає `403` і `Just a moment…` на будь-який чистий
HTTP (перевірено curl-ом із реальним Chrome-UA; те саме для `robots.txt`).
Тому спайк виконано справжнім Chrome через Playwright:

1. persistent-контекст Chrome, локаль uk-UA, стелс-прапорці проти
   `navigator.webdriver`, очікування челенджу й клік по Turnstile у
   `iframe[src*="challenges.cloudflare.com"]`;
2. після проходу челенджу — `https://sluhay.com/sitemap.xml` (200, через
   сесію; curl-ом — 403);
3. дочірні sitemap-и забрано тим самим сесійним контекстом.

**Застереження методу:** це desktop Chrome, не WebView-банка застосунку.
Твердження «сесія з WebView працює так само» лишається неперевіреним на
пристрої (ручний крок спеки).

## Виміряне

| sitemap | статус | `<loc>` | книжкових URL |
|---|---|---|---|
| `static_pages.xml` | 200 | 4 | 0 |
| `category_pages.xml` | 200 | 48 | 0 (категорії) |
| `tags_pages.xml` | 200 | 1 980 | 0 (теги) |
| `news_pages.xml` | 200 | **5 828** | **5 826** |

- Форма книжкового URL (той самий фільтр, який використовував би кар'єр):
  `https://sluhay.com/<категорія>/<id>-<slug>.html`, напр.
  `…/ukrayinska-literatura/5855-melamed-gennadyy-myy-superdydus.html`;
  `news_pages` віддає найновіші першими (5855 → 5853 → …), ID сягають ~5855.
  Поріг виміряно саме цим фільтром, не «сирими» `<loc>`.
- Головна: 36 poster-блоків, у першому екрані категорії
  `svitova-literatura`, `ukrayinska-literatura`, `kazka`,
  `zarubizhna-literatura`; категорійна сторінка — 39 poster-блоків,
  `?page=` у розмітці не видно (пагінація, ймовірно, AJAX).
- `robots.txt` віддає `Sitemap: https://slushay-knigi.com/sitemap.xml` —
  **чужий сайт** (окремий каталог, 38 668 книжок, російська транслитерація;
  його шляхи дають 404 на sluhay.com). Це артефакт шаблону, не дзеркало.

## Висновок спайк-гейту

- **Масштаб: PASS.** 5 826 унікальних книжкових URL (поріг ~4 000+).
  «10 000» із meta — маркетинг, як і попереджав гриль; реальний ID-простір
  ~5.9k.
- **Перетин із 4read: критерій застарів.** 4read видалено як скам-джерело
  (2026-09-11, хвиля #741): його каталог більше не існує в застосунку, тож
  «перетин ≤70%» не має предмета. Джерело цінне саме тим, що лишилося.
- **Сесійність: підтверджена на рівні браузера.** Sitemap недоступний чистим
  HTTP; потрібна жива сесія — механіка spec-42 #427 (WebView-кукі, host-aware)
  лишається правдоподібним, але не перевіреним у застосунку.

## Ухвалені рішення та реалізація

**A1 — індекс може нести session-backed джерела; матч придатний лише за
живої сесії.** `WorkIndexRefresher` віддає індекс, `SourceReplacementMapping`
приймає запис, якщо джерело `DIRECT` **або** `sessionAlive(sourceId)`; без
сесії запис пропускається і резолвер тримає чесний шлях. Жива сесія — це
робочий транспорт (cookie-fetch сторінки + Referer-стрім), не нові браузерні
двері. Записано амендментом **ADR-0037**, дзеркально — в CONTEXT.md
(«Replacement Mapping»).

**B1 — §8 без змін.** Сесійний sitemap-запит несе Cookie живого WebView, тож
іде поза кошиком і горлом за ADR-0039 §8; ввічливість тримають один запит на
джерело за каталожний TTL (24 год), host-scoped кукі, single-flight, без
обходу категорій. Явно записано уточненням до **ADR-0039** і KDoc кар'єра.

Зроблено в гілці:

1. `WorkIndexRefresher`: шов `cookieProvider: SourceCookieProvider` (той самий
   спільний інстанс, не лямбда) + реєстрація `sluhay` у `SITEMAP_SPECS`
   (`news_pages.xml` + фільтр книжкових URL). Без сесії — best-effort miss.
2. `SourceReplacementMapping`: шов `sessionAlive(sourceId)` і правило
   `usableIndexMatch` для обох входів (`resolve`, `resolveLocalOnly`).
3. Композиція в `App`: кар'єр бере кукі з `AndroidSourceCookieProvider`;
   резолвер перевіряє живу сесію через `hasUsableSourceSession`.
4. Тести: сесійний sitemap несе Cookie і дає лише книжкові URL; без сесії —
   нічого; DIRECT-матч без сесії працює як раніше; BROWSER-матч без сесії
   пропускається, із сесією — приймається. 5/5 + 2/2 зелені.

**Залишок (не блокер):**
- Таймінг: індекс оновлюється на старті під TTL; сесія, здобута в роботі,
  потрапить на наступному старті після TTL.
- Ручна перевірка на пристрої: реальна WebView-банка застосунку (спайк
  використовував desktop Chrome) — крок зі спеки #725.

## Свідомо поза межами (рішення гриля 2026-09-11)

- `accessMode` sluhay лишається BROWSER; DIRECT-ранг не вводимо.
- Release-двері для sluhay не додаємо (ADR-0027).
- `search()` лишається порожнім (robots забороняє `do=search`).
- Завантаження зі sluhay.com — поза межами (лише стрім).

## Артефакти

Сирі sitemap-и та HTML лежать у `/tmp/opencode/` (`sluhay-own-sitemap.xml`,
`news_pages.xml`, `category_pages.xml`, `sluhay-home-live2.html`); у репо не
зберігаємо за ADR-0016. Ключові числа й зразки URL наведено вище.
