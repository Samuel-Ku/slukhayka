# Спайк хвилі 53 T1: вбудований рушій метаданих для надсилань

Живий прогін 2026-09-10, `NewPipeExtractor v0.26.5` (уже в застосунку),
звичайна мережа без токенів. Канал для перевірки:
`https://www.youtube.com/@-Kalidor` («Аудіокниги Українською — Студія
КАЛІДОР», 91500 підписників). Сирі зрізи — у `fixtures/wave-53/`.

## Вердикт: PASS

- **Канал** читається (`ChannelInfo`): ім'я, підписники, чотири таби —
  `videos`, `shorts`, `livestreams`, `playlists`.
- **Таб відео** (`ChannelTabInfo`): 30 позицій, кожна — `STREAM` з реальною
  тривалістю (напр. `F_OkQ2hHEvQ` — 4674 с) і канонічним watch-URL.
- **Таб плейлистів**: 30 позицій-плейлистів із реальною кількістю відео
  (8, 11, 12, 18, 63…).
- **Плейлист** (`PlaylistInfo`): ordered entries у порядку сторінки, кожен —
  watch-URL + реальна тривалість (4285, 4075, 1966, …); `streamCount`
  збігається з фактичною кількістю.
- **Одиночний стрім** (`StreamInfo`): назва, тривалість, ім'я каналу.

## Рішення для реалізації (випливають зі спайка)

1. Таби каналу приходять як **`ListLinkHandler`**, а не рядки: рядковий URL
   таба плейлистів (`…/UCT…/playlists`) `PlaylistInfo` не приймає. Для
   вмісту таба — `ChannelTabInfo.getInfo(service, linkHandler)`; для самого
   плейлиста — `PlaylistInfo.getInfo(service, url)`.
2. Тривалості доступні **і для відео, і для кожного entry плейлиста** —
   отже хвиля 53 може давати реальні тривалості розділів (оновлення
   поточного плану, який тривалостей не ніс).
3. Жодних ознак блокування/челенджу на метаданих не спостерігалось —
   `yt-dlp` як обов'язковий бекенд більше не потрібен; код лишається за
   швом як необов'язковий.
4. Транспорт — той самий `SharedClientDownloader` (спільний клієнт,
   браузерна ідентичність, приватний маршрут), що й для стрімів; NewPipe
   ініціалізується один раз на процес (наявний `NewPipeYouTubeExtractor`).
