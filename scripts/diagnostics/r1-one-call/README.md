# Один Linux-прогін для #487

Ручна діагностика порівнює один виклик production `OnnxEmbedder.embed` із уже отриманими Mac-даними. Вхід — один публічний Твір із каталогу. Приватної історії слухача тут немає.

`r1-one-work-linux.yml` запускається лише вручну з `authorize_one_public_work=true`. Він компілює незмінні вихідні файли коміту `022c786f33e860579fab78c7f91413c9b0b5325e` і до inference перевіряє SHA моделі, токенізатора, залежностей та всіх 21 backend-класів. Вхід має збігтися з Mac: 302 токени й ті самі tensor bytes. Якщо перевірка не проходить, результат не доводить паритет.

JDI-спостерігач читає фактичні input tensors, hidden output, production pooling і return одного виклику. Модель і токенізатор беруться з зафіксованої ревізії Hugging Face; залежності — Maven Central. Сесія використовує production default options. Linux JVM та native runtime можуть відрізнятися від Mac, тому пакет сам по собі не встановлює причину різниці платформ.

Artifact `r1-one-public-work-linux-<run_id>` містить лише файли з явного переліку `finalize_artifact.py`: один текст, його tensors і вектор, provenance та обмежені дані можливого збою. Розмір — до 2 MiB, зберігання — 3 дні. Репозиторій публічний: текст/scripts залишаються в Git, Actions logs мають власний термін зберігання, а читачі GitHub можуть завантажити artifact після входу. Асети моделі й залежності не завантажуються в artifact.

Прогін обмежено 20 хвилинами; diagnostic JVM — 180 секундами. Автоматичного повтору немає. Цей результат не є eval-gate на 18 188 Творах і не закриває quality AC #487.
