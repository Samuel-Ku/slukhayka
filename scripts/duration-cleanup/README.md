# Прибирання спільної бази тривалостей (#528)

Тут лежить інструмент, який прибирає зі спільної бази значення, що не є
тривалостями книжок — передусім 52-секундну врізку 4read, яку CDN віддає
замість розділу під HTTP 200 з правильним URL і Referer.

## Чому це обов'язково, а не косметика

`book_durations` дозволяє лише `create` (`allow update, delete: if false`), а
клієнт після #528 читає документ без `schemaVersion` як промах. Тому документ,
що вже лежить у базі, **блокує правильне значення назавжди**: ні виправити, ні
перезаписати. Поки врізка там, спільна тривалість цієї книжки не відновиться.

## Одне правило, без вигадування (ADR-0014)

| що в базі | що робимо |
|---|---|
| значення проходить контракт (`300 ≤ s ≤ 360000`, `s ≠ 14400`) | лишаємо значення, ставимо `schemaVersion: 2` |
| значення не проходить | видаляємо — це не тривалість книжки |

Нічого не перераховуємо й не вгадуємо. Після прибирання база гоїться сама:
`putDuration` викликають `DurationEnrichment` (метадані джерела) і
`ChapterDurationProbe` (проба самого потоку), тож наступний оновлений клієнт,
що розпізнає книжку, опублікує правильне значення.

## Порядок

```bash
# 1. Подивитися, що зіпсовано. Лише читання, ключів не треба:
#    правила дозволяють публічне читання, а ключ беруть із
#    app/google-services.json (він і так лежить у кожному APK).
node scripts/duration-cleanup/inventory.mjs
node scripts/duration-cleanup/inventory.mjs --json /tmp/inv.json

# 2. Сухий прогін прибирання — потрібен сервісний акаунт:
cd scripts/duration-cleanup && npm install
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json
node purge.mjs                 # нічого не пише, лише показує

# 3. Застосувати (спершу збереже резервну копію):
node purge.mjs --apply
```

`inventory.mjs` виходить із кодом 1, якщо знайшов порушників, тож його можна
повісити в CI як гейт.

## Ключ сервісного акаунта

Firebase Console → Project settings → Service accounts → Generate new private
key. Ключ **обходить правила**, тож поводься з ним як з паролем: не комітити,
не пересилати в чатах, тримати поза репозиторієм. Резервна копія того, що
скрипт збирається змінити, пишеться у `/tmp` перед будь-яким записом.

Шлях до `google-services.json` можна перевизначити змінною
`GOOGLE_SERVICES_JSON`, а id проєкту — `FIREBASE_PROJECT`.
